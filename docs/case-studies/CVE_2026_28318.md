# SolarWinds Serv-U: unauthenticated DoS via Content-Encoding: deflate (CVE-2026-28318)

An unauthenticated caller can crash the SolarWinds Serv-U service by sending crafted POST requests carrying Content-Encoding: deflate. Every request can take the FTP server down, so an exposed deployment is trivially deniable; SolarWinds publishes mitigation steps for customers who cannot update immediately.

## The vulnerability

Serv-U's request handling crashes on specially crafted deflate-encoded POST bodies, so an unauthenticated caller can take the service down at will. Eden fronts the Serv-U HTTP listener, so the encoded body rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the upload route and its descendants. This blocks every upload, benign or not (the recorded false positive) — but the deflate crash shape reaches any POST route, so the module tier below is the better control.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/upload",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_servu_v1 waits for a complete request and refuses any POST carrying Content-Encoding: deflate — the exact crash shape from the advisory — while ordinary POST bodies (identity, gzip) continue. Content-Encoding is an end-to-end header, so unlike Connection it is presented to module evaluation.

```rust
if let Some(ce) = header_value(hdrs, b"content-encoding") {
    if eq_ignore_case(ce.trim_ascii(), b"deflate") { return Ok(Decision::Refuse); }
}
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-28318/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded SolarWinds Serv-U version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declarative policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-28318/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** Apply the update for the affected release or device model. Follow the vendor's guidance for the installed build. [Advisory reference](https://www.solarwinds.com/trust-center/security-advisories/CVE-2026-28318)

## Fixture and probes

The benign probe posted an ordinary upload body. The advisory-shaped probe posted a deflate-encoded body — the crash shape from the advisory. The fixture incremented its marker when a deflate-encoded body reached its parser.

## Measured comparison (2026-11-13 UTC)

The module refuses Content-Encoding: deflate on any POST routed through the interlay — the exact advisory shape. Other compression algorithms were not recorded as crash shapes in the advisory. Identity and gzip bodies continue.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
