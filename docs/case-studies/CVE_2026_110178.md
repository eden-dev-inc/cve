# ContextForge: cross-tenant overwrite of public tools and credentials (CVE-2026-110178)

In IBM ContextForge MCP Gateway 1.0.0 through 1.0.11, a user holding only a team-scoped import permission can overwrite the endpoint URLs, headers, and credentials of public tools, resources, and prompts owned by other tenants. The gateway is an AI tool broker: cross-tenant credential overwrite turns every connected model call into an exfiltration path.

## The vulnerability

The gateway checks import permissions but not object ownership, so a team-scoped user rewrites other tenants' public tool definitions — including their upstream credentials. Eden fronts the gateway, so the overwrite rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/tools",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_cfxtenant_v1 waits for a complete request, matches tool-definition routes, and refuses write operations carrying endpoint or credential changes without a tenant binding header — the cross-tenant overwrite shape. Tenant-bound writes continue.

```rust
const ROUTE: &[u8] = b"/tools";
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-110178/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded IBM ContextForge MCP Gateway version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-110178/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-110178) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe updated a tool presenting the tenant binding. The advisory-shaped probe overwrote a public tool's endpoint and credentials without any binding. The fixture incremented its marker when a cross-tenant overwrite reached the tool store.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign tenant-bound tool update | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped cross-tenant overwrite | 200, 1 | 403, 0 | 403, 0 |

The module enforces a tenant-binding contract on definition writes naming endpoints or credentials; it does not validate the binding's value, so a forged binding passes and is a bypass to record. The durable fix is the vendor's ownership-check patch.

## Signed module authority

Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403).
