# FUXA: authentication bypass via Referer spoof to script execution (CVE-2025-69985)

FUXA through 1.2.8 lets a remote attacker run arbitrary Node.js code without logging in: spoofing the Referer header reaches /api/runscript, and public exploit code is available. An unauthenticated remote-code-execution on a SCADA/HMI dashboard is full control of the connected plant view.

## The vulnerability

The runscript endpoint's middleware accepts a forged Referer as proof of origin, so an unauthenticated caller posts Node.js code that the server executes. Eden fronts the FUXA dashboard, so the forged request rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/api/runscript",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_fuxareferer_v1 waits for a complete request, matches the /api/runscript route, and refuses requests carrying Node.js execution markers (require(, child_process, eval() that present no Authorization header — the unauthenticated script-execution shape. Authenticated script requests continue.

```rust
const ROUTE: &[u8] = b"/api/runscript";
static MARKS: [&[u8]; 3] = [b"require(", b"child_process", b"eval("];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2025-69985/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded FUXA (@frangoteam) version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2025-69985/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2025-69985) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe posted a benign script with a valid JWT. The advisory-shaped probe posted a child_process payload with no Authorization header, matching the public exploit shape. The fixture incremented its marker when an unauthenticated script reached the executor.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign authenticated script | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped unauthenticated RCE | 200, 1 | 403, 0 | 403, 0 |

The rule requires an Authorization header on marker-bearing runscript requests; a forged-but-present token would pass the module and is a bypass to record (the module does not validate tokens). Marker-free Node.js escapes (obfuscated require calls) are also a bypass. The durable fix is the vendor's middleware patch.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
