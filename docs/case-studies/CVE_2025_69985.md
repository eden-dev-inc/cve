# FUXA: authentication bypass via Referer spoof to script execution (CVE-2025-69985)

An unauthenticated attacker can spoof the Referer header on affected FUXA versions and gain access to a script endpoint that runs Node.js code. Code execution can compromise the server and expose the systems it manages.

## The vulnerability

The affected versions and upgrade guidance are listed above. The Eden policy and module were tested against the HTTP fixture described below.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/api/runscript",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** The module checks the runscript route and refuses requests with selected Node.js markers when the Authorization header is absent.

```rust
const ROUTE: &[u8] = b"/api/runscript";
static MARKS: [&[u8]; 3] = [b"require(", b"child_process", b"eval("];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2025-69985/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded FUXA (@frangoteam) version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2025-69985/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the marked fixture request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** Consult the linked project and CVE record for affected versions and fix status. This report does not establish a fixed release. [Project reference](https://github.com/frangoteam/FUXA/blob/master/server/api/jwt-helper.js)

## Fixture and probes

The benign probe posted a benign script with the fixture's accepted authorization value. The marked fixture probe posted a child_process payload with no Authorization header. The fixture incremented its marker when an unauthenticated script reached the executor.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the marked fixture probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).

## Test scope

The fixture counted selected script markers on the runscript route when an Authorization header was absent. The module permits any present Authorization header. It does not validate a token or inspect Referer, and the test did not exercise the affected FUXA middleware or execute code.
