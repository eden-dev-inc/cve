# VITEC EZ TV: unauthenticated ASPX upload to remote code execution (CVE-2026-82504)

An unauthenticated caller can use the affected VITEC EZ TV upload handler to write an executable file into a web-accessible directory. When the web server executes that file, the attacker can run code with its privileges.

## The vulnerability

The affected versions and upgrade guidance are listed above. The Eden policy and module were tested against the HTTP fixture described below.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/EZhander",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** The module checks the fixture upload route and refuses the request when the target or body contains one of the two selected ASP.NET filename markers.

```rust
const ROUTE: &[u8] = b"/EZhander/upload";
static MARKS: [&[u8]; 2] = [b".aspx", b".ashx"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-82504/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded VITEC EZ TV Platform Server version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-82504/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the marked fixture request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** Upgrade to 8.5.0 or later, or use the vendor's patch for supported 8.3.0, 8.3.1, 8.4.0, and 8.4.1 installations. Releases older than 8.3.0 should upgrade. [Publisher advisory](https://www.vulncheck.com/advisories/vitec-ez-tv-platform-server-unauthenticated-file-upload-via-uploadhandler-ashx)

## Fixture and probes

The benign probe uploaded an MP4 presentation. The marked fixture probe uploaded shell.aspx. The fixture incremented its marker when an ASPX-named upload reached the handler.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the marked fixture probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).

## Test scope

The fixture checked selected ASP.NET extension markers in the request target and body. The advisory identifies X-FILENAME as the input that controls the uploaded filename. The module does not check that header, and the test did not use VITEC or execute a file.
