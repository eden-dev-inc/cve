# VITEC EZ TV: unauthenticated ASPX upload to remote code execution (CVE-2026-82504)

The VITEC EZ TV Platform Server's upload handler lets an unauthenticated attacker on the network upload arbitrary files — including malicious ASPX pages the web server runs. Remote code execution on a streaming platform, with no login and no user action.

## The vulnerability

The upload handler writes caller-supplied files into the web root without extension confinement, so ASPX uploads execute with the server's privileges. Eden fronts the EZ TV web interface, so the executable upload rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/EZhander",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_eztvupload_v1 waits for a complete request, matches the upload handler route, and refuses bodies naming ASP.NET executable uploads (.aspx, .ashx). Ordinary media uploads continue.

```rust
const ROUTE: &[u8] = b"/EZhander/upload";
static MARKS: [&[u8]; 2] = [b".aspx", b".ashx"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-82504/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded VITEC EZ TV Platform Server version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-82504/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-82504) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe uploaded an MP4 presentation. The advisory-shaped probe uploaded shell.aspx. The fixture incremented its marker when an ASPX-named upload reached the handler.

## Measured comparison (2026-11-13 UTC)

The rule matches the recorded ASP.NET extension markers (.aspx, .ashx); alternate executable mappings (asax, ascx) were not enumerated and are a bypass to record. The durable fix is the vendor's upload confinement.

## Signed module authority

Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
