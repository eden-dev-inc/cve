# vBulletin: eval injection in the template runtime (CVE-2026-61511)

An unauthenticated caller can run arbitrary PHP through vBulletin's template runtime by placing an eval expression in the `pagenav[pagenumber]` parameter on `/vb5/template/runtime.php`. Successful exploitation executes with the web server's privileges, exposing the forum database credentials and the host.

## The vulnerability

vBulletin 5.x and 6.x releases before 6.2.2 pass the `pagenav[pagenumber]` request parameter into template evaluation on `/vb5/template/runtime.php` without separating it from code, so an unauthenticated caller reaches `eval` through the public template runtime. Eden fronts the vBulletin web tier, so the parameter rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on `/vb5/template/runtime.php` and its descendants. This is a coarse rule: it also blocked the benign navigation probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/vb5/template/runtime.php",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** `gabriel_vbulletin_v1` waits for a complete request, checks whether the target starts with `/vb5/template/runtime.php`, and looks for eval-injection markers in the full target and body. Without a marker the module returns Continue, which passed the benign `pagenav[pagenumber]=2` navigation request.

```rust
const ROUTE: &[u8] = b"/vb5/template/runtime.php";
static NEEDLES: [&[u8]; 5] = [b"eval(", b"assert(", b"system(", b"php://", b"${"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-61511/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded vBulletin version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declarative policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-61511/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds; re-approve, re-admit, and reactivate a replacement operation to restore protection. Keep the route isolated during the change window.

**Vendor update.** vBulletin 6.2.2 carries the durable fix; the [advisory](https://cve.now/CVE-2026-61511) links the vendor's update instructions. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe requested page 2 of a thread through the same route and parameter the advisory names. The advisory-shaped probe placed `eval(base64_decode(...))` in `pagenav[pagenumber]`. The fixture incremented its marker when the injected expression reached the template handler.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's template-eval counter. The declarative tier blocked the benign probe on the same route (the recorded false positive); the module tier refused only the marker-bearing request.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign pagenav request | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped eval payload | 200, 1 | 403, 0 | 403, 0 |

The rule is a marker scan over the raw target and body: even a template comment naming one of the markers is refused. PHP constructs and encodings that avoid these exact byte sequences were not exercised. The route scope is the advisory's public runtime path.
