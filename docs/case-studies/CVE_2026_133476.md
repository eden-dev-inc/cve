# Dolibarr USF SQL filters injection (CVE-2026-133476)

An authenticated remote caller can submit a crafted `sqlfilters` parameter to a Dolibarr REST API list endpoint (before 24.0.3) and bypass the universal-search-criteria field gate: operands with more than one dot skip the forbidden-field check (a db-prefix existence oracle / SQL error leak), and `pass_temp` — the password-reset hash — is missing from the forbidden list, letting a caller probe it with sequential `like:` comparisons and take over accounts. Update Dolibarr to 24.0.3.

**Result.** Both published bypass shapes reached the fixture's simulated SQL fragment on every attack probe in the baseline (authenticated REST `sqlfilters`, GET and POST forms): a two-dot operand (`llx_db.llx_user.pass:=:1`) escapes 24.0.2's single-prefix stripper (`preg_replace('/^[a-z0-9_]+\./i')` strips only one prefix) and reaches the WHERE fragment — the vendor's db-prefix existence oracle — and `t.pass_temp:like:'ab%'` reaches the WHERE because 24.0.2's always-forbidden list (`pass`, `pass_crypted`, `api_key`) omits `pass_temp` — the account-takeover path. The native module refused every attack shape with HTTP 403 before release, while every benign filter kept HTTP 200 (bare and single-alias-prefixed ordinary fields, multi-criteria AND-joined filters) and the outside-scope control kept passing. After revocation the interlay failed closed rather than silently re-exposing the API, and a replacement operation restored the refusal.

## The vulnerability

Dolibarr's REST API list endpoints (`/api/index.php/users`, `/thirdparties`, `/products`, … — see e.g. `htdocs/user/class/api_users.class.php:86,132`) accept a `sqlfilters` parameter "Universal SQL filter string … `(t.field:operator:value)`" which `forgeSQLFromUniversalSearchCriteria()` (`htdocs/core/lib/functions.lib.php`) parses per-criterion via `dolForgeSQLCriteriaCallback()`, building SQL WHERE fragments. The callback's field gate in 24.0.2:

```php
$operand = preg_replace('/[^a-z0-9\._]/i', '', trim($tmp[0]));
$operandwithoutprefix = preg_replace('/^[a-z0-9_]+\./i', '', $operand);  // strips ONE prefix
if (in_array(strtolower($operandwithoutprefix), $newforbiddenfields)) {   // pass, pass_crypted, api_key
    return '1=1';
}
```

Two bypasses (both fixed in 24.0.3):

- **Multi-dot operands.** The stripper removes only one alias prefix, so an operand like `dbprefix.table.field` (`substr_count('.') > 1`) skips the forbidden-field check entirely. The 24.0.3 fix neutralizes any operand with more than one dot: *"An operand with more than one level of prefix (example: dbprefix.table.field) is not valid into a USF criteria, we neutralize it like a forbidden field to avoid any leak or SQL error based on db prefix existence."*
- **`pass_temp`.** The always-forbidden list omits `pass_temp` (the password-reset token), so `t.pass_temp:like:'prefix%'` probing yields a db-prefix/token-existence oracle — the vendor's account-takeover path. 24.0.3 adds `$newforbiddenfields[] = 'pass_temp';`.

## Fixture verification (2026-11-19 UTC)

The fixture mirrors the upstream 24.0.2 parser (read from the vendor's 24.0.2 tag) — criteria regex `\(([a-zA-Z0-9_\.]+):([<>!=insotlke]+):([^\(\)]+)\)` case-insensitive, single-prefix stripper, the 24.0.2 forbidden list — and its oracle records a `dolibarr_primitive` effect when either bypass shape reaches the simulated WHERE fragment:

| Probe | `sqlfilters` | Baseline (24.0.2 semantics) |
| --- | --- | --- |
| benign_rowid | `(t.rowid:=:1)` | 200 — clean WHERE `t.rowid = 1` |
| benign_like | `(t.ref:like:'SO-%')` | 200 — clean quoted LIKE |
| benign_multi_criteria | `((t.rowid:=:1) AND (t.email:like:'a@b.c'))` | 200 — both criteria clean |
| attack_multidot_pass | `(llx_db.llx_user.pass:=:1)` | 200 — **`t.llx_db.llx_user.pass = 1` reaches the fragment** (stripper removed only `llx_db.`) |
| attack_multidot_generic | `(llx_societe.db.rowid:=:1)` | 200 — **2-dot operand in the fragment** |
| attack_pass_temp | `(t.pass_temp:like:'ab%')` | 200 — **`t.pass_temp like 'ab%'` in the fragment** |
| attack_pass_temp_post | POST form body, same | 200 — same via POST |
| neutralized_pass | `(t.pass:=:x)` | 200 — `1=1` (24.0.2 already neutralizes it) |
| benign_outside_scope | `/public/index.php?sqlfilters=(a.b.pass:=:1)` | 200 (route outside the module scope) |

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies `GET`/`POST` on the `/api/index.php` route family. This is a coarse rule: it also blocks the benign API probes on the same route (recorded false positives).

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [
            "GET",
            "POST"
          ],
          "path": "/api/index.php",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** The module scans the `sqlfilters` parameter (query string or urlencoded body) with a streaming, allocation-free parser mirroring the vendor criteria grammar: `(operand:op:value)` with operand `[A-Za-z0-9_.]+`, operator from the vendor's operator charset, value without parens. It refuses either published bypass shape after percent-decoding — an operand with more than one dot, or an operand whose final component names one of the vendor's fixed forbidden fields (`pass`, `pass_crypted`, `pass_temp`, `api_key`).

```rust
/// The vendor's fixed always-forbidden field list (24.0.3).
const FORBIDDEN: [&[u8]; 4] = [b"pass", b"pass_crypted", b"pass_temp", b"api_key"];

const OP_CHARS: &[u8] = b"<>!=insotlke";

fn lower(b: u8) -> u8 {
    if b.is_ascii_uppercase() { b + 32 } else { b }
}

fn starts_with_ci(hay: &[u8], needle: &[u8]) -> bool {
    if hay.len() < needle.len() { return false; }
    hay.iter().zip(needle).all(|(a, b)| lower(*a) == lower(*b))
}

fn is_hex(b: u8) -> bool {
    (b >= b'0' && b <= b'9') || (b >= b'a' && b <= b'f') || (b >= b'A' && b <= b'F')
}

fn hex_val(b: u8) -> u8 {
    match b {
        b'0'..=b'9' => b - b'0',
        b'a'..=b'f' => b - b'a' + 10,
        _ => b - b'A' + 10,
    }
}

fn is_op_char(b: u8) -> bool {
    let lb = lower(b);
    OP_CHARS.contains(&lb)
}

fn eq_ci(a: &[u8], b: &[u8]) -> bool {
    if a.len() != b.len() { return false; }
    a.iter().zip(b).all(|(x, y)| lower(*x) == lower(*y))
}

/// Is this criteria operand one of the two published bypass shapes?
/// Streaming scanner over the percent-decoded `sqlfilters` bytes:
///   criteria := '(' operand ':' op ':' value ')' — operand [A-Za-z0-9_.]+,
///   op from the vendor operator charset, value without parens.
/// Bypass if the operand has more than one dot (escapes the 24.0.2
/// single-prefix stripper) or names a fixed forbidden field in its final
/// component (24.0.2 misses `pass_temp`; the module enforces the whole
/// 24.0.3 list).
fn sqlfilters_is_attack(raw: &[u8]) -> bool {
    let mut opbuf = [0u8; 64];
    let mut oplen = 0usize;
    // states: 0 = idle (scan for '('), 1 = operand, 2 = operator, 3 = value
    let mut state = 0u8;
    let mut i = 0usize;
    let n = raw.len();
    while i < n {
        let b = if raw[i] == b'%' && i + 2 < n && is_hex(raw[i + 1]) && is_hex(raw[i + 2]) {
            let d = (hex_val(raw[i + 1]) << 4) | hex_val(raw[i + 2]);
            i += 3;
            d
        } else {
            let d = raw[i];
            i += 1;
            d
        };
        match state {
            0 => {
                if b == b'(' {
                    state = 1;
                    oplen = 0;
                }
            }
            1 => {
                if b.is_ascii_alphanumeric() || b == b'_' || b == b'.' {
                    if oplen < opbuf.len() {
                        opbuf[oplen] = b;
                        oplen += 1;
                    }
                } else if b == b':' {
                    if oplen == 0 {
                        // '(:' cannot start a criteria operand
                        state = 0;
                    } else {
                        state = 2;
                    }
                } else {
                    // not a criteria start (e.g. '((' or '( )')
                    state = 0;
                }
            }
            2 => {
                if is_op_char(b) {
                    // operator continues
                } else if b == b':' {
                    state = 3;
                } else {
                    state = 0;
                }
            }
            3 => {
                if b == b')' {
                    // complete criteria: apply the fixed-version field gate
                    if operand_is_attack(&opbuf[..oplen]) {
                        return true;
                    }
                    state = 0;
                } else if b == b'(' {
                    // a '(' inside the value region invalidates the criteria
                    state = 0;
                }
                // any other byte is value content
            }
            _ => { state = 0; }
        }
    }
    false
}

/// The fixed 24.0.3 operand gate: neutralize (here: refuse) operands with
/// more than one dot, or whose final component names a forbidden field.
fn operand_is_attack(op: &[u8]) -> bool {
    let mut dots = 0usize;
    for &b in op {
        if b == b'.' {
            dots += 1;
        }
    }
    if dots > 1 {
        return true;
    }
    let last = match op.iter().rposition(|&b| b == b'.') {
        Some(p) => &op[p + 1..],
        None => op,
    };
    for f in FORBIDDEN.iter() {
        if eq_ci(last, f) {
            return true;
        }
    }
    false
}

/// Find the raw (urlencoded) value bytes of a form key, starting at `from`.
fn find_value(src: &[u8], key: &[u8], from: usize) -> Option<(usize, usize)> {
    let n = src.len();
    let mut i = from;
    while i + key.len() <= n {
        let edge = i == 0 || src[i - 1] == b'&' || src[i - 1] == b'?';
        if edge {
            let mut m = true;
            for (j, kb) in key.iter().enumerate() {
                if lower(src[i + j]) != lower(*kb) {
                    m = false;
                    break;
                }
            }
            if m {
                let start = i + key.len();
                let mut end = start;
                while end < n && src[end] != b'&' && src[end] != b' '
                    && src[end] != b'\r' && src[end] != b'\n' {
                    end += 1;
                }
                return Some((start, end));
            }
        }
        i += 1;
    }
    None
}

fn request_is_attack(head: &[u8], body: &[u8]) -> bool {
    // Route gate: the REST API family.
    let line_end = head.iter().position(|&b| b == b'\r').unwrap_or(head.len());
    let reqline = &head[..line_end];
    let sp = reqline.iter().position(|&b| b == b' ').unwrap_or(0);
    if !starts_with_ci(&reqline[sp + 1..], ROUTE) {
        return false;
    }
    // The sqlfilters parameter rides the query string or a urlencoded body.
    for src in [head, body] {
        if let Some((s, e)) = find_value(src, b"sqlfilters=", 0) {
            if sqlfilters_is_attack(&src[s..e]) {
                return true;
            }
        }
    }
    false
}
```

**Stated limits.** The module enforces the *fixed 24.0.3* field list, which is stricter than 24.0.2's neutralization for the single-dot forbidden names (`t.pass` is neutralized to `1=1` by 24.0.2 but refused at the boundary by the module — a filter naming a password or key field is never legitimate; the `neutralized_pass` probe records this deliberately). The scan enforces the operand grammar only; values and operators are left to the product's own escaping (24.0.2 quotes/escapes values). The durable fix is Dolibarr 24.0.3.

## Implement the remediation

1. **Prepare the target.** Confirm the Dolibarr version (`htdocs/core/lib/functions.lib.php` / release notes) against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission.
2. **Apply the declarative policy.** Set `INTERLAY` to the target interlay UUID. Save the interlay's settings, place the tier-1 policy in `settings.remediation`, and PATCH with a fresh `Idempotency-Key`. Read back `remediation_status.state == ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the published source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and all shards are acknowledged.
4. **Verify, revoke, and restore.** Replay the benign and marked probes and compare the fixture oracle. Revoke and confirm the route fails closed (503); re-approve, re-admit and reactivate a replacement operation to restore protection.
