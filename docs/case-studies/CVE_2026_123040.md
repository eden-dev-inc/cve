# TrueConf Server: privilege escalation with prior code execution (CVE-2026-123040)

*[cve.now](https://cve.now/CVE-2026-123040) entry. Product: TrueConf Server
(Linux) 4.7.2 up to, but not including, 5.5.6 (fixed in 5.5.6).*

Eden terminates the HTTP connection to the affected product, evaluates a
declarative policy and — in tier 2 — a separately compiled native Rust module
under signed module authority, before any byte reaches the application. It does
**not** patch the affected component; the vendor's fixed release remains the
durable repair.

**Status: NA-grade — no HTTP-boundary remediation claim. No module compiled,
no run performed. Recorded as a reference entry.**

## The vulnerability

An attacker who **already has the ability to execute arbitrary code as the
`trueconf` user** on a system running TrueConf Server (Linux) 4.7.2 ≤ version
< 5.5.6 can escalate to further execution. The precondition is prior local
code execution in the `trueconf` security context.

## Why no boundary proof

The exploit prerequisite is a compromise that has *already happened* — code
running as the service user on the host. There is no HTTP delivery shape whose
arrival at the vulnerable component can be refused by an ingress rule: the
attacker's legs are local, not the request path. A deny rule on TrueConf's HTTP
surface would not interdict a local escalation and would only destroy the
legitimate capability (the product's API/room management) — the blanket-block
pattern this portfolio explicitly rejects as low quality.

We record this honestly as **NA-grade**: no tier-1 or tier-2 module was built,
no live run claimed, no fixture fabricated to imply one. The vendor's fixed
release (5.5.6) is the repair; host-level containment for the `trueconf`
user is the compensating control.
