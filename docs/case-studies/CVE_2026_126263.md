# FortiMail: unauthenticated SQL injection to code execution (CVE-2026-126263)

Fortinet FortiMail has an SQL injection flaw that may let an attacker execute unauthorized code or commands with specially crafted requests — reachable remotely, without logging in, per the advisory's CVSS vector. A mail-gateway compromise cascades to every domain it filters.

## The vulnerability

The appliance interpolates unauthenticated parameters into SQL, so a crafted value reads or writes the mail database and reaches command execution. Eden fronts the appliance's HTTP interface, so the injection rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/api/v2/mail/search",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_ftmail2_v1 waits for a complete request, matches the FortiMail API route, and refuses bodies carrying SQL injection markers (' OR, union select, 1=1) — the recorded injection shapes.

```rust
const ROUTE: &[u8] = b"/api/v2/mail";
static NEEDLES: [&[u8]; 3] = [b"' or", b"union select", b"1=1"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-126263/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Fortinet FortiMail version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-126263/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-126263) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe searched mail with a clean query. The advisory-shaped probe injected a SQL predicate. The fixture incremented its marker when injected SQL reached its query engine.
