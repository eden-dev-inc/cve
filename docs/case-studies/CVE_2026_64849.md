# MLflow: unauthenticated SSRF in webhook delivery (CVE-2026-64849)

An unauthenticated caller can make affected MLflow servers fetch internal resources through webhook testing and read the responses. This can expose otherwise unreachable services and cloud metadata.

**Patch title.** MLflow SSRF in Webhook Delivery Guard (`mlflow-ssrf-in-webhook-delivery-guard` in the registry). The [original source snapshot](https://github.com/eden-dev-inc/cve/blob/9a7217a0a882374c5ab97d74c96df9b77637f923/docs/case-studies/modules/CVE-2026-64849.rs) preserves the source available for the historical report.

**Result.** The marked request reached the synthetic backend in the baseline. Both protected configurations returned HTTP 403 for that request and the backend counter did not change. The native module passed the benign probe. The recorded comparison used a separate synthetic endpoint. The vendor vulnerability occurs when an outbound webhook follows a redirect or resolves the destination again.

## The vulnerability

The affected versions and upgrade guidance are listed above. The Eden policy and module were tested against the HTTP fixture described below.

## Synthetic HTTP controls

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/api/2.0/mlflow-webhook",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** The rule checks the fixture webhook route for selected URL scheme strings in the target or body.

```rust
const ROUTE: &[u8] = b"/api/2.0/mlflow-webhook";
static SCHEMES: [&[u8]; 3] = [b"://", b"%3a%2f%2f", b"%3a//"];
```

## Implement the remediation

Upgrade affected MLflow installations to 3.15.0 or later using the project advisory. [Advisory and remediation guidance](https://github.com/mlflow/mlflow/security/advisories/GHSA-7gwp-5pfp-969j)

The recorded module and policy reproduce the synthetic comparison. [Fixture API example](../../cve/CVE-2026-64849/http-request-filter/api.md)

## Fixture and probes

The ordinary webhook probe omitted a URL. The marked probe supplied a URL and the fixture counted its delivery.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the marked fixture probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).

## Test scope

The fixture rule matches /api/2.0/mlflow-webhook and scans for selected URL scheme strings. MLflow's advisory identifies /api/2.0/mlflow/webhooks/{id}/test. The test did not follow redirects, resolve DNS, or send an outbound request.
