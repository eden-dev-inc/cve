# cPanel and WHM: login-flow authentication bypass (CVE-2026-41940)

An unauthenticated remote caller can bypass the cPanel and WHM login flow and take over the hosting control panel. The flaw is on CISA's exploited-in-the-wild catalog, so an internet-exposed panel should be patched immediately; a takeover grants the attacker every site, database, and mail account on the server.

## The vulnerability

The cPanel and WHM vulnerability affects session handling during login. The disclosed technique injects CRLF-delimited fields into session data. The Eden fixture exercised a passwordless form request on the web login route.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on `/login` and its descendants. This is the bluntest recorded tier: it blocks every login, benign or not, and is only acceptable while the panel is being upgraded or retired behind Eden.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/login",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** `gabriel_cpanel_v1` waits for a complete request, matches POSTs to `/login`, and refuses a form body that names a `user` but carries no `password` parameter — the advisory's passwordless login-flow shape. Requests that present a password continue, which passed the benign probe.

```rust
const ROUTE: &[u8] = b"/login";
// refuse POST bodies with user= and no password=
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-41940/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded WebPros cPanel and WHM version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declarative policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-41940/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds; re-approve, re-admit, and reactivate a replacement operation to restore protection. Keep the route isolated during the change window.

**Vendor update.** Apply the fix for the installed release line. The [advisory](https://support.cpanel.net/hc/en-us/articles/40073787579671-cPanel-WHM-Security-Update-04-28-2026) documents affected versions and update guidance.

## Fixture and probes

The benign probe posted a correct username and password to `/login`. The advisory-shaped probe posted `user=admin&goto=%2Fcpanel` with no password parameter. The fixture incremented its marker when a session was granted without a password.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's session-granted-without-password counter. The declarative tier blocked the benign login too (the recorded false positive); the module refused only the passwordless shape.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign credential login | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped passwordless login | 200, 1 | 403, 0 | 403, 0 |

The module inspects the raw form body for `user=` without `password=`; JSON or alternative encodings of the same bypass were not exercised, and the panel's other ports (2087, 2096) are separate interlays not covered by this recording. The `goto` value is not validated.



## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal.
