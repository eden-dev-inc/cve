# pgAdmin 4: OS command execution through COPY TO PROGRAM in query export (CVE-2026-116241)

An authenticated low-privilege database account can run operating-system commands on the pgAdmin 4 host by sending a crafted query through its Import/Export Data tool. The permission it needs is granted to non-administrators by default, so any database user may reach the server's shell.

## The vulnerability

pgAdmin's Import/Export tool builds a COPY statement from the submitted query, so an attacker who controls the query reaches TO PROGRAM and the pgAdmin host shell. Eden fronts the pgAdmin web tier, so the crafted query rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the query route and its descendants. This blocks every query, benign or not (the recorded false positive) — trading the editor for safety during upgrade.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/sqleditor/query",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_pgadmin_v1 waits for a complete request, matches targets starting with the query route, and refuses bodies carrying the COPY ... TO PROGRAM command shape. Ordinary SELECT queries continue.

```rust
const ROUTE: &[u8] = b"/sqleditor/query";
if find_ignore_case(body, b"to program").is_some() { return Ok(Decision::Refuse); }
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-116241/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded pgAdmin 4 version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declarative policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-116241/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** See the advisory for the fixed release carries the durable fix; the [advisory](https://cve.now/CVE-2026-116241) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe posted SELECT 1. The advisory-shaped probe posted COPY (SELECT 1) TO PROGRAM — the command-execution shape of the export tool. The fixture incremented its marker when a program-exec command reached its query engine.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign SELECT query | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped TO PROGRAM export | 200, 1 | 403, 0 | 403, 0 |

The rule matches the TO PROGRAM command shape; other SQL command-execution paths (pg_read_file, lo_import) were not exercised. The real-world path is an authenticated low-privilege database user — the recorded risk is that default grants reach the host shell.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
