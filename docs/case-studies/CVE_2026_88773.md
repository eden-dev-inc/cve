# NetScaler: security-control bypass via HTTP request smuggling (CVE-2026-88773)

Citrix NetScaler ADC and NetScaler Gateway interpret HTTP requests inconsistently, letting an attacker smuggle requests to bypass security controls or interfere with other users' traffic passing through the appliance. A front-door device that mis-parses framing is a control-integrity failure for everything behind it.

## The vulnerability

The appliance's parser resolves the CL/TE ambiguity differently than its own backend, letting a smuggled request split into one the controls see and one they do not. Eden's interlay fronts the appliance — and its framing layer refuses the ambiguous header pair outright, a normalization that kills the ambiguity before it can ever reach the fronted device.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/epa",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_nssmuggle_v1 waits for a complete request and refuses any request presenting both Content-Length and Transfer-Encoding framing headers — the ambiguity smuggling depends on. On the tested 1.103.0 interlay the smuggling shape was refused by the gateway's own framing validation before any policy or module (see the measured comparison); the rule is recorded as defense-in-depth and its refusal was not reachable through this profile.

```rust
let has_cl = header_value(hdrs, b"content-length").is_some();
let has_te = header_value(hdrs, b"transfer-encoding").is_some();
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-88773/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Citrix NetScaler ADC / NetScaler Gateway version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-88773/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-88773) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe sent a cleanly framed request. The advisory-shaped probe presented both framing headers with a chunked smuggled prefix — the classic CL.TE shape. The fixture's marker never fired because the interlay refused the frame before release at every tier.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign clean-framed request | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped CL.TE smuggled frame | 400 framing, 0 | 400 framing, 0 | 400 E1A44, 0 |

Product finding (tier-0 normalization): the 1.103.0 interlay returns 400 \"HTTP request framing is invalid\" for requests presenting both Content-Length and Transfer-Encoding — RFC 7230's required anti-smuggling behavior — at the framing layer, before policy or module evaluation. With the module active the same shape surfaces as 400 E1A44 (inspection input malformed); under tier-1 it is the framing 400. The backend effect is therefore prevented in every arm, but by the gateway's framing validation rather than a module 403, which this profile cannot demonstrate for this shape. The rule remains correct defense-in-depth for deployments whose fronting path lacks this normalization.
