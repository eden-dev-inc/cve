# Airflow: bulk task-instance authorization against the wrong dag (CVE-2026-41084)

Apache Airflow's bulk Task Instances API (PATCH/DELETE /api/v2/dags/{dag_id}/dagRuns/{dag_run_id}/taskInstances) evaluated authorization against the dag_id in the URL path while operating on the dag_id/dag_run_id extracted from request-body entity fields — an authenticated UI/API user with edit permission on one Dag could mutate Task Instance state in any other Dag.

The native module refused the advisory-shaped request (403, counter unchanged) while the benign probe stayed HTTP 200 — surgical, verified against an independent backend counter through Eden 1.103.0.

## The vulnerability

The API authorizes the path dag but mutates the body dag, so a user with edit rights on their own DAG modifies other DAGs' task instances. Eden fronts the API server, so the mismatched write rides an HTTP request Eden can refuse before release — by comparing the body dag_id against the path dag.

## The Eden patch

**Tier 1 — declaratory policy.** The recorded policy denies every method on the recorded route family and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/api/v2/dags",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** airflow_bulk_task_instance_dag_guard waits for a complete request, matches task-instance and XCom routes, refuses unauthenticated writes, refuses deserialization gadget markers in body values, and refuses bulk PATCH/DELETE bodies whose dag_id differs from the path dag — the task-instance family's four shapes. Bound, clean, matching writes continue.

```rust
static GADGETS: [&[u8]; 6] = [b"__import__", b"os.system", b"import_string", b"subprocess", b"rO0AB", b"eval("];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-41084/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Apache Airflow (bulk Task Instances API) version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged.
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-41084) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe PATCHed the bulk endpoint with a body dag_id matching the path dag. The advisory-shaped probe PATCHed the same path with a body naming a different dag. The fixture incremented its marker when a mismatched dag reached the mutation.

## Measured comparison (2026-11-14 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign matching bulk write | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped cross-dag write | 200, 1 | 403, 0 | 403, 0 |

The rule refuses bulk PATCH/DELETE task-instance bodies whose dag_id differs from the path dag — a genuinely request-shape-level fix for this authorization flaw, not just a marker scan. Dag-run mismatches (body dag_run_id vs path) were not separately parsed and are a bypass to record. The durable fix is the vendor's authorization patch. This module also carries the family's auth-presence and gadget rules (see CVE-2026-68982/67260).
