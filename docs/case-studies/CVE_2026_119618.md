# Apache HTTP Server: mod_http2 heap corruption and RCE in assign_headers (CVE-2026-119618)

[Source and API bundle](../../cve/CVE-2026-119618/README.md)

*[cve.now](https://cve.now/CVE-2026-119618) entry. Product: Apache HTTP Server
(lab: `gabriel-modhttp2-app`).*

Eden terminates the HTTP connection to the affected product, evaluates a
declarative policy and — in tier 2 — a separately compiled native Rust module
under signed module authority, before any byte reaches the application. It does
**not** patch the affected component; the vendor's fixed release remains the
durable repair.

**Status: Remediated (tier 1 + tier 2), live-proven 2026-11-11T17:02:28Z on the
installed `eden-product-release:1.103.0` lab container.**

## The vulnerability

`mod_http2`'s `assign_headers` corrupts the heap when a crafted continuation
frame reassigns a stream's header state, enabling RCE. The fixture
(`make_modhttp2`, port 18316) reproduces the delivery shape: a frame payload
carrying the continuation-reassignment marker records a heap-corruption mark.

## The Eden patch

**Tier 1 — declarative policy (blunt, fail-closed):** deny every request under
`/h2frame`, ordinary stream assignments included — false positives measured
below.

**Tier 2 — native Rust module `gabriel_modhttp2_v1` (surgical):** refuses
frame bodies carrying the continuation-reassignment marker; ordinary h2
header assignments pass unchanged.

## Authority lifecycle and negatives

Import 201, `activation: explicit_required`; publisher `enroll_key`, host
`inventory` + `approve`, reader `inspect` refused 403; tampered-statement admit
400; invalid-signature admit 403; `admit` prepared (not serving), `activate`
→ receipt `serving_now`, applied shards **2/2**. Revoke → the identical attack
gets **503** (fail-closed); re-approve + re-activate → 403 again. All recorded
in the evidence JSON.

## Honest scope

The fixture reproduces the continuation-reassignment shape on an HTTP/1.1
delivery route, not a real h2 session stream — the binary h2 framing path is
out of scope. This is an HTTP-layer content rule; the vendor fix remains the
durable repair. Module binary SHA-256 `8c4c7050…`, source
`modules/gabriel_modhttp2_v1.rs`.
