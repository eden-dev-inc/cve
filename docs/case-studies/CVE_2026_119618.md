# Apache HTTP Server: mod_http2 heap corruption and RCE in assign_headers (CVE-2026-119618)

Concurrent requests can trigger a race in affected Apache HTTP/2 header assignment and may lead to code execution. Upgrade the relevant httpd or standalone mod_h2 release to remove the unsafe shared-state behavior.

**Status: Remediated (tier 1 + tier 2), live-proven 2026-11-11T17:02:28Z on the
installed `eden-product-release:1.103.0` lab container.**

## The vulnerability

`mod_http2`'s `assign_headers` corrupts the heap when a crafted continuation
frame reassigns a stream's header state, enabling RCE. The fixture
(`make_modhttp2`, port 18316) reproduces the delivery shape: a frame payload
carrying the continuation-reassignment marker records a heap-corruption mark.

## The Eden patch

**Tier 1 — declarative policy (blunt, fail-closed):** deny every request under
`/h2frame`, ordinary stream assignments included — false positives measured
below.

**Tier 2 — native Rust module `gabriel_modhttp2_v1` (surgical):** refuses
frame bodies carrying the continuation-reassignment marker; ordinary h2
header assignments pass unchanged.

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md).

1. **Prepare the target.** Verify the loaded product and version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Open the [deployment example](../../cve/CVE-2026-119618/http-request-filter/deployment.json) and [API instructions](../../cve/CVE-2026-119618/http-request-filter/api.md). The bundle identifies module `gabriel_modhttp2_v1` version `1.0.0` and the SDK revision in [patch.toml](../../cve/CVE-2026-119618/http-request-filter/patch.toml). Run the policy extraction from the adapter directory.
2. **Apply the declarative policy.** Scope the policy to `/h2frame` and descendants (all methods, `deny`). Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Run an authenticated `GET /api/v1/interlays/{interlay}` with `X-Eden-Verbose: true`. Save its complete current settings object as `current-settings.json` and retain the prior remediation declaration for recovery. Set `IDEMPOTENCY_KEY` to a fresh key for this intended mutation.

```sh
jq -e '.tier1' deployment.json > remediation.json
jq -e --slurpfile policy remediation.json \
  '.remediation = $policy[0] | {settings: .}' current-settings.json \
  > interlay-update.json
eden api request PATCH "/api/v1/interlays/$INTERLAY" \
  --header "Idempotency-Key:$IDEMPOTENCY_KEY" \
  --body-file interlay-update.json --content-type application/json --confirm
```

3. **Verify the serving policy.** Read back the interlay.

```sh
eden api request GET "/api/v1/interlays/$INTERLAY" \
  --header 'X-Eden-Verbose:true'
```

Check that `remediation_status.state` is `ready` and both desired and effective SHA-256 values match the intended declaration. Replay the benign and marked requests in the recorded comparison on an isolated target. Check the recorded response and backend outcome for each probe. Use the request and expected-status table in the linked API example alongside the observed comparison.
4. **Restore the previous policy.** Coordinate the change with any other operator updating this interlay. Read current settings again and merge the saved remediation field into them. If the prior settings had no remediation field, omit it in the replacement. Send the same PATCH with a fresh idempotency key, then read back the intended state. Repeat the verification probes. Keep the affected route isolated if restoring the prior settings reopens exposure.

### Native module `gabriel_modhttp2_v1`

1. **Prepare the archive.** Use the [version 1.0.0 bundle](../../cve/CVE-2026-119618/README.md) for source, target, and build profile. Configure independent host approval for the installed Eden release. Use the authenticated principals required by the native authority contract. Set `PATCH_ARCHIVE` to the exact schema-2 package and `PACKAGE_SHA256` to its expected archive digest. Verify and import it using the same target interlay.

```sh
printf '%s  %s\n' "$PACKAGE_SHA256" "$PATCH_ARCHIVE" | sha256sum --check &&
  eden api request PUT "/api/v1/interlays/$INTERLAY/patch-packages/$PACKAGE_SHA256" \
    --body-file "$PATCH_ARCHIVE" \
    --content-type application/vnd.eden.patch-package.v2+tar --confirm
```

2. **Approve and activate.** Enroll the publisher key, attest host software inventory, and inspect the configuration returned by import. Obtain independent host approval. Sign the typed statement with the matching SDK. Send the admit action followed by activate for the prepared operation. Use the applicable typed payload for each action in `authority-action.json`.

```sh
eden api request POST "/api/v1/interlays/$INTERLAY/native-authority" \
  --body-file authority-action.json --content-type application/json --confirm
```

3. **Verify the operation.** Read the receipt through the same endpoint. Confirm `serving_now` and the full expected shard acknowledgment. Repeat the report’s benign and marked probes and check the backend observations.
4. **Revoke or restore.** Send revoke with the exact operation UUID. Mandatory protection can refuse traffic until a compatible operation is approved and activated. Verify the restored receipt and repeat the probes.

**Vendor update.** Use the [advisory](https://httpd.apache.org/security/vulnerabilities_24.html) to identify the supported update or workaround for the installed release. The advisory data used here supplies no fixed version. Confirm the running version and verify the affected feature after the change.

in the evidence JSON.

## Honest scope

The fixture reproduces the continuation-reassignment shape on an HTTP/1.1
delivery route, not a real h2 session stream — the binary h2 framing path is
out of scope. This is an HTTP-layer content rule; the vendor fix remains the
durable repair. Module binary SHA-256 `8c4c7050…`, source
`modules/gabriel_modhttp2_v1.rs`.
