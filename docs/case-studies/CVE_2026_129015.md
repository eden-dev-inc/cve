# ReviewX storefront SVG XXE (CVE-2026-129015)

A visitor to a WordPress site running the ReviewX plugin (3.0.1 and earlier; fixed in 3.0.2) can submit a review with an SVG attachment whose DTD declares an external `SYSTEM` entity. The plugin sanitizes the SVG with `SvgSanitizer::sanitize()` (`app/Utilities/SvgSanitizer.php`) — loading it via `DOMDocument::loadXML($svgContent, LIBXML_NOENT | LIBXML_NONET | LIBXML_COMPACT)` and only removing the DOCTYPE *after* the load. With `LIBXML_NOENT`, entity substitution happens during the load: the declared file's contents are read into memory and appear inside the sanitized markup the plugin returns and stores with the review — an unauthenticated arbitrary local file read through the storefront review form.

**Result.** The real plugin sanitizer — the actual `SvgSanitizer::sanitize()` from the reviewx 3.0.1 release, executed in a php 8.2 container — was fed the crafted SVG (`<svg…><text>&xxe;</text></svg>` with a `<!DOCTYPE` declaring `<!ENTITY xxe SYSTEM "file:///etc/hostname">`). The sanitizer's output contained `<text>907fbc61887e</text>`: the entity expanded during `loadXML(LIBXML_NOENT)` and the substituted file content — the container's hostname, read from `/etc/hostname` — appeared in the markup the plugin returns and stores. A benign SVG passed through the sanitizer normally (same output shape, no expansion), as did an SVG carrying only an escaped `&amp;xxe;` text node (no DTD). The native module refused the XXE-carrying submission with HTTP 403 before release — no DTD-carrying SVG reached the sanitizer while the module served — while the benign SVGs, a PNG attachment carrying a DTD marker (not an XML part), and a same-shape submission on a different route all passed. After revocation the interlay failed closed rather than silently re-exposing the endpoint, and a replacement operation restored the refusal.

## The vulnerability

The storefront review form posts to the plugin's REST route (`POST /wp-json/reviewx/api/v1/storefront/reviews`, guarded by a storefront nonce issued to any visitor), carrying `attachments[]` file parts. `ReviewService::fileUpload()` passes SVG uploads (by extension or `image/svg+xml` type) to `SvgSanitizer::sanitizeFile()`, which calls `sanitize()`:

```php
// reviewx 3.0.1 — app/Utilities/SvgSanitizer.php
$dom = new \DOMDocument();
$dom->formatOutput = false;
$dom->preserveWhiteSpace = true;
$dom->strictErrorChecking = false;
// Load the SVG as XML.
$loaded = $dom->loadXML($svgContent, \LIBXML_NOENT | \LIBXML_NONET | \LIBXML_COMPACT);
...
// Remove the DOCTYPE if present (prevent entity expansion attacks).
foreach ($dom->childNodes as $child) {
    if ($child instanceof \DOMDocumentType) {
        $dom->removeChild($child);
        break;
    }
}
```

The DOCTYPE is removed *after* the load. `LIBXML_NOENT` enables entity substitution *during* the load — so by the time the DOCTYPE is stripped, a declared `SYSTEM` entity has already been resolved and its file contents substituted into the document. `LIBXML_NONET` blocks network protocols (`http://`), but `file://` is a local scheme and resolves. The substituted content then survives into the returned markup (the plugin strips `<`/`>` markup in the *output filtering*, but the text content of the entity — including newlines and file data — remains).

## Real-product verification (2026-11-20 UTC)

The fixture runs the **real plugin sanitizer** (the `SvgSanitizer.php` from the reviewx 3.0.1 release zip, `ABSPATH` defined) in a php 8.2 container. Each probe shape's upload was run through the real `sanitize()` and the outputs recorded:

| Shape | Real sanitizer output |
| --- | --- |
| clean SVG (`<rect>…`) | pass-through — `<svg…><rect …/></svg>` (76 bytes, no expansion) |
| XXE SVG (`<!ENTITY xxe SYSTEM "file:///etc/hostname">` + `<text>&xxe;</text>`) | **`<svg…><text>907fbc61887e\n</text></svg>`** — the entity expanded; the substituted `/etc/hostname` content is in the returned markup |
| percent-encoded DTD spelling (`%3C%21DOCTYPE…`) | rejected by the sanitizer (0 bytes) — **honest control: XML does not percent-decode, so this is not a product-level XXE** |
| SVG with escaped `&amp;xxe;` text (no DTD) | pass-through (68 bytes, no expansion) |

The leaked value `907fbc61887e` is the php container's hostname — the exact bytes of `/etc/hostname`. Any file readable by the web server (configuration, `wp-config.php` secrets) can be read the same way.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies `POST` on the storefront reviews route. This is a coarse rule: it also blocks the benign review submissions on the same route (recorded false positives).

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [
            "POST"
          ],
          "path": "/wp-json/reviewx/api/v1/storefront/reviews",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** The module refuses storefront-review multipart requests whose SVG file parts (filename `.svg` or `image/svg+xml` content type) carry a DTD / external-entity declaration: the markers `<!DOCTYPE`, `<!ENTITY`, or `SYSTEM`, matched case-insensitively against the raw or percent-decoded stream — a streaming decoder with no fixed buffers (no `memcpy`/`memset` imports; closed profile). Only SVG parts are scanned: a PNG attachment carrying the literal marker passes (it is not XML, and the product never loads it as XML). Benign SVGs (no DTD — the near-universal case, and the form's own template output) pass untouched.

```rust
/// Case-insensitive match of `needle` against the percent-decoded stream
/// of `region` — no buffer, no copying: the raw stream is walked once,
/// decoding `%xx` escapes inline, and each decoded position is tried as a
/// needle match. An escape inside the needle span is handled by decoding
/// the needle cursor forward in lock-step with the region.
fn contains_ci_decoded(region: &[u8], needle: &[u8]) -> bool {
    if needle.is_empty() || region.is_empty() {
        return false;
    }
    let n = region.len();
    let nl = needle.len();
    let mut i = 0usize;
    while i < n {
        // try to match the needle starting at decoded position i
        let mut j = 0usize;
        let mut k = i;
        let mut ok = true;
        while j < nl {
            // decode the region byte at k
            let b = if region[k] == b'%' && k + 2 < n && is_hex(region[k + 1]) && is_hex(region[k + 2]) {
                (hex_val(region[k + 1]) << 4) | hex_val(region[k + 2])
            } else {
                region[k]
            };
            if lower(b) != lower(needle[j]) {
                ok = false;
                break;
            }
            j += 1;
            // advance k past the consumed byte (escape or raw)
            k = if region[k] == b'%' && k + 2 < n && is_hex(region[k + 1]) && is_hex(region[k + 2]) {
                k + 3
            } else {
                k + 1
            };
            if k > n {
                ok = false;
                break;
            }
        }
        if ok {
            return true;
        }
        // advance the start position by one decoded byte
        i = if region[i] == b'%' && i + 2 < n && is_hex(region[i + 1]) && is_hex(region[i + 2]) {
            i + 3
        } else {
            i + 1
        };
    }
    false
}

fn find_lower(hay: &[u8], needle: &[u8]) -> Option<usize> {
    if hay.len() < needle.len() { return None; }
    'o: for i in 0..=(hay.len() - needle.len()) {
        for (j, nb) in needle.iter().enumerate() {
            if lower(hay[i + j]) != lower(*nb) { continue 'o; }
        }
        return Some(i);
    }
    None
}

fn eq_bytes(a: &[u8], b: &[u8]) -> bool {
    if a.len() != b.len() { return false; }
    for (x, y) in a.iter().zip(b) {
        if x != y { return false; }
    }
    true
}

/// DTD/external-entity markers that never appear in a legitimate SVG
/// attachment upload. `SYSTEM` catches parameter-entity forms even when
/// the `<!ENTITY` spelling is obfuscated.
const DTD_MARKERS: [&[u8]; 3] = [b"<!DOCTYPE", b"<!ENTITY", b"SYSTEM"];

/// Scan a multipart body for SVG parts carrying DTD/external-entity
/// declarations. A boundary delimiter line is `--<boundary>`; this scanner
/// searches for the bare boundary token and verifies the preceding dashes
/// inline (the first delimiter starts at body offset 2), then checks each
/// part: only parts that look like SVG (filename `.svg` or the
/// `image/svg+xml` content type in their headers) are scanned for DTD
/// markers, raw or percent-encoded. No fixed arrays are copied or zeroed.
fn multipart_carries_dtd(body: &[u8], boundary: &[u8]) -> bool {
    let n = body.len();
    let mut cursor = 0usize;
    while cursor < n {
        // find the next boundary token
        let rel = match find_lower(&body[cursor..], boundary) {
            Some(r) => r,
            None => return false,
        };
        let b_at = cursor + rel;
        // delimiter line: "--boundary" (the dashes sit immediately before
        // the token; the first line of the body starts with them)
        if b_at < 2 || body[b_at - 2] != b'-' || body[b_at - 1] != b'-' {
            cursor = b_at + 1;
            continue;
        }
        let after = b_at + boundary.len();
        // epilogue ("--boundary--") terminates the parts
        if after + 2 <= n && body[after] == b'-' && body[after + 1] == b'-' {
            return false;
        }
        // part content begins after the boundary line's newline
        let part_start = match find_lower(&body[after..], b"\r\n") {
            Some(r) => after + r + 2,
            None => match find_lower(&body[after..], b"\n") {
                Some(r) => after + r + 1,
                None => return false,
            },
        };
        // part headers end at the blank line
        let hdr_rel = match find_lower(&body[part_start..], b"\r\n\r\n") {
            Some(r) => r + 4,
            None => match find_lower(&body[part_start..], b"\n\n") {
                Some(r) => r + 2,
                None => return false,
            },
        };
        let hdrs = &body[part_start..part_start + hdr_rel];
        let content_start = part_start + hdr_rel;
        // only guard SVG attachments (other types are not XML)
        let is_svg = contains_ci_decoded(hdrs, b".svg")
            || contains_ci_decoded(hdrs, b"image/svg+xml");
        if is_svg {
            // scan the part content (to the next boundary token)
            let next = match find_lower(&body[content_start..], boundary) {
                Some(r) => content_start + r,
                None => n,
            };
            for marker in DTD_MARKERS.iter() {
                if contains_ci_decoded(&body[content_start..next], marker) {
                    return true;
                }
            }
        }
        cursor = part_start;
    }
    false
}

fn extract_boundary(head: &[u8]) -> Option<&[u8]> {
    let at = find_lower(head, b"boundary=")?;
    let mut rest = &head[at + b"boundary=".len()..];
    if rest.first() == Some(&b'"') {
        rest = &rest[1..];
        let end = rest.iter().position(|&b| b == b'"')?;
        Some(&rest[..end])
    } else {
        let end = rest
            .iter()
            .position(|&b| b == b';' || b == b'\r' || b == b'\n' || b == b' ')
            .unwrap_or(rest.len());
        Some(&rest[..end])
    }
}

fn request_is_attack(head: &[u8], body: &[u8]) -> bool {
    // Route gate: the storefront review submission endpoint.
    let line_end = head.iter().position(|&b| b == b'\r').unwrap_or(head.len());
    let reqline = &head[..line_end];
    let sp = reqline.iter().position(|&b| b == b' ').unwrap_or(0);
    if !starts_with_ci(&reqline[sp + 1..], ROUTE) {
        return false;
    }
    // Content type must be multipart with a boundary
    let boundary = match extract_boundary(head) {
        Some(b) => b,
        None => return false,
    };
    multipart_carries_dtd(body, boundary)
}
```

**Stated limits.** The scan matches the DTD markers anywhere in the SVG part content, so an attachment whose content legitimately contains the literal strings (not a DTD) is refused too — a design decision, since a DTD marker in an SVG upload is never legitimate. The percent-encoded shape is refused as defense in depth even though the product itself rejects it (recorded honestly as a control). The module keys on the reviews route; other routes accepting SVG uploads are out of scope. The durable fix is plugin 3.0.2.
