# WP Maps Pro: unauthenticated privilege escalation via nopriv AJAX (CVE-2026-8732)

The WP Maps Pro plugin for WordPress is vulnerable to privilege escalation via administrator account creation in all versions up to 6.1.0: the wpgmp_temp_access_ajax AJAX action is registered with wp_ajax_nopriv_ and protected only by a nonce check, so unauthenticated callers create administrator accounts.

## The vulnerability

The plugin registers a privileged AJAX action in the nopriv namespace, so an unauthenticated caller invoking it with a valid nonce creates admin accounts. Eden fronts the WordPress origin, so the escalation request rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/wp-admin/admin-ajax.php",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_wpmaps_v1 waits for a complete request, matches the WordPress AJAX route, and refuses wpgmp_temp_access actions carrying no admin binding header — the nopriv escalation shape. Bound actions continue.

```rust
//! refuse nopriv AJAX privilege escalation without an admin binding.
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-8732/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded WP Maps Pro (WordPress plugin) version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-8732/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-8732) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe requested temporary access presenting the admin binding. The advisory-shaped probe invoked the same action requesting the admin role without any binding. The fixture incremented its marker when an unbound nopriv escalation reached the handler.

## Measured comparison (2026-11-14 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign bound temp access | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped nopriv escalation | 200, 1 | 403, 0 | 403, 0 |

The module enforces an admin-binding contract on the recorded action; it does not validate the nonce (the plugin's own check), so a leaked-but-valid nonce passes the module and is a bypass to record. The durable fix is the vendor's registration patch (moving the action out of nopriv).
