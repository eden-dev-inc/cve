# Ivanti Connect Secure: authentication bypass via certificate spoofing (CVE-2026-104935)

A remote attacker without any login credentials can bypass authentication on Ivanti Connect Secure releases prior to the fixed version by spoofing — and run arbitrary commands on the appliance. The flaw is exploited in the wild, and a VPN concentrator compromise is a direct network-perimeter breach.

## The vulnerability

The appliance's client-certificate authentication path accepts a spoofed identity assertion without binding it to an authenticated session, so an unauthenticated caller runs commands. Eden fronts the appliance's web interface, so the forged assertion rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/dana-ws",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_icscert_v1 waits for a complete request, matches the appliance web-services route, and refuses requests presenting a spoofed client-identity header without a bound session — the unauthenticated identity-assertion shape the bypass accepts.

```rust
const ROUTE: &[u8] = b"/dana-ws/";
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-104935/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Ivanti Connect Secure / Ivanti Cloud Services Appliance version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-104935/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-104935) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe accessed the web-services endpoint presenting a bound session. The advisory-shaped probe asserted an administrator identity with no session binding. The fixture incremented its marker when a spoofed identity reached the authenticated handler.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign bound web-services call | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped spoofed identity | 200, 1 | 403, 0 | 403, 0 |

The module enforces a session-binding contract against raw identity-assertion headers on the web-services route; the vendor's exact spoofing mechanics (certificate fields) are not fully public, so the fixture delivers the assertion shape honestly. Forged sessions pass the module and are a bypass to record.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
