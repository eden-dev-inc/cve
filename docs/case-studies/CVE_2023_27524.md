# Superset: forged sessions via the default SECRET_KEY (CVE-2023-27524)

An unauthenticated caller can forge administrator sessions against Apache Superset deployments running the default SECRET_KEY: Flask session cookies signed with a public constant grant the attacker the admin role, and with it database connections and query execution. Default-key installs are remotely critical.

**Result.** The forged admin session raised the backend counter in the baseline (200, +1). The declarative tier refused it (403, benign false positive recorded). The native module refused the forged session (403, counter unchanged) while the benign credential login stayed HTTP 200. Recorded through Eden 1.103.0 on 2026-11-13 (UTC).

## The vulnerability

Superset installs that keep the shipped default SECRET_KEY sign session cookies with a public constant, so anyone can mint an admin session and reach the full application. Eden fronts the Superset web tier, so the forged session rides an HTTP request Eden can refuse before release. The durable fix is rotating the key, which invalidates all forged cookies.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on /login and its descendants. This blocks every login, benign or not (the recorded false positive) — an emergency posture while the SECRET_KEY is rotated.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/login",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_superset_v1 waits for a complete request, matches POSTs to /login, and refuses session cookies carrying the recorded default-key forgery markers (base64 is_admin / admin fragments). Requests without those markers continue.

```rust
let cookie = header_value(hdrs, b"cookie").unwrap_or(b"");
static MARKS: [&[u8]; 3] = [b"aXNfYWRtaW4", b"is_admin", b"YWRtaW4"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2023-27524/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Apache Superset version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declarative policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2023-27524/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the marked fixture request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** Upgrade to a fixed release and configure a unique SECRET_KEY. Follow the application's key-rotation process for existing deployments. [Advisory reference](https://superset.apache.org/docs/security/cves/)

## Fixture and probes

The benign probe posted an ordinary credential login. The marked fixture probe presented a session cookie forged with the default-key admin marker. The fixture incremented its marker when a forged admin session was accepted.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign credential login | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped forged admin session | 200, 1 | 403, 0 | 403, 0 |

The module matches the recorded forgery markers in cookies; other default-key signature shapes and header-borne sessions were not exercised. The durable remediation is SECRET_KEY rotation — the module is a stopgap for deployments that cannot rotate immediately.

## Signed module authority

Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal.
