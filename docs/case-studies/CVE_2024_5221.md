# Qi Blocks XSS via uploader (CVE-2024-5221)

[Source and API bundle](../../cve/CVE-2024-5221/README.md)

*[cve.now](https://cve.now/CVE-2024-5221) entry. Product: Qi Blocks WordPress
plugin (lab: `gabriel-qiblocks-app`).*

Eden terminates the HTTP connection to the affected product, evaluates a
declarative policy and — in tier 2 — a separately compiled native Rust module
under signed module authority, before any byte reaches the application. It does
**not** patch the affected component; the vendor's fixed release remains the
durable repair.

**Status: Remediated (tier 1 + tier 2), live-proven 2026-11-11T16:47:56Z on the
installed `eden-product-release:1.103.0` lab container.**

## The vulnerability

The Qi Blocks uploader renders a caller-supplied content field unescaped,
persisting markup. The fixture (`make_qiblocks`) reproduces the shape: an
upload whose content carries a raw angle-bracket tag (`<x>`) records a
stored-XSS mark.

## The Eden patch

**Tier 1 — declarative policy (blunt, fail-closed):** deny every request under
`/wp-admin/admin-ajax.php`, ordinary block uploads included — false positives
measured below.

**Tier 2 — native Rust module `gabriel_qiblocks_v1` (surgical):** refuses
upload bodies carrying raw angle-bracket markers (`<x>`); ordinary block
content passes unchanged.
