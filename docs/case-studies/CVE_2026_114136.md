# Django REST framework: RCE via byte-transform codecs in the charset (CVE-2026-114136)

Django REST framework 3.6.4 through 3.18.2 passes the client-supplied Content-Type charset to codecs.getreader, which accepts byte-transform codecs. A crafted charset value can reach code execution on parsers that accept it — any DRF endpoint parsing JSON with a client-controlled charset is exposed.

## The vulnerability

The JSON parser uses the client-controlled charset to pick a reader codec, and byte-transform codecs decode attacker bytes into arbitrary streams, escaping to code execution. Eden fronts the DRF application, so the crafted header rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/api/items",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_drfcharset_v1 waits for a complete request and refuses Content-Type headers whose charset names a byte-transform codec (base64, zip, bz2, hex) — the recorded dangerous values getreader accepts.

```rust
static CODECS: [&[u8]; 4] = [b"base64", b"zip", b"bz2", b"hex"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-114136/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Django REST framework version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-114136/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-114136) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe posted JSON with charset=utf-8. The advisory-shaped probe posted the same JSON with charset=base64. The fixture incremented its marker when a transform codec reached the parser.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |

| Benign JSON with utf-8 | 200, 0 | 403, 0 | 200, 0 |

The rule refuses the four recorded byte-transform codecs; other dangerous codec names were not enumerated and are a bypass to record. The durable fix is the vendor's 3.18.2+ patch pinning safe charsets.
