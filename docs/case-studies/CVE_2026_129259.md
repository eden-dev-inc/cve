# VanBlog: stored XSS via the image upload endpoint (CVE-2026-129259)

VanBlog's Image Upload Endpoint lets a low-privilege authenticated caller store script content that later runs in other users' browsers — stored XSS with a victim-side action requirement.

## The vulnerability

The image upload accepts file content without sanitizing script markers, so a stored upload executes in victims' sessions. Eden fronts the VanBlog server, so the crafted upload rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/api/img/upload",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_vanblogimg2_v1 waits for a complete request, matches the image upload route, and refuses upload bodies carrying script-bearing markers (<script, <img, <iframe, onerror=) — the injection shapes that reach the stored page. Clean image uploads continue.

```rust
const ROUTE: &[u8] = b"/api/img/upload";
static MARKS: [&[u8]; 4] = [b"<script", b"<img", b"<iframe", b"onerror="];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-129259/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded VanBlog version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-129259/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-129259) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe uploaded a clean image name. The advisory-shaped probe uploaded script-tag content. The fixture incremented its marker when a script-bearing upload reached the store.

## Measured comparison (2026-11-14 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign clean upload | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped script upload | 200, 1 | 403, 0 | 403, 0 |

The rule matches the recorded script markers in upload bodies; encodings that avoid these exact tags (event handlers beyond onerror) were not exercised and are a bypass to record. The real-world path is a low-privilege login with a victim action. The durable fix is the vendor's content sanitization.

## Signed module authority

Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403).
