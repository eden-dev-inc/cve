# Wazuh: RCE via unsafe deserialization in the server API (CVE-2025-24016)

An attacker with access to Wazuh’s DistributedAPI can supply a crafted JSON object that evaluates Python code on a server. A compromised dashboard, cluster node, or in some configurations an agent can provide that access.

## Synthetic HTTP controls

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/api",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** The rule scans POST bodies on the /api prefix for selected strings.

```rust
const ROUTE: &[u8] = b"/api";
static GADGETS: [&[u8]; 6] = [b"rO0AB", b"getRuntime", b"exec(", b"__import__", b"os.system", b"subprocess"];
```

## Implement the remediation

**Vendor update.** Upgrade Wazuh server nodes to 4.9.1 or a later supported release. Verify the installed release on each node and confirm cluster health. [Vendor instructions](https://github.com/wazuh/wazuh/security/advisories/GHSA-hcrc-79hj-m3qh).

The published package uses the build name above. Verify its own archive digest before import. Use the [fixture API example](../../cve/CVE-2025-24016/http-request-filter/api.md) to reproduce the recorded comparison. It covers the declaration, signed module activation, verification, revocation, and restoration.

## Fixture and probes

The benign probe listed agents with a clean request. The marked probe posted a body carrying serialized-gadget markers. The fixture incremented its marker when a gadget-bearing body reached the deserialization path.

## Test scope

The rule scans POST bodies on the /api prefix for selected strings. The fixture did not run Wazuh, send a DistributedAPI request, deserialize a Wazuh object, or execute Python.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the marked probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
