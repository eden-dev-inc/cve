# Airflow: unauthenticated variable import (CVE-2021-38540)

The variable import endpoint in Airflow 2.0.0 through 2.1.2 was not protected by authentication: unauthenticated users could hit the endpoint to add or modify Airflow variables used in DAGs — variable tampering that redirects task behavior.

## The vulnerability

The variable import endpoint performs no authentication, so a network caller rewrites DAG-consumed variables. Eden fronts the webserver, so the unauthenticated import rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declaratory policy.** The recorded policy denies every method on the recorded route family and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/api/v1/variables",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_afunauth_v1 waits for a complete request, matches the Experimental API and variable-import routes, and refuses unauthenticated requests on them. Authenticated calls continue.

```rust
//! refuse unauthenticated access on the Experimental API and variable-import routes.
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2021-38540/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Apache Airflow 2.0–2.1 version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged.
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2021-38540) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe imported variables presenting credentials. The advisory-shaped probe imported the same variables unauthenticated. The fixture incremented its marker when an unauthenticated import reached the handler.

## Measured comparison (2026-11-14 UTC)

The module enforces an authentication-presence contract on the variable-import route (shared with the Experimental API rule, CVE-2020-13927). The durable fix is the vendor's 2.1.3 patch.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal.
