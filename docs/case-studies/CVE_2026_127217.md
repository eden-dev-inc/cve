# Post to Google My Business: blind SSRF through the fetch parameter (CVE-2026-127217)

The Post to Google My Business plugin for WordPress has a blind server-side request forgery flaw: a remote attacker with a low-privilege login (Contributor or higher) can make the web server send requests to arbitrary hosts — scanning internal ports and probing otherwise-isolated networks from inside the perimeter.

## The vulnerability

The plugin's fetch action takes a caller-supplied URL without confining its destination, so the server becomes an internal-network probe for any contributor. Eden fronts the WordPress origin, so the crafted fetch rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/wp-admin/admin-ajax.php",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_gmbssrf_v1 waits for a complete request, matches the plugin's AJAX action, extracts the url parameter value, and refuses it when it names a scheme-bearing address (raw or percent-encoded) that is not the expected Google API host. Requests to the legitimate API endpoint continue.

```rust
const ROUTE: &[u8] = b"/wp-admin/admin-ajax.php";
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-127217/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Post to Google My Business (WordPress plugin) version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-127217/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-127217) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe fetched the legitimate googleapis.com endpoint through the action. The advisory-shaped probe fetched an internal admin address (http://10.0.0.5:8080/admin) percent-encoded in the url parameter. The fixture incremented its marker when an out-of-scope destination reached the fetch handler.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign API fetch | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped internal SSRF | 200, 1 | 403, 0 | 403, 0 |

The rule refuses scheme-bearing url values (raw and percent-encoded) that do not name the expected API host; destinations reached without a URL scheme, or additional legitimate hosts, are a bypass to record and require rebuilding the host needle. The durable fix is the vendor's destination validation.
