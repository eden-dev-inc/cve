# ExifTool: DjVu arbitrary code execution on crafted files (CVE-2021-22204)

A crafted file — a DjVu document disguised inside a .jpg — executes arbitrary code when parsed by ExifTool 7.44 and later before the fixed release. Any service that runs ExifTool on uploaded files becomes remote code execution for whoever can upload; the advisory notes public exploitation.

**Result.** The crafted upload raised the backend counter in the baseline (200, +1). The declarative tier refused it (403, benign false positive recorded). The native module refused the DjVu payload (403, counter unchanged) while the benign JPEG stayed HTTP 200. Recorded through Eden 1.103.0 on 2026-11-13 (UTC).

## The vulnerability

ExifTool's DjVu parser evaluates Perl code embedded in crafted metadata, so a malicious DjVu file inside an accepted upload executes with the parsing service's privileges. Eden fronts the upload service, so the crafted file rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on /upload and its descendants. This blocks every upload, benign or not (the recorded false positive) — an emergency posture.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/upload",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_exiftool_v1 waits for a complete request, matches targets starting with /upload, and refuses bodies carrying DjVu/ExifTool execution markers (djvu, $url, image::exiftool). Ordinary JPEG bytes continue.

```rust
const ROUTE: &[u8] = b"/upload";
static MARKS: [&[u8]; 3] = [b"djvu", b"$url", b"image::exiftool"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2021-22204/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded ExifTool version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declarative policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2021-22204/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the marked fixture request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** Apply the fix for the installed release line and verify the application behavior after upgrading. [Advisory reference](https://github.com/exiftool/exiftool/commit/cf0f4e7dcd024ca99615bfd1102a841a25dde031)

## Fixture and probes

The benign probe uploaded ordinary JPEG bytes. The marked fixture probe uploaded a crafted body embedding the DjVu/ExifTool execution markers. The fixture incremented its marker when the crafted document reached its parser.

The rule matches the recorded marker strings; alternate encodings of the DjVu payload (for example whitespace or comment-obfuscated forms) were not exercised.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal.
