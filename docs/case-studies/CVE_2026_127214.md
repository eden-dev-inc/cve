# Flowise: SSRF through the Custom Function sandbox via module subpaths (CVE-2026-127214)

Flowise lets a remote attacker with chatflow or agentflow create-or-update permissions bypass the Custom Function sandbox's SSRF protection by requiring an allowlisted package's module subpath, then send arbitrary GET and POST requests from the server. A workflow server becomes an internal-network pivot.

## The vulnerability

The sandbox allowlist checks the package name but the runtime resolves subpaths, so requiring 'pkg/child' escapes into arbitrary code that can make server-side requests. Eden fronts the Flowise API, so the crafted function body rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/api/v1/nodes",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_flowise_v1 waits for a complete request, matches the node update route, and refuses custom-function bodies importing module subpaths (a '/' inside the required/imported package specifier) — the sandbox escape shape. Top-level package imports continue.

```rust
const ROUTE: &[u8] = b"/api/v1/nodes";
static FORMS: [&[u8]; 3] = [b"require('", b"import(", b"from '"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-127214/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Flowise version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-127214/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-127214) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe updated a node importing a top-level allowlisted package. The advisory-shaped probe imported a subpath of it. The fixture incremented its marker when a subpath import reached the function sandbox.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign top-level import | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped subpath import | 200, 1 | 403, 0 | 403, 0 |

The rule matches require/import forms with a '/' in the first quoted specifier; alternate import syntaxes (dynamic import with variables) were not exercised and are a bypass to record. The durable fix is the vendor's sandbox patch.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
