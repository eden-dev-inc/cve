# DDI Central Telnet IPv6 Scope Injection (CVE-2026-95643)

An authenticated remote caller can submit crafted connectivity or policy data to ManageEngine DDI Central (through 6.3.1 build 6301) that escapes the command context the product builds on the managed Windows host, reaching remote code execution. Update DDI Central to build 6500, which validates the inputs at the command-execution layer.

**Result.** The vendor-documented injection shape reached the fixture's simulated command construction in the baseline on every attack probe, and the native module refused each one with HTTP 403 before release — no crafted value reached the simulated command path while the module served — while every benign probe kept HTTP 200, including the clean-zone-ID and wildcard-domain controls. After revocation the interlay failed closed rather than silently re-exposing the route, and a replacement operation restored the refusal.

## The vulnerability

ManageEngine DDI Central (through 6.3.1 build 6301) builds a PowerShell command from the telnet connectivity feature's parameters (`/ipam/telnet/`) and executes it on the managed Windows node. IPv6 scope identifiers (zone IDs) passed the feature's IP validation without character validation, so a crafted value could escape the expected PowerShell string context and execute unintended PowerShell commands on the node (remote code execution). Fixed in build 6500, which validates zone IDs, allowlists command inputs, and converts ports to integers before command execution.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies `POST` on the `/ipam/telnet` route family and its descendants. This is a coarse rule: it also blocks the benign probes on the same route (recorded false positives).

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {"methods": ["POST"], "path": "/ipam/telnet", "descendants": true},
        "require": {"kind": "deny"}
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** The module refuses `/ipam/telnet/` requests whose parameters carry a PowerShell string-context breakout (`'` or backtick) or an IPv6 scope identifier whose zone-ID portion contains characters outside the safe zone charset `[A-Za-z0-9._-]`. Both the raw and percent-decoded parameter streams are scanned, so escaped (`%xx`) and raw forms are covered alike. `"` is deliberately not refused: it is structural in JSON bodies, and the telnet parameters (IP addresses, ports, hostnames) never legitimately carry quote material.

```rust
fn zone_safe(b: u8) -> bool {
    b.is_ascii_alphanumeric() || b == b'.' || b == b'_' || b == b'-'
}

/// PowerShell string-context breakout and command separators that never
/// belong inside an IP address or its zone ID.
fn ps_danger(b: u8) -> bool {
    // `&` is excluded: it is the raw query/form value separator and would
    // false-positive every benign multi-parameter request (an escaped `%26`
    // is real content and is still caught by the quote check after decode).
    matches!(b, b')' | b'(' | b';' | b'|' | b'<' | b'>' | b'$'
             | b' ' | b'\t' | b'\r' | b'\n')
}

/// Stream the percent-decoded bytes of `src`, feeding each decoded byte to
/// `on_byte`. Returns false when `on_byte` returns false (refuse).
fn stream_decoded<F: FnMut(u8) -> bool>(src: &[u8], mut on_byte: F) -> bool {
    let mut i = 0usize;
    let n = src.len();
    while i < n {
        let b = src[i];
        if b == b'%' && i + 2 < n && is_hex(src[i + 1]) && is_hex(src[i + 2]) {
            let d = (hex_val(src[i + 1]) << 4) | hex_val(src[i + 2]);
            i += 3;
            if !on_byte(d) { return false; }
        } else {
            i += 1;
            if !on_byte(b) { return false; }
        }
    }
    true
}

/// Refuse when a parameter stream carries the injection shape:
/// - a PowerShell single-quote breakout/backtick/quote anywhere, or
/// - a `%` scope marker whose zone-ID run is followed by a PowerShell-dangerous byte.
fn carries_injection(src: &[u8]) -> bool {
    let mut hit = false;
    let mut in_zone = false;
    let mut seen_colon_hex = false;
    stream_decoded(src, |b| {
        // The breakout set is `'` (single-quote, which terminates the
        // single-quoted PowerShell string the feature builds) and backtick.
        // `"` is deliberately NOT refused here: it is structural in every
        // JSON body; the telnet parameters (IP addresses, ports, hostnames)
        // never legitimately carry quote material. A value that must carry a
        // `"` rides JSON's own \" escape, whose content is still caught by
        // the zone-unsafe scan below when it is injection-shaped.
        if b == b'\'' || b == b'`' {
            hit = true;
            return false;
        }
        if b == b'%' {
            in_zone = true;
            return true;
        }
        if in_zone {
            if zone_safe(b) {
                return true; // still inside a clean zone-ID run
            }
            // zone terminated: an unsafe byte right after the run means the
            // scope identifier itself carries injection material
            if ps_danger(b) && !is_hex(b) && b != b':' {
                hit = true;
                return false;
            }
            in_zone = false;
        }
        if b == b':' { seen_colon_hex = true; }
        true
    });
    let _ = seen_colon_hex;
    hit
}
```

**Stated limits.** Finite lab route; the module keys on the vendor-published feature route (`/ipam/telnet/`) but not on individual parameter names (unpublished), so every parameter of the route is scanned; a deployment whose telnet parameters legitimately carry quote material must adjust the route scope. Fixed release: build 6500.

## Fixture and probes

The fixture (`gabriel-dditel-app`) mirrors the vendor-documented data flow — the telnet connectivity request builds the same single-quoted PowerShell `Test-NetConnection` command line the vendor describes, and the oracle reports whether the caller-supplied address escapes the quoted string context. Recorded effect deltas distinguish injection hits from benign requests.

| Probe | Shape | Baseline | Tier 1 | Tier 2 (module) |
| --- | --- | --- | --- | --- |
| benign_ipv4 | `POST /ipam/telnet/` JSON `{"host": "192.168.1.5", "port": 23}` | 200, clean command | 403 | 200, clean command |
| benign_ipv6_no_zone | JSON `{"host": "fe80::1", "port": 23}` | 200, clean command | 403 | 200, clean command |
| benign_ipv6_clean_zone | form `host=fe80%3A%3A1%25eth0&port=23` (clean zone ID `eth0`) | 200, clean command | 403 | 200, clean command |
| attack_zone_breakout | JSON `{"host": "fe80::1%eth0'); Start-Process calc; #", "port": 23}` | 200, **PowerShell string-context breakout → injected command** | 403 | 403, refused |
| attack_zone_breakout_form | form `host=fe80%3A%3A1%25eth0%27%29%3BStart-Process+calc&port=23` (escaped form) | 200, **breakout → injected command** | 403 | 403, refused |

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the marked probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal.
