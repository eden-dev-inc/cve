# Rails Active Storage: unsafe libvips image processing (CVE-2026-66066)

An attacker who can upload images to an affected Rails application using Active Storage with libvips can trigger unsafe image operations. A successful attack can read files and secrets available to the Rails process, which can lead to code execution.

## The vulnerability

The affected versions and upgrade guidance are listed above. The Eden policy and module were tested against the HTTP fixture described below.

## Synthetic HTTP controls

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/wp-admin/admin-ajax.php",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** The rule checks the synthetic AJAX route for an action marker and selected traversal or path strings.

```rust
const ROUTE: &[u8] = b"/wp-admin/admin-ajax.php";
static MARKS: [&[u8]; 4] = [b"../", b"..%2f", b"/etc/", b"file:"];
```

## Implement the remediation

Upgrade the activestorage gem to 7.2.3.2, 8.0.5.1, or 8.1.3.1 for your release branch. Use libvips 8.13 or later. Follow the Rails advisory's guidance for replacing secrets the affected application could access. [Advisory and remediation guidance](https://github.com/rails/rails/security/advisories/GHSA-xr9x-r78c-5hrm)

The recorded module and policy reproduce the synthetic comparison. [Fixture API example](../../cve/CVE-2026-66066/http-request-filter/api.md)

## Signed module authority

Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403).
