# Airflow: forged Celery callbacks run code on every worker (CVE-2026-68982)

Apache Airflow's CeleryExecutor runs callback workloads without checking their authentication token: anyone who can write to the Celery broker can queue a forged callback and run arbitrary code on every CeleryExecutor worker, without Airflow credentials. Only CeleryExecutor deployments are affected. The direct forgery vector is the broker wire (Redis/RabbitMQ protocol) — a recorded protocol gap; the module protects the HTTP callback-queueing surface of the Airflow API that feeds the same execution path.

## The vulnerability

The executor executes queued callback workloads without verifying their origin, so a forged callback on the broker — or an unauthenticated callback queued through the API surface — runs attacker code on every worker. Eden fronts the Airflow API server, so the unauthenticated callback-queueing request rides an HTTP request Eden can refuse before release; the broker wire itself is a protocol gap recorded in the annex.

## The Eden patch

**Tier 1 — declaratory policy.** The recorded policy denies every method on the recorded route family and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/api/v2/dags",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** airflow_celery_callback_guard waits for a complete request, matches task-instance and XCom routes, refuses unauthenticated writes, refuses deserialization gadget markers in body values, and refuses bulk PATCH/DELETE bodies whose dag_id differs from the path dag — the task-instance family's four shapes. Bound, clean, matching writes continue.

```rust
static GADGETS: [&[u8]; 6] = [b"__import__", b"os.system", b"import_string", b"subprocess", b"rO0AB", b"eval("];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-68982/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Apache Airflow (CeleryExecutor) version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged.
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-68982) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe queued a callback presenting API credentials. The advisory-shaped probe queued the callback unauthenticated with an execution gadget in the spec. The fixture incremented its marker when an unauthenticated callback reached the queueing handler.

## Measured comparison (2026-11-14 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign authed callback queue | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped unauth callback | 200, 1 | 403, 0 | 403, 0 |

The rule requires authentication on the task-instance write family and refuses gadget markers (see CVE-2026-41084). The primary unauthenticated vector — writing the forged callback directly to the Redis/RabbitMQ broker — is outside the HTTP boundary and recorded as a protocol gap; broker ACLs and broker-side auth are the durable mitigation there. The durable Airflow fix is the vendor's callback token check.
