# WordPress newspaper theme: unauthenticated options access via td_ajax_update_panel (CVE-2016-10972)

The WordPress newspaper theme lacks access control on its theme options, so an unauthenticated remote caller can reach them through the td_ajax_update_panel action. Option manipulation defaces the site and can pivot to stored payloads against its editors.

**Patch title.** WordPress Newspaper Theme Options Guard (`wordpress-newspaper-theme-options-guard` in the registry). ## The vulnerability

The theme's AJAX handler executes td_ajax_update_panel without a capability check, so anyone reachable can read and write theme options. Eden fronts the WordPress origin, so the action rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on /wp-admin/admin-ajax.php and its descendants. This blocks every AJAX action, benign or not (the recorded false positive) — an emergency posture.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/wp-admin/admin-ajax.php",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_wpnewspaper_v1 waits for a complete request, matches targets starting with /wp-admin/admin-ajax.php, and refuses bodies carrying the td_ajax_update_panel action marker. Other AJAX actions (the recorded benign heartbeat) continue.

```rust
const ROUTE: &[u8] = b"/wp-admin/admin-ajax.php";
if find_ignore_case(body, b"td_ajax_update_panel").is_some() { return Ok(Decision::Refuse); }
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2016-10972/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded WordPress newspaper theme version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declarative policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2016-10972/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** Apply the update for the affected release or device model. Follow the vendor's guidance for the installed build. [Advisory reference](https://www.cve.org/CVERecord?id=CVE-2016-10972)

## Fixture and probes

The benign probe posted an ordinary heartbeat action. The advisory-shaped probe posted the td_ajax_update_panel action with an option payload. The fixture incremented its marker when the unguarded action reached the options handler.
