# Kendo UI for jQuery: XSS in the Chart default tooltip (CVE-2026-124698)

[CVE advisory record](https://cve.now/CVE-2026-124698) · [Vendor advisory](https://www.telerik.com/kendo-jquery-ui/documentation/knowledge-base/kb-security-kendo-chart-tooltip-point-value-xss-cve-2026-124698) · [Module source](modules/gabriel_kendochart2_v1.rs)

**Result.** Both baseline requests returned HTTP 200 with zero marker change. The native rule refused the second probe and let the benign request through. These observations establish request refusal for the tested bytes. The synthetic fixture ran through Eden 1.103.0 on November 12, 2026 (UTC).

## The vulnerability

The default tooltip renders string point values as HTML. An attacker who can control a point value may cause script execution when the user hovers over that point. The default tooltip consumes point values, while the shared tooltip advisory covers category and series names.

Progress verified affected releases at least as far back as 2016.2.607 through 2026.3.1015. The fix is in 2026.4.1111. The CVE record reports a CVSS base score of **7.1**.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies requests to `/kendo-ui/chart2` and its descendants. The empty method list leaves the deny unrestricted by HTTP method. This is a coarse rule and blocked the benign probe on the same path.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/kendo-ui/chart2",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** `gabriel_kendochart2_v1` waits for the request to be complete, checks whether the request target starts with `/kendo-ui/chart2`, and looks for any configured marker in the body. The substring comparison is ASCII case-insensitive. Outside that prefix or without a marker, the module returns `Continue`. The shown lines are excerpts from the linked source.

```rust
const ROUTE: &[u8] = b"/kendo-ui/chart2";
static NEEDLES: [&[u8]; 2] = [b"<SCRIPT", b"OnErRoR="];
```

```rust
NEEDLES.iter().any(|n| find_ignore_case(body, n).is_some()) && return Ok(Decision::Refuse);
```

## Fixture and probes

The fixture was a synthetic HTTP handler behind Eden. It answered the probes and kept a separate counter that increased when the handler recognized its marker bytes. The counter measures a fixture effect. An HTTP 200 from the baseline does not by itself establish that the counter moved.

**Request.** `POST /kendo-ui/chart2/shared` for the benign probe and the marked probe.

The benign probe sent a plain tooltip value. The second body used an uppercase script fragment and a mixed-case JSON key named OnErRoR. That key is followed by JSON punctuation, so the recorded body did not contain the literal event-handler marker with an equals sign. The case-insensitive native rule refused the probe.

## Test scope

The backend oracle searches for lowercase markers using case-sensitive byte matching. It returned 200 and recorded no marker for the mixed-case baseline. This experiment shows the gateway refused the tested bytes and preserved the benign request. It supplies no baseline evidence of an effect and did not exercise the default tooltip in a browser.
