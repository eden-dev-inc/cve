# Kendo UI for jQuery: XSS in the Chart default tooltip (CVE-2026-124698)

A malicious point value can execute script when a user hovers over it in an affected Kendo Chart default tooltip. Upgrade the widget to protect people viewing charts that contain untrusted point values.

## The vulnerability

The default tooltip renders string point values as HTML. An attacker who can control a point value may cause script execution when the user hovers over that point. The default tooltip consumes point values, while the shared tooltip advisory covers category and series names.

Progress verified affected releases at least as far back as 2016.2.607 through 2026.3.1015. The fix is in 2026.4.1111. The CVE record reports a CVSS base score of **7.1**.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies requests to `/kendo-ui/chart2` and its descendants. The empty method list leaves the deny unrestricted by HTTP method. This is a coarse rule and blocked the benign probe on the same path.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/kendo-ui/chart2",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** `gabriel_kendochart2_v1` waits for the request to be complete, checks whether the request target starts with `/kendo-ui/chart2`, and looks for any configured marker in the body. The substring comparison is ASCII case-insensitive. Outside that prefix or without a marker, the module returns `Continue`. The shown lines are excerpts from the linked source.

```rust
const ROUTE: &[u8] = b"/kendo-ui/chart2";
static NEEDLES: [&[u8]; 2] = [b"<SCRIPT", b"OnErRoR="];
```

```rust
NEEDLES.iter().any(|n| find_ignore_case(body, n).is_some()) && return Ok(Decision::Refuse);
```

## Implement the remediation

Use this procedure in an isolated fixture to reproduce the scoped restriction. Follow the vendor update for the underlying exposure. See [deployment prerequisites](../deployment.md).

1. **Prepare the target.** Verify the loaded product and version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source when applicable.
2. **Apply the declarative policy.** Scope the policy to `/kendo-ui/chart2` and descendants (all methods, `deny`). Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Run an authenticated `GET /api/v1/interlays/{interlay}` with `X-Eden-Verbose: true`. Save its complete current settings object as `current-settings.json` and retain the prior remediation declaration for recovery. Set `IDEMPOTENCY_KEY` to a fresh key for this intended mutation.

Save the JSON in the patch section as `remediation.json`.

```sh
jq -e --slurpfile policy remediation.json \
  '.remediation = $policy[0] | {settings: .}' current-settings.json \
  > interlay-update.json
eden api request PATCH "/api/v1/interlays/$INTERLAY" \
  --header "Idempotency-Key:$IDEMPOTENCY_KEY" \
  --body-file interlay-update.json --content-type application/json --confirm
```

3. **Verify the serving policy.** Read back the interlay.

```sh
eden api request GET "/api/v1/interlays/$INTERLAY" \
  --header 'X-Eden-Verbose:true'
```

Check that `remediation_status.state` is `ready` and both desired and effective SHA-256 values match the intended declaration. Replay both recorded probes in an isolated fixture. The baseline recorded no marker, so the check establishes request refusal for the tested bytes.
4. **Restore the previous policy.** Coordinate the change with any other operator updating this interlay. Read current settings again and merge the saved remediation field into them. If the prior settings had no remediation field, omit it in the replacement. Send the same PATCH with a fresh idempotency key, then read back the intended state. Repeat the verification probes. Keep the affected route isolated if restoring the prior settings reopens exposure.

**Vendor update.** Use the [advisory](https://www.telerik.com/kendo-jquery-ui/documentation/knowledge-base/kb-security-kendo-chart-tooltip-point-value-xss-cve-2026-124698) to select the fixed release for the installed branch. Reported fixed releases include `2026.4.1111`. Follow the vendor’s update instructions and confirm the version actually loaded by the service.

## Fixture and probes

The fixture was a synthetic HTTP handler behind Eden. It answered the probes and kept a separate counter that increased when the handler recognized its marker bytes. The counter measures a fixture effect. An HTTP 200 from the baseline does not by itself establish that the counter moved.

**Request.** `POST /kendo-ui/chart2/shared` for the benign probe and the marked probe.

The benign probe sent a plain tooltip value. The second body used an uppercase script fragment and a mixed-case JSON key named OnErRoR. That key is followed by JSON punctuation, so the recorded body did not contain the literal event-handler marker with an equals sign. The case-insensitive native rule refused the probe.

## Test scope

The backend oracle searches for lowercase markers using case-sensitive byte matching. It returned 200 and recorded no marker for the mixed-case baseline. This experiment shows the gateway refused the tested bytes and preserved the benign request. It supplies no baseline evidence of an effect and did not exercise the default tooltip in a browser.
