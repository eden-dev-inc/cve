# LearnPress: unauthenticated wishlist change via IDOR (CVE-2026-127213)

The LearnPress Course Wishlist add-on for WordPress lets anyone on the network — without logging in — change any user's course wishlist by supplying a different user ID, and probe who wishlisted what. User activity is mutable by strangers.

## The vulnerability

The add-on's AJAX handler accepts a caller-supplied user ID without authenticating the caller, so anyone rewrites other users' wishlists. Eden fronts the WordPress origin, so the IDOR request rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/wp-admin/admin-ajax.php",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_learnpress_v1 waits for a complete request, matches the WordPress AJAX route, and refuses wishlist actions that carry no session binding header — the unauthenticated IDOR shape. Bound wishlist requests continue.

```rust
const ROUTE: &[u8] = b"/wp-admin/admin-ajax.php";
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-127213/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded LearnPress Course Wishlist (ThimPress) version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-127213/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-127213) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe performed a wishlist change presenting the session binding. The advisory-shaped probe changed another user's wishlist without the binding. The fixture incremented its marker when an unbound wishlist write reached the handler.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign bound wishlist change | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped unbound IDOR write | 200, 1 | 403, 0 | 403, 0 |

The module enforces a session-header contract on wishlist actions; it does not validate the bound user against the target ID, so a valid session for a different user would pass and is a bypass to record. The durable fix is the vendor's patch.

## Signed module authority

Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
