# Burst Statistics: authentication bypass to admin accounts (CVE-2026-8181)

An attacker who knows an administrator username can use an invalid WordPress Application Password to impersonate that administrator for the request on affected Burst Statistics versions.

[Public CVE record](https://www.cve.org/CVERecord?id=CVE-2026-8181) · [Vendor advisory or update instructions](https://burst-statistics.com/docs/changelog/#3421-may-14-2026) · [Module source](modules/CVE-2026-8181.rs) · [Source and API bundle](../../cve/CVE-2026-8181/README.md) · [CNA advisory](https://www.wordfence.com/threat-intel/vulnerabilities/id/8ca830d6-3d3c-4026-85cd-8447b8a568d3?source=cve)

**Result.** The marked request reached the synthetic backend in the baseline. Both protected configurations returned HTTP 403 for that request and the backend counter did not change. The native module passed the benign probe.

## Synthetic HTTP controls

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/wp-json/burst",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** The rule checks for the presence of X-Burst-Auth on POST, PUT and DELETE under /wp-json/burst.

```rust
const ROUTE: &[u8] = b"/wp-json/burst";
```

## Implement the remediation

**Vendor update.** Update Burst Statistics through WordPress to a maintained release at least as recent as 3.4.2.1. The vendor documents direct credential validation in 3.4.2.1. On staging, confirm invalid application passwords are refused and authorized MainWP calls still work if you use the integration. [Vendor instructions](https://burst-statistics.com/docs/changelog/#3421-may-14-2026).

The published package uses the build name above. Verify its own archive digest before import. Use the [fixture API example](../../cve/CVE-2026-8181/http-request-filter/api.md) to reproduce the recorded comparison. It covers the declaration, signed module activation, verification, revocation, and restoration.

## Fixture and probes

The benign probe tracked analytics presenting the auth binding. The marked probe deleted a goal without any binding. The fixture incremented its marker when an unbound privileged operation reached the plugin.

## Test scope

The rule checks for the presence of X-Burst-Auth on POST, PUT and DELETE under /wp-json/burst. It did not validate a WordPress Application Password or reproduce the vendor’s Basic Authentication bypass.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the marked probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
