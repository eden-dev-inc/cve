# FortiSandbox: path traversal privilege escalation in the JRPC API (CVE-2026-39813)

FortiSandbox 4.4.0-4.4.8 and 5.0.0-5.0.5 expose a path traversal in the JRPC API that bypasses authentication and escalates privileges, reachable remotely without logging in.

**Patch title.** FortiSandbox JRPC Path Guard (`fortisandbox-jrpc-path-guard` in the registry). The [original source snapshot](https://github.com/eden-dev-inc/cve/blob/9a7217a0a882374c5ab97d74c96df9b77637f923/docs/case-studies/modules/CVE-2026-39813.rs) preserves the source available for the historical report.

**Result.** The advisory-shaped request raised the backend counter in the baseline (200, +1). The declarative tier refused it (403, counter unchanged, benign false positive recorded). The native module refused the advisory-shaped request (403, counter unchanged) while the benign probe stayed HTTP 200, verified against an independent backend counter through Eden 1.103.0.

## The vulnerability

The JRPC API resolves a caller-supplied path across an authorization boundary, so a traversal sequence escapes the confinement and reaches privileged handlers unauthenticated. Eden fronts the appliance API, so the crafted request rides an HTTP request Eden can refuse.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the JRPC route and its descendants. This blocks every API call, benign or not (the recorded false positive) — an emergency posture on a sandbox appliance.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/jrpc",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_fortisandbox_v1 waits for a complete request, matches targets starting with the JRPC route, and refuses any target or body carrying traversal markers (../, ..%2f, %2e%2e). Clean JSON-RPC calls continue.

```rust
const ROUTE: &[u8] = b"/jrpc";
static MARKS: [&[u8]; 3] = [b"../", b"..%2f", b"%2e%2e"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-39813/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Fortinet FortiSandbox version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declarative policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-39813/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** Apply the update for the affected release or device model. Follow the vendor's guidance for the installed build. [Advisory reference](https://fortiguard.fortinet.com/psirt/FG-IR-26-112)

## Fixture and probes

The benign probe posted a clean JSON-RPC info call. The advisory-shaped probe posted a method carrying ../filedir traversal in its path argument. The fixture incremented its marker when a traversal-bearing path reached its handler.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign JSON-RPC info call | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped traversal call | 200, 1 | 403, 0 | 403, 0 |

The rule matches raw and percent-encoded traversal markers on the JRPC route; alternate encodings were not exercised. The real appliance speaks its API on a management interface — front it as its own interlay.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
