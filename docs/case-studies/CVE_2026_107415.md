# NetScaler ADC and Gateway: memory overflow DoS in Email OTP authentication (CVE-2026-107415)

A memory overflow in the Email OTP authentication feature of Citrix NetScaler ADC and NetScaler Gateway lets a remote unauthenticated caller crash the service. Every crafted request can take the gateway down, so an exposed deployment is trivially deniable.

## The vulnerability

The Email OTP feature mishandles crafted authentication values, overflowing memory and crashing the appliance. Eden fronts the gateway's HTTP listener, so the crafted OTP request rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/nf/otp",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_nsotp_v1 waits for a complete request, matches the OTP route, and refuses POSTs whose form body carries a parameter value longer than 64 bytes — the oversized authentication-value overflow shape.

```rust
const ROUTE: &[u8] = b"/nf/otp";
// refuse POST parameter values longer than 64 bytes
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-107415/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Citrix NetScaler ADC / Gateway version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-107415/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-107415) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe posted an ordinary email address to the OTP endpoint. The advisory-shaped probe posted a 180-byte value. The fixture incremented its marker when an oversized value reached the OTP handler.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign OTP request | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped oversized OTP value | 200, 1 | 403, 0 | 403, 0 |

The rule refuses oversized form values on the recorded OTP route; query-borne shapes and other authentication routes were not exercised. The 64-byte threshold is a lab recording, not a vendor boundary.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
