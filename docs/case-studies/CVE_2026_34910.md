# UniFi OS: command injection via improper input validation (CVE-2026-34910)

An attacker with network access to an affected UniFi OS device can inject commands. Successful exploitation can compromise the device and disrupt the network it manages.

## Synthetic HTTP controls

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

  "profile": "http-structure-v1",

**Tier 2 — native Rust module.** On the /proxy/network/api prefix, the shared rule scans the target and body for selected shell and traversal strings.

## Implement the remediation

**Vendor update.** Identify the device model and use Ubiquiti Bulletin 064 to select the matching fixed firmware. Confirm that the installed release is on the supported track for that device. [Vendor instructions](https://community.ui.com/releases/Security-Advisory-Bulletin-064-064/84811c09-4cf4-42ab-bd61-cc994445963b).

The published package uses the build name above. Verify its own archive digest before import. Use the [fixture API example](../../cve/CVE-2026-34910/http-request-filter/api.md) to reproduce the recorded comparison. It covers the declaration, signed module activation, verification, revocation, and restoration.

## Fixture and probes

The benign probe issued a traffic command with clean input. The marked probe appended a metacharacter command. The fixture incremented its marker when injected input reached the command path.

## Test scope

On the /proxy/network/api prefix, the shared rule scans the target and body for selected shell and traversal strings. The fixture did not call a UniFi command handler or execute commands.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the marked probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
