# WordPress File Upload plugin: unauthenticated SQL injection (CVE-2026-62071)

An unauthenticated attacker can inject SQL into affected versions of the WordPress File Upload plugin. The flaw can expose database contents accessible to WordPress and affect service availability, so sites running the affected plugin should update it.

## The vulnerability

The affected versions and upgrade guidance are listed above. The Eden policy and module were tested against the HTTP fixture described below.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/wp-admin/admin-ajax.php",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** On the fixture AJAX route, the module requires an action=nbfu_ marker in the body and refuses selected SQL markers in the request target or body.

```rust
const ROUTE: &[u8] = b"/wp-admin/admin-ajax.php";
static NEEDLES: [&[u8]; 4] = [b"' or", b"union select", b"1=1", b"'--"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-62071/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Nickboss WordPress File Upload plugin version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-62071/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the marked fixture request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** Follow the update instructions for the installed product and release line. [Vendor or publisher advisory](https://patchstack.com/database/wordpress/plugin/wp-file-upload/vulnerability/wordpress-wordpress-file-upload-plugin-5-1-10-sql-injection-vulnerability?_s_id=cve)

## Fixture and probes

The benign probe listed uploaded files by a clean folder name. The marked fixture probe appended a SQL predicate to the same parameter. The fixture incremented its marker when injected SQL reached its query engine.

## Test scope

The synthetic route looked for an action=nbfu_ marker in the request body and a selected SQL marker in the body or target. The test measured a fixture counter. It did not exercise the plugin's database queries, other delivery routes, or alternative encodings.
