# Simple File List: rename-to-PHP remote code execution (CVE-2020-36847)

An unauthenticated caller can turn an uploaded file into executable PHP through the plugin's rename function: a disguised upload (a PHP payload with a .png extension) is renamed to .php and then requested, running with the web server's privileges. Public exploits include a Metasploit module, so an exposed installation should be treated as compromisable.

## The vulnerability

The plugin's rename function accepts a caller-supplied new filename without confining its extension, so a .png upload becomes .php and the web server executes it. Eden fronts the WordPress origin, so the rename request rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the plugin's rename endpoint and its descendants. This is a coarse rule: it also blocked the benign rename, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/wp-content/plugins/simple-file-list/rename.php",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_sflist_v1 refuses a .php target in rename bodies on the plugin route. Its import was blocked by the recorded product bug: the patch-package PUT returned 400 E1A30 (native module lifetime profile not qualified), so the module tier never activated in this comparison.

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2020-36847/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Simple File List (WordPress plugin) version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declarative policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Verify the recorded outcome.** Import returned HTTP 400 with E1A30. Use the declarative comparison to evaluate the route-wide deny and review its benign impact. Native activation and rollback require separate qualification.

**Vendor update.** Apply the fix for the installed release line and verify the application behavior after upgrading. [Advisory reference](https://www.wordfence.com/threat-intel/vulnerabilities/id/9eb835fd-6ebf-4162-856c-0366b663a07e?source=cve)

## Fixture and probes

The benign probe renamed a report PNG to another PNG name. The marked fixture probe renamed a disguised upload to shell.php. The fixture incremented its marker when a PHP target reached the rename handler.

## Signed module authority

Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal.
