# WordPress: path traversal in page-template resolution (CVE-2026-87902)

[Advisory record](https://cve.now/CVE-2026-87902) · [Vendor advisory](https://github.com/WordPress/wordpress-develop/security/advisories/GHSA-7hp8-65ch-5whp)

**Status.** Two-tier request-filter comparison against Eden 1.103.0 using a synthetic HTTP fixture.

[Module source](modules/gabriel_wppagetpl_v1.rs)

## The vulnerability

WordPress before 7.1.2 can resolve a readable PHP file outside the active theme through page-template selection under certain server and theme conditions.

## The Eden patch

**Tier 1 — declarative policy.** Deny all requests under the fixture prefix `/wp-content/themes`, including benign requests.

**Tier 2 — native Rust module.** Match `/wp-content/themes` and refuse requests containing a configured marker in the request target.

## Measured comparison (2026-11-12 UTC)

| Configuration | Benign request | Attack fixture |
| --- | --- | --- |
| Baseline | HTTP 200 | HTTP 200, no marker change observed |
| Tier 1 route deny | HTTP 403 | HTTP 403 |
| Tier 2 native module | HTTP 200 | HTTP 403, backend marker absent |

## Signed module authority

The module was imported for explicit activation. All expected shards acknowledged activation. Reader inspection, a tampered statement and an invalid signature were rejected. After revocation the same request received HTTP 503. Re-approval and reactivation restored HTTP 403.

## Test scope

The fixture tests the HTTP request target on a theme-directory route. The baseline returned 200 with zero observed marker change. The module's 403 establishes refusal of the test request. WordPress page-template resolution and PHP file inclusion remain unverified.

The measurements cover the supplied fixture probes. Alternate routes, encodings, and other bypasses remain untested.
