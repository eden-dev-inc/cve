# Drupal core: SQL injection on PostgreSQL sites (CVE-2026-9082)

[CVE advisory record](https://cve.now/CVE-2026-9082) · [Vendor advisory](https://www.drupal.org/sa-core-2026-004) · [Module source](modules/gabriel_drupalsqli_v1.rs)

**Result.** The marked request reached the backend in the baseline and raised its counter. The native rule refused that request with HTTP 403 and preserved HTTP 200 for the benign probe. The synthetic fixture ran through Eden 1.103.0 on November 12, 2026 (UTC).

## The vulnerability

Drupal’s database abstraction layer is supposed to keep request data separate from SQL. On the affected PostgreSQL path, a crafted request can reach query construction and change the resulting SQL. Anonymous access matters because the advisory does not require an authenticated Drupal account.

Drupal lists fixed releases 10.4.10, 10.5.10, 10.6.9, 11.1.10, 11.2.12, and 11.3.10. Its advisory documents separate guidance for Drupal 8 and 9. The CVE record reports a CVSS base score of **9.8**.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies requests to `/api/entity_form/system` and its descendants. The empty method list leaves the deny unrestricted by HTTP method. This is a coarse rule and blocked the benign probe on the same path.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/api/entity_form/system",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** `gabriel_drupalsqli_v1` waits for the request to be complete, checks whether the request target starts with `/api/entity_form/system`, and looks for any configured marker in the body. The substring comparison is ASCII case-insensitive. Outside that prefix or without a marker, the module returns `Continue`. The shown lines are excerpts from the linked source.

```rust
const ROUTE: &[u8] = b"/api/entity_form/system";
static NEEDLES: [&[u8]; 3] = [b"' OR ", b"union select", b"1=1"];
```

```rust
NEEDLES.iter().any(|n| find_ignore_case(body, n).is_some()) && return Ok(Decision::Refuse);
```

## Fixture and probes

The fixture was a synthetic HTTP handler behind Eden. It answered the probes and kept a separate counter that increased when the handler recognized its marker bytes. The counter measures a fixture effect. An HTTP 200 from the baseline does not by itself establish that the counter moved.

**Request.** `POST /api/entity_form/system` for the benign probe and the marked probe.

The benign fixture requested a search operation in a form field. The second body used a SQL predicate marker in that field. The handler incremented a marker on byte match and did not execute a database query.

## Signed module authority

The module import returned HTTP 201 and required explicit activation. Signature verification was deferred at import. Read-only inspection returned HTTP 403, admission with a tampered statement returned HTTP 400, and admission with an invalid signature returned HTTP 403. The activation receipt reported the module serving on all expected shards.

After revocation, the same marked request received HTTP 503. Re-approval and reactivation restored HTTP 403. The source digest below identifies the linked Rust file. The binary digest identifies the artifact recorded in the activation evidence.

## Test scope

The fixture used a synthetic form route. The experiment did not exercise Drupal’s database abstraction layer or a PostgreSQL backend. This rule can also refuse innocent input containing SQL-like text and does not cover all request shapes that might reach the database path.
