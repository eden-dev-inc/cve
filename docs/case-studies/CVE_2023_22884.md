# Airflow: command injection in the MySQL Provider example DAG (CVE-2023-22884)

The Apache Airflow MySQL Provider's example DAG exposes improper neutralization of special elements used in a command, letting a UI-reachable attacker inject OS commands through the provider's connection parameters.

## The vulnerability

The provider example DAG builds SQL/shell commands from trigger-supplied connection parameters unquoted, so a UI user injects commands. Eden fronts the webserver, so the injected connection parameter rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declaratory policy.** The recorded policy denies every method on the recorded route family and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/api/v1/dags",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** airflow_mysql_provider_trigger_guard waits for a complete request, matches POSTs on the dagRuns trigger route, and refuses bodies carrying shell metacharacter or SQL markers (;, $(, backtick, ' OR, union select) — the injection family the example-DAG and parameter flaws expose. Clean trigger bodies continue.

```rust
static MARKS: [&[u8]; 5] = [b";", b"$(", b"`", b"' or", b"union select"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2023-22884/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Apache Airflow MySQL Provider version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged.
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2023-22884) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe triggered with a clean connection name. The advisory-shaped probe supplied a connection value carrying a SQL/marker payload. The fixture incremented its marker when injected input reached the command construction.

Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403).
