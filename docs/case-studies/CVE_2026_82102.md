# DataStage: server-side request forgery via connector fields (CVE-2026-82102)

IBM DataStage on Cloud Pak for Data contains a server-side request forgery flaw that lets a remote attacker with a low-privilege login obtain sensitive information — the data-integration platform makes requests to attacker-chosen addresses, and its connectors hold the credentials of every system it integrates.

## The vulnerability

The connector configuration resolves caller-supplied destinations without confinement, so a low-privilege user points the platform at internal metadata and credential services. Eden fronts the DataStage API, so the forged destination rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/v3/connectors",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_dssrrf_v1 waits for a complete request, matches connector routes, and refuses requests whose connector fields mention a url or host and carry a scheme-bearing address (://, percent-encoded forms) — the forged-destination shape. Plain internal connector hostnames continue.

```rust
const ROUTE: &[u8] = b"/v3/connectors";
static SCHEMES: [&[u8]; 3] = [b"://", b"%3a%2f%2f", b"%3a//"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-82102/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded IBM DataStage on Cloud Pak for Data version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-82102/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-82102) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe configured a connector with a plain internal hostname. The advisory-shaped probe set the connector's url field to a link-local metadata address. The fixture incremented its marker when a scheme-bearing destination reached the connector handler.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign internal connector host | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped forged metadata fetch | 200, 1 | 403, 0 | 403, 0 |

The rule refuses scheme-bearing destinations in connector url/host fields; scheme-free hostnames resolving attacker-side are a bypass to record (the same family as CVE-2026-106042 Xtraction). The durable fix is the vendor's destination validation.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
