# Sonatype Nexus Repository: task component code execution (CVE-2026-3199)

An authenticated Nexus Repository user with task creation permissions can bypass a script creation restriction and execute arbitrary code. A compromised repository can put stored artifacts and credentials at risk.

[Public CVE record](https://cve.now/CVE-2026-3199) · [Vendor or publisher advisory](https://support.sonatype.com/hc/en-us/articles/50615414548499) · [Module source](modules/CVE-2026-3199.rs) · [Source and API bundle](../../cve/CVE-2026-3199/README.md)

## The vulnerability

The affected versions and upgrade guidance are listed above. The test submitted script-related markers to a synthetic task handler.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/service/rest",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_nexus_v1 waits for a complete request, matches the task API route, and refuses bodies carrying script-creation markers (groovy, script.create, allowCreation).

```rust
const ROUTE: &[u8] = b"/service/rest";
static MARKS: [&[u8]; 3] = [b"groovy", b"script.create", b"allowcreation"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-3199/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Sonatype Nexus Repository version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-3199/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the marked fixture request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** Follow the update instructions for the installed product and release line. [Vendor or publisher advisory](https://support.sonatype.com/hc/en-us/articles/50615414548499)

## Fixture and probes

The benign probe scheduled an ordinary cleanup task. The marked fixture probe submitted a task carrying script-creation markers. The fixture incremented its marker when script content reached its scheduler.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the marked fixture probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
