# Xtraction: connector credential capture via request redirect (CVE-2026-106042)

Ivanti Xtraction lets a remote attacker with valid login credentials redirect the application's outbound requests to a server they control, capturing the EPMM connector credentials the application sends. Stolen connector credentials grant access to the mobile-management backend the connector serves.

## The vulnerability

The connector configuration accepts a caller-controlled destination without confining it to the expected management endpoints, so an authenticated attacker points it at a capture server. Eden fronts the Xtraction web tier, so the crafted connector request rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/api/connectors",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_xtraction_v1 waits for a complete request, matches the connector API route, and refuses connector requests whose url or host parameters carry a scheme-bearing address (raw or percent-encoded) — the redirect-to-attacker shape. Plain internal hostnames continue.

```rust
const ROUTE: &[u8] = b"/api/connectors";
static SCHEMES: [&[u8]; 3] = [b"://", b"%3a%2f%2f", b"%3a//"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-106042/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Ivanti Xtraction version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-106042/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-106042) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe configured a connector with a plain internal hostname. The advisory-shaped probe set the host parameter to an attacker URL. The fixture incremented its marker when a scheme-bearing destination reached the connector handler.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign internal connector host | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped attacker redirect | 200, 1 | 403, 0 | 403, 0 |

The rule refuses scheme-bearing values in url/host parameters on the connector route; hostnames without a scheme that still resolve attacker-side (DNS) are a bypass to record. The real-world path is an authenticated low-privilege user. The durable fix is the vendor's destination validation.

## Signed module authority

Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403).
