# FortiMail: IBE webmail session takeover via incorrect authorization (CVE-2026-126155)

An unauthenticated remote caller can take over an authenticated IBE webmail session and read or send that recipient's encrypted mail, through crafted HTTP requests. The flaw lets the attacker act as any IBE recipient without ever logging in.

## The vulnerability

Fortinet attributes the session takeover to incorrect authorization in FortiMail IBE. The Eden fixture modeled a cross-recipient request with no session header and measured whether it reached the synthetic handler.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/fortimail_ibe/inbox",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_fmsession_v1 waits for a complete request, matches the IBE inbox route, and refuses inbox requests naming another recipient (rcpt=) that carry no IBE session header — the cross-recipient takeover shape.

```rust
const ROUTE: &[u8] = b"/fortimail_ibe/inbox";
// refuse cross-recipient requests without a session
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-126155/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Fortinet FortiMail version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-126155/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** Apply the vendor update for the installed release or model. [Advisory reference](https://fortiguard.fortinet.com/psirt/FG-IR-26-207)

## Fixture and probes

The benign probe fetched the inbox presenting a session header. The marked fixture probe fetched the inbox naming a victim recipient with no session. The fixture incremented its marker when a cross-recipient request reached the mail handler.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign sessioned inbox fetch | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped cross-recipient takeover | 200, 1 | 403, 0 | 403, 0 |

The module requires a session header on cross-recipient inbox requests but does not validate the session value; a forged session header would pass the module and is a bypass to record. The takeover marker (rcpt=) is a fixture-delivered shape.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
