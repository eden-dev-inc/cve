# aiohttp: denial of service in form posts (CVE-2026-128126)

Crafted form posts let an unauthenticated remote attacker drive the aiohttp server's form handling into resource exhaustion, denying service to legitimate users.

## The vulnerability

The form handler allocates proportional to the crafted body, exhausting worker resources. Eden fronts the aiohttp service, so the oversized form rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/submit",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_aioform_v1 waits for a complete request and refuses urlencoded form bodies larger than 4096 bytes — the oversized-form shape that exhausts handling. Ordinary small forms continue.

```rust
//! refuse oversized urlencoded form bodies.
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-128126/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded aiohttp (form posts) version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-128126/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-128126) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe posted a small form. The advisory-shaped probe posted a 6 KiB form. The fixture incremented its marker when an oversized form reached the handler.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign small form | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped oversized form | 200, 1 | 403, 0 | 403, 0 |

The rule refuses oversized urlencoded bodies; other form encodings are covered by the sibling multipart rule, and chunked slow sends were not exercised. The threshold is a lab recording.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).

The baseline arm measures the unprotected interlay's forward path, which exhibits a separate ~41 ms response-write stall on this release (a recorded product finding), so it is not a like-for-like module-overhead comparison; the deny and module arms are the comparable pair.
