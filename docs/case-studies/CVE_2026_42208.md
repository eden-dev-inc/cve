# LiteLLM: SQL injection in proxy API key verification (CVE-2026-42208)

LiteLLM — the AI gateway proxy for calling LLM APIs — has a SQL injection flaw in its API key check: an attacker reads arbitrary database contents, including every stored LLM provider credential the proxy holds. A gateway compromise leaks all upstream keys.

## The vulnerability

The key verification interpolates caller-supplied key identifiers into SQL, so a crafted key reads the credential database. Eden fronts the LiteLLM proxy, so the injected key rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/key",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_litesqli_v1 waits for a complete request, matches key routes, and refuses targets or bodies carrying SQL injection markers (' OR, union select, 1=1). Clean key requests continue.

```rust
static NEEDLES: [&[u8]; 3] = [b"' or", b"union select", b"1=1"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-42208/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded LiteLLM version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-42208/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-42208) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe queried a well-formed key. The advisory-shaped probe supplied a key carrying a SQL predicate. The fixture incremented its marker when injected SQL reached the key check.

## Measured comparison (2026-11-14 UTC)

The rule matches the recorded error-based SQL markers on key routes; blind or time-based forms without these bytes were not exercised. The durable fix is the vendor's parameterization patch.

## Signed module authority
