# Realtek SDK miniigd: SOAP command execution via NewInternalClient (CVE-2014-8361)

The miniigd SOAP service in the Realtek SDK — shipped in many networked devices — executes a crafted NewInternalClient value with the device's privileges, unauthenticated. The advisory records in-the-wild exploitation through 2023.

**Patch title.** Realtek Miniigd NewInternalClient Guard (`realtek-miniigd-newinternalclient-guard` in the registry). ## The vulnerability

miniigd's SOAP handler passes the NewInternalClient value into command execution without authentication, so a crafted SOAP body runs code on the device. Eden fronts the device's UPnP port, so the crafted body rides an HTTP request Eden can refuse.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the UPnP control route and its descendants. This blocks every SOAP control call, benign or not (the recorded false positive).

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/upnp/control/WANIPConnection",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_realtek_v1 waits for a complete request, matches targets starting with the UPnP control route, and refuses SOAP bodies carrying shell metacharacter markers (;, $(, backtick) — the shapes the advisory names for the crafted NewInternalClient value. Ordinary SOAP control calls continue.

```rust
const ROUTE: &[u8] = b"/upnp/control/WANIPConnection";
static MARKS: [&[u8]; 3] = [b";", b"$(", b"`"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2014-8361/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Realtek SDK miniigd version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declarative policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2014-8361/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** Apply the update for the affected release or device model. Follow the vendor's guidance for the installed build. [Advisory reference](https://www.cve.org/CVERecord?id=CVE-2014-8361)

## Fixture and probes

The benign probe sent a standard SetConnectionTypeInfo SOAP call. The advisory-shaped probe sent an AddPortMapping body whose NewInternalClient value carries a command-injection marker. The fixture incremented its marker when the crafted value reached its command path.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign SOAP control call | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped NewInternalClient | 200, 1 | 403, 0 | 403, 0 |

The rule matches the metacharacter shapes the advisory names for the crafted NewInternalClient value on the recorded UPnP control route; other SOAP actions and encodings were not exercised. The real service speaks UPnP on a separate port — front it as its own interlay.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).

## Test scope

The corrected fixture matched the UPnP path regardless of case and recorded a backend effect for the marked NewInternalClient request before enforcement. The rule inspects the tested SOAP request on the configured listener. Vendor firmware, alternate SOAP actions, and other encodings were outside the fixture.
