# CuppaCMS: local file inclusion via the url parameter (CVE-2022-25486)

CuppaCMS 1.0 contains a local file inclusion flaw in the url parameter of /alerts/alertConfigField.php. The advisory rates the flaw critical, and include-based exploitation reaches arbitrary local files — configuration and credential material included.

## The vulnerability

The handler includes a caller-supplied file path without confining it to the intended template directory, so traversal and wrapper sequences read arbitrary files. Eden fronts the CuppaCMS application, so the crafted url rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/alerts/alertConfigField.php",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_cuppacms_v1 waits for a complete request, matches the alert configuration route, and refuses url parameter values carrying file-inclusion markers (../, percent-encoded forms, php:// wrappers, /etc/ targets). The intended field-template values continue.

```rust
const ROUTE: &[u8] = b"/alerts/alertConfigField.php";
static MARKS: [&[u8]; 5] = [b"../", b"..%2f", b"%2e%2e", b"php://", b"/etc/"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2022-25486/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded CuppaCMS version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2022-25486/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2022-25486) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe loaded the intended alert configuration template by its clean relative name. The advisory-shaped probe traversed to /etc/passwd through the url parameter. The fixture incremented its marker when an inclusion-bearing path reached the handler.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign template load | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped traversal include | 200, 1 | 403, 0 | 403, 0 |

The rule matches the recorded traversal, wrapper, and /etc/ markers on the alert configuration route; file reads without these markers (absolute paths to readable files) were not exercised and are a bypass to record. The durable fix is the vendor's path confinement.

## Signed module authority
