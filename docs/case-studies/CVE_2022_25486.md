# CuppaCMS: local file inclusion via the url parameter (CVE-2022-25486)

The affected CuppaCMS alert configuration handler can include a local file selected by an attacker. This can expose files readable by the web process.

**Patch title.** CuppaCMS URL Parameter Guard (`cuppacms-url-parameter-guard` in the registry). The [original source snapshot](https://github.com/eden-dev-inc/cve/blob/9a7217a0a882374c5ab97d74c96df9b77637f923/docs/case-studies/modules/CVE-2022-25486.rs) preserves the source available for the historical report.

## The vulnerability

The affected versions and upgrade guidance are listed above. The Eden policy and module were tested against the HTTP fixture described below.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/alerts/alertConfigField.php",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** The module looks for a url parameter marker on the fixture alert configuration route, then checks the target and body for selected traversal, wrapper, and path markers.

```rust
const ROUTE: &[u8] = b"/alerts/alertConfigField.php";
static MARKS: [&[u8]; 5] = [b"../", b"..%2f", b"%2e%2e", b"php://", b"/etc/"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2022-25486/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded CuppaCMS version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2022-25486/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the marked fixture request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** Consult the linked project and CVE record for affected versions and fix status. This report does not establish a fixed release. [Project reference](https://github.com/CuppaCMS/CuppaCMS/issues/25)

## Fixture and probes

The benign probe loaded the intended alert configuration template by its clean relative name. The marked fixture probe traversed to /etc/passwd through the url parameter. The fixture incremented its marker when an inclusion-bearing path reached the handler.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the marked fixture probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).

## Test scope
