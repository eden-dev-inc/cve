## The vulnerability

Fortinet reports that unauthenticated path traversal in affected FortiMail releases can lead to code or command execution on the appliance. The fixture used traversal markers on a representative export route and counted delivery to a synthetic handler. The appliance's vulnerable handler and code execution were outside the test.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/fortimail/api",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_fmtrav_v1 waits for a complete request, matches targets starting with the FortiMail API route, and refuses any target or body carrying raw or percent-encoded traversal markers (../, ..%2f, %2e%2e). Clean API calls continue.

```rust
const ROUTE: &[u8] = b"/fortimail/api";
static MARKS: [&[u8]; 3] = [b"../", b"..%2f", b"%2e%2e"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-126147/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Fortinet FortiMail version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-126147/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** Follow the update instructions for the installed product and release line. [Vendor advisory](https://fortiguard.fortinet.com/psirt/FG-IR-26-199)

## Fixture and probes

The benign probe fetched a settings resource by its clean path. The marked fixture probe exported through a path carrying ../../ segments. The fixture incremented its marker when a traversal-bearing path reached its file handler.

## Measured comparison (2026-11-13 UTC)

The rule matches raw and percent-encoded traversal markers on the recorded API route; alternate encodings were not exercised. The exact vulnerable route is appliance-internal; the fixture delivers the traversal shape on a representative API path.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
