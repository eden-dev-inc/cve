# Essential Real Estate: PHP object injection in saved-search storage (CVE-2026-5765)

The Essential Real Estate plugin for WordPress stores the caller-supplied saved-search query and later unserializes it in a scheduled task without validation, so an authenticated attacker with Subscriber-level access can store a serialized PHP object and reach a POP chain installed by another plugin or theme. The durable repair is the fixed plugin release.

## The vulnerability

The plugin's save-search ajax action (action=ere_save_search_ajax on /wp-admin/admin-ajax.php) inserts the caller's ere_query value into a database row; the daily cron reads every row and calls unserialize(base64_decode($result->query)) with no allowed-classes restriction. The modal form submits base64_encode(serialize($search_query)) — an array — but nothing stops a subscriber from submitting base64 of a serialized object instead. Eden fronts the WordPress site, so the saved-search request rides an HTTP request Eden can refuse before the value is ever stored.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded route family and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/wp-admin/admin-ajax.php",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** essential_real_estate_saved_search_object_injection_guard waits for a complete request, matches POSTs on the WordPress ajax route, extracts the ere_query form value (body or query string), percent-decodes and base64-decodes it, and refuses the request only when the decoded payload carries a serialized PHP object marker (O:<digits>:" or C:<digits>:") — the injection family the saved-search flaw exposes. The benign form value is always a serialized array (a:...), which never contains an object marker, so legitimate saved searches continue.

```rust
fn has_object_marker(bytes: &[u8]) -> bool { // O:<digits>:" or C:<digits>:" }
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-5765/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Essential Real Estate (WordPress plugin) version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission.
2. **Apply the declarative policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged.
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-5765) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probes submitted saved searches whose ere_query values were base64-encoded serialized arrays (a location/price filter array, and a single-key sort array). The advisory-shaped probes submitted base64-encoded serialized objects instead: a direct object payload, a nested object inside an array, and a custom-serializable (C:) payload. The fixture mirrored the plugin's primitive: it marked the trigger when the stored ere_query would unserialize an object rather than an array.

Finite lab route. The module gates the ere_query value only (the field the advisory names); other unvalidated parameters are out of scope. The discriminator is the serialized-object marker in the decoded value, so a benign array whose string content literally embeds the marker text would be refused (an accepted edge case for a search form).
