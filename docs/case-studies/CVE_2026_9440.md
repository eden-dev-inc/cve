# Edimax BR-6478AC: OS command injection in formAccept (CVE-2026-9440)

Edimax BR-6478AC 1.23 passes the formAccept POST handler's parameter unescaped to the operating system, letting a remote attacker inject OS commands through /goform/formAccept. The router's web form becomes a root shell.

## The vulnerability

The goform handler passes caller-supplied form values into OS commands unquoted, so a crafted value executes with the router's privileges. Eden fronts the router's web interface, so the injected form rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/goform/formAccept",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_edimax_v1 waits for a complete request, matches the /goform/form handler family, and refuses targets or bodies carrying shell metacharacter markers. Clean form posts continue.

```rust
const ROUTE: &[u8] = b"/goform/form";
static MARKS: [&[u8]; 3] = [b";", b"$(", b"`"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-9440/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Edimax BR-6478AC version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-9440/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-9440) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe submitted a clean formAccept field. The advisory-shaped probe appended a metacharacter command. The fixture incremented its marker when injected characters reached the command path.
