# Artifactory: authentication bypass to administrative access (CVE-2026-82329)

Under the default configuration of affected Artifactory releases, an unauthenticated network caller may gain administrative privileges. This can expose or allow changes to repositories and their configuration.

**Patch title.** Artifactory Administrative Access Guard (`artifactory-administrative-access-guard` in the registry). The [original source snapshot](https://github.com/eden-dev-inc/cve/blob/9a7217a0a882374c5ab97d74c96df9b77637f923/docs/case-studies/modules/CVE-2026-82329.rs) preserves the source available for the historical report.

## The vulnerability

The affected versions and upgrade guidance are listed above. The Eden policy and module were tested against the HTTP fixture described below.

## Synthetic HTTP controls

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/artifactory/api",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** The rule refuses matching fixture requests when both the X-JFrog-Art-Api and Authorization headers are absent.

```rust
const ROUTE: &[u8] = b"/artifactory/api";
```

## Implement the remediation

For self-hosted Artifactory, select the patched version for your branch from JFrog's advisory and follow its upgrade instructions. [Advisory and remediation guidance](https://docs.jfrog.com/releases/docs/jfrog-security-advisories)

The recorded module and policy reproduce the synthetic comparison. [Fixture API example](../../cve/CVE-2026-82329/http-request-filter/api.md)

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the marked fixture probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).

## Test scope

The fixture rule checks for the presence of either of two credential headers on a representative API route. It does not validate the header value. The test did not run Artifactory or exercise its authentication bypass.
