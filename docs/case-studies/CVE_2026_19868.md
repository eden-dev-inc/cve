# SonicOS SSLVPN SAML enforcement bypass via alternate authentication (CVE-2026-19868)

[Source and API bundle](../../cve/CVE-2026-19868/README.md)

*[cve.now](https://cve.now/CVE-2026-19868) entry. Product: SonicWall SonicOS
SSLVPN service (lab: `gabriel-sonicwall-app`). On the CISA KEV catalog;
no vendor fix listed at press time.*

Eden terminates the HTTP connection to the affected product, evaluates a
declarative policy and — in tier 2 — a separately compiled native Rust module
under signed module authority, before any byte reaches the application. It does
**not** patch the affected component; the vendor's fixed release remains the
durable repair.

**Status: Remediated at the boundary (tier 1 + tier 2), live-proven
2026-11-11T17:09:34Z on the installed `eden-product-release:1.103.0` lab container.**

## The vulnerability

The SonicOS SSLVPN service lets a user holding valid credentials for an
alternate (local) authentication method bypass SAML controls, including
SAML-enforced MFA. The fixture (`make_sonicwall`, port 18325) reproduces the
delivery shape: a login body selecting `authType: local` records a
SAML-bypass mark while SAML enforcement is active.

## The Eden patch

**Tier 1 — declarative policy (blunt, fail-closed):** deny every request under
`/sslvpn`, SAML logins included — false positives measured below.

**Tier 2 — native Rust module `gabriel_sonicwall_v1` (surgical):** refuses
login bodies that select the local auth type while SAML is the enforced
method; SAML logins (`authType: saml`) pass unchanged.

## Authority lifecycle and negatives

Import 201, `activation: explicit_required`; publisher `enroll_key`, host
`inventory` + `approve`, reader `inspect` refused 403; tampered-statement admit
400; invalid-signature admit 403; `admit` prepared (not serving), `activate`
→ receipt `serving_now`, applied shards **2/2**. Revoke → the identical attack
gets **503** (fail-closed); re-approve + re-activate → 403 again. All recorded
in the evidence JSON.

## Honest scope

The fixture reproduces the alternate-auth selection shape, not the full
SSLVPN handshake. Other alternate methods (LDAP, RADIUS) are not covered by
this rule's needle, and no-fix-listed means the boundary rule is the only
available control until SonicWall ships a patch. First live attempt hit the
trailing-slash policy rejection (E04FF) and a native-conditions exact-path
mismatch; both fixed, case re-run clean. Module binary SHA-256 `2cdac2ad…`,
source `modules/gabriel_sonicwall_v1.rs`.
