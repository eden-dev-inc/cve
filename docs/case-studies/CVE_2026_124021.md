# CWP: authorization bypass in the remote API (CVE-2026-124021)

Control Web Panel versions before the fixed release contain an authorization bypass in the remote API, reachable over the network without logging in by an attacker holding a password/passkey. The API is the panel's management surface: a bypass is administrative control of the host.

The declaratory tier refused it (403, counter unchanged; benign false positive recorded where the tier-1 deny covers the benign route). ## The vulnerability

The remote API accepts privileged operations without validating the caller's key against the action, so a partial credential reaches admin functions. Eden fronts the panel API, so the crafted request rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/api",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_cwpapi_v1 waits for a complete request, matches the API route, and refuses unauthenticated write operations (POST/PUT) that carry no panel key binding — the unbound bypass-call shape. Keyed operations continue.

```rust
const ROUTE: &[u8] = b"/api";
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-124021/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Control Web Panel remote API version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-124021/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-124021) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe created an account presenting the panel key. The advisory-shaped probe performed the same write without any key. The fixture incremented its marker when an unbound write reached the API handler.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign keyed account create | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped unkeyed write | 200, 1 | 403, 0 | 403, 0 |

The module enforces a key-binding contract on API writes; the vendor's exact bypass mechanics are not published, so the fixture delivers the binding shape honestly. Forged keys pass the module and are a bypass to record. The durable fix is the vendor's patched release.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
