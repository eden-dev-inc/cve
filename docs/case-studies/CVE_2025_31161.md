# CrushFTP: unauthenticated admin takeover via session injection (CVE-2025-31161)

An unauthenticated caller can bypass CrushFTP's login and take over the crushadmin account, giving full control of the file-transfer server. The flaw is on CISA's exploited catalog and has been exploited in the wild; a DMZ proxy in front prevents it, but a directly exposed server should be treated as compromised.

## The vulnerability

CrushFTP's AWS4-HMAC authorization handling can leave an authenticated session available after processing a malformed authorization header. The fixture exercises an HTTP login request carrying a session marker. Eden can inspect requests on the listener where it is deployed.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on both web login surfaces — `/login.jsp` and `/WebInterface` — and their descendants. This blocks every web login, benign or not (the recorded false positive), and leaves the file protocols on their own ports.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/login.jsp",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      },
      {
        "scope": {
          "methods": [],
          "path": "/WebInterface",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** `gabriel_crushftp_v1` waits for a complete request, matches the two login surfaces, and refuses any request whose target, body, or cookie carries a `currentAuth=` or `CrushAuth=` session-injection marker. Requests without the marker continue, which passed the benign form login.

```rust
static ROUTES: [&[u8]; 2] = [b"/login.jsp", b"/WebInterface"];
static MARKS: [&[u8]; 2] = [b"currentauth=", b"crushauth="];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2025-31161/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded CrushFTP version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declarative policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2025-31161/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds; re-approve, re-admit, and reactivate a replacement operation to restore protection. Keep the route isolated during the change window.

**Vendor update.** Apply the fix for the installed release line. The [advisory](https://outpost24.com/blog/crushftp-auth-bypass-vulnerability/) documents affected versions and update guidance.

## Fixture and probes

The benign probe posted a correct username and password to `/login.jsp`. The advisory-shaped probe requested `/login.jsp` with `username=crushadmin&currentAuth=`, a session-marker fixture. The fixture incremented its marker when an admin session was granted without credentials.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's admin-takeover counter. The declarative tier blocked the benign login too (the recorded false positive); the module refused only the session-injection shape.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign credential login | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped session injection | 200, 1 | 403, 0 | 403, 0 |

The module matches the two recorded marker names case-insensitively across target, body, and cookies. Alternative session parameter names, the FTP/SFTP/WebClient ports, and API-only installations were not exercised. The cookie scan is over the raw header bytes.

Product finding recorded during the run: a native module configuration listing two `conditions` entries (or an entry whose path carries unusual segments) failed authority inspection with `503 E1A03 Remediation policy unavailable`, so the module could not be scoped to two distinct exact paths; a single descendants-scoped route condition inspected and served cleanly.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal.

## Test scope
