# iCagenda: unauthenticated PHP upload to RCE (CVE-2026-48939)

The iCagenda event calendar extension for Joomla lets an attacker upload arbitrary files — including PHP code — through its file attachment feature, running that code on the web server. The flaw is exploited in the wild; an unauthenticated upload becomes server RCE.

## The vulnerability

The attachment feature accepts file names without confining their extensions, so PHP uploads execute with the web server's privileges. Eden fronts the Joomla origin, so the executable upload rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/icagenda",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_icagendaphp_v1 waits for a complete request, matches iCagenda attachment routes, and refuses POSTs whose bodies name PHP executable uploads (.php, phar:) — the executable-extension shapes that reach the web root. Ordinary attachment uploads continue.

```rust
static MARKS: [&[u8]; 2] = [b".php", b"phar:"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-48939/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded iCagenda (Joomla extension) version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-48939/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-48939) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe uploaded an agenda PDF attachment. The advisory-shaped probe uploaded shell.php. The fixture incremented its marker when a PHP-named upload reached the attachment handler.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| --- | --- | --- | --- |
| Benign PDF attachment | 200, 0 | 403, 0 | 200, 0 |

The rule matches the recorded executable markers in attachment uploads on iCagenda routes; alternate executable extensions (.php5, .pht) were not enumerated and are a bypass to record. The durable fix is the vendor's extension confinement.

## Signed module authority

Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
