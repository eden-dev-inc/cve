# Cisco ISE: authentication bypass through a privileged API endpoint (CVE-2026-76460)

Cisco Identity Services Engine and the ISE Passive Identity Connector have a flaw in an API endpoint that lets an attacker bypass authentication remotely, without logging in, and gain unauthorized access to the device through its web-based management interface. ISE is the network's identity anchor — a compromise cascades to every policy decision it makes.

## The vulnerability

The privileged API endpoint accepts writes without binding them to an authenticated session, so an unauthenticated caller changes device configuration. Eden fronts the ISE management interface, so the crafted request rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/ers/config",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_ciscoise_v1 waits for a complete request, matches the config API route, and refuses unauthenticated write operations (POST/PUT) that carry no session header — the unbound privileged-call shape the bypass accepts.

```rust
const ROUTE: &[u8] = b"/ers/config";
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-76460/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Cisco Identity Services Engine version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-76460/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-76460) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe created a network device presenting the session binding. The advisory-shaped probe performed the same write without a session. The fixture incremented its marker when an unbound write reached its config handler.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign bound device creation | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped unbound write | 200, 1 | 403, 0 | 403, 0 |

The module enforces a session-header contract on config-API writes but does not validate the header's value; a forged session would pass the module and is a bypass to record. The recorded route is a fixture-delivered shape for the ERS config API.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
