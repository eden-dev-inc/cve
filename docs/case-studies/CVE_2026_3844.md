# Breeze Cache: unauthenticated arbitrary file upload (CVE-2026-3844)

Unauthenticated attackers can make affected Breeze Cache installations write arbitrary files through the remote Gravatar fetch. If PHP files can execute from the cache directory, the attacker can run code. Local Gravatar hosting must be enabled for this path.

**Patch title.** Breeze Cache Upload Request Guard (`breeze-cache-upload-request-guard` in the registry). The [original source snapshot](https://github.com/eden-dev-inc/cve/blob/9a7217a0a882374c5ab97d74c96df9b77637f923/docs/case-studies/modules/CVE-2026-3844.rs) preserves the source available for the historical report.

## Synthetic HTTP controls

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/wp-json/breeze",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** The rule scans bodies under the /wp-json/breeze prefix for .php or phar:.

```rust
const ROUTE: &[u8] = b"/wp-json/breeze";
static MARKS: [&[u8]; 2] = [b".php", b"phar:"];
```

## Implement the remediation

**Vendor update.** In WordPress, update Breeze Cache to 2.4.5 or later and confirm the installed version. If the upgrade must wait, disable local Gravatar hosting in Breeze’s advanced settings. [Vendor instructions](https://www.cloudways.com/blog/breeze-cache-plugin-security-advisory/).

The published package uses registry name `breeze-cache-upload-request-guard`. Verify its own archive digest before import. Use the [fixture API example](../../cve/CVE-2026-3844/http-request-filter/api.md) to reproduce the recorded comparison. It covers the declaration, signed module activation, verification, revocation, and restoration.

## Fixture and probes

The benign probe saved a clean text file. The marked probe uploaded a PHP payload. The fixture incremented its marker when an executable-named upload reached the write path.

## Test scope

The rule scans bodies under the /wp-json/breeze prefix for .php or phar:. The fixture did not run the plugin’s Gravatar fetch, write files, or execute PHP.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the marked probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
