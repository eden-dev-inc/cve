# Breeze Cache: unauthenticated arbitrary file upload (CVE-2026-3844)

The Breeze Cache plugin for WordPress is vulnerable to arbitrary file uploads through missing file type validation in the fetch_gravatar_from_remote function (all versions up to 2.4.4) — unauthenticated attackers upload arbitrary files, leading to remote code execution when the file is executable.

## The vulnerability

The plugin's remote-fetch helper writes caller-supplied file names without type validation, so a public upload places executable files. Eden fronts the WordPress origin, so the arbitrary upload rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/wp-json/breeze",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_breeze_v1 waits for a complete request, matches Breeze Cache routes, and refuses upload bodies naming PHP executables (.php, phar:) — the arbitrary-upload shapes. Clean cache operations continue.

```rust
const ROUTE: &[u8] = b"/wp-json/breeze";
static MARKS: [&[u8]; 2] = [b".php", b"phar:"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-3844/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Breeze Cache (WordPress plugin) version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-3844/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-3844) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe saved a clean text file. The advisory-shaped probe uploaded a PHP payload. The fixture incremented its marker when an executable-named upload reached the write path.
