# OFBiz: authentication bypass via password-change logic flaw (CVE-2026-45434)

Apache OFBiz has an authentication bypass in its password-change logic: an attacker submits a crafted request to the forgot-password flow that resets credentials without proving identity — full takeover of the ERP application with a single request.

## The vulnerability

The password-change flow fails to bind the reset to an authenticated session, so an unauthenticated caller completes credential takeover. Eden fronts the OFBiz web tier, so the crafted reset rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/control/forgotpassword",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_ofbizpwd_v1 waits for a complete request, matches the forgot-password route by path, and refuses unauthenticated POSTs carrying a username parameter — the unbound reset shape the bypass needs. Authenticated password changes continue.

```rust
//! refuse posts to the password-change route without a bound identity.
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-45434/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Apache OFBiz version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-45434/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-45434) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe initiated a password change with credentials. The advisory-shaped probe submitted the same reset unauthenticated. The fixture incremented its marker when an unbound reset reached the change logic.

## Measured comparison (2026-11-14 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign authed password change | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped unauth takeover | 200, 1 | 403, 0 | 403, 0 |

The module enforces an authentication-presence contract on the forgot-password path; it does not validate the credential, so a forged-but-present Authorization passes and is a bypass to record. The durable fix is the vendor's patch.

## Signed module authority

Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403).
