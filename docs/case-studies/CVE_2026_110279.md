# ContextForge: X-Upstream-Authorization header replaces managed credentials (CVE-2026-110279)

IBM ContextForge MCP Gateway accepts a request header named X-Upstream-Authorization that replaces the gateway's managed upstream credential. A remote attacker (per the advisory, with the right access) who can set that header makes every tool call authenticate as their chosen bearer — turning the gateway's managed-credential security into an attacker-controlled credential channel.

## The vulnerability

The gateway forwards a caller-supplied header in place of its managed upstream credential, so a client that sets it controls the bearer every tool call uses. Eden fronts the gateway, so the header-bearing request rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/tools/call",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_cfxupstream_v1 waits for a complete request and refuses any request presenting an X-Upstream-Authorization header — the credential-replacement name — on every route. Only the gateway's internal injection may set that header; a client-supplied copy is refused. Ordinary requests continue.

```rust
//! refuse client-supplied X-Upstream-Authorization headers.
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-110279/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded IBM ContextForge MCP Gateway version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-110279/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-110279) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe called a tool with ordinary arguments. The advisory-shaped probe called the same tool carrying X-Upstream-Authorization with an attacker bearer. The fixture incremented its marker when a client-supplied credential replacement reached the gateway.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign ordinary tool call | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped credential replacement | 200, 1 | 403, 0 | 403, 0 |

The rule refuses the header on every route — the same inverse-header family recorded for CVE-2026-86863 (pgAdmin identity) and CVE-2025-6899 (NetScaler console identity): a header that only the trusted fronting layer should ever set. No bypass shape exists for a client-supplied managed-credential header: any client copy is by definition an attack. The durable fix is the vendor's header-removal patch.
