# WSO2: authentication bypass via JWT algorithm confusion (CVE-2026-5430)

Several WSO2 products — API Manager, API Control Plane, Traffic Manager and Universal Gateway — accept login tokens signed with an unsupported algorithm, letting an attacker bypass authentication and take over accounts, including administrator accounts.

## The vulnerability

The token validation accepts JWTs signed with algorithms it should reject, so a forged token authenticates as any user, including administrators. Eden fronts the WSO2 gateway, so the forged token rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/api",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_wso2_v1 waits for a complete request, matches API routes, and refuses Bearer tokens whose header carries the none-algorithm marker (raw alg:none fragment or its base64 form) — the forged-token shape the validation flaw accepts.

```rust
static MARKS: [&[u8]; 3] = [b"alg\":\"none", b"alg none", b"eyJhbGciOiJub25lIn0"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-5430/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded WSO2 (API Manager and related) version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-5430/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-5430) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe called the API with a properly signed RS256 bearer token. The advisory-shaped probe carried a none-algorithm token header. The fixture incremented its marker when a forged token reached its validator.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign signed API call | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped none-alg token | 200, 1 | 403, 0 | 403, 0 |

The rule matches none-algorithm markers (raw and base64-encoded JWT header) on API routes; other unsupported-algorithm shapes (e.g. algorithm confusion between HS/RS) were not exercised and are a bypass to record.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
