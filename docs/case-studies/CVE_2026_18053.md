# MemberDash: subscriber account takeover via IDOR (CVE-2026-18053)

The MemberDash WordPress plugin lets a logged-in basic subscriber remotely take over any WordPress user — changing their email and password, including the administrator's, and logging in with full admin control. The member-management AJAX surface trusts the caller's target user.

## The vulnerability

The plugin's member-management AJAX authorizes actions by object ID without checking the caller's authority over the target user, so a subscriber rewrites administrator credentials. Eden fronts the WordPress origin, so the IDOR request rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/wp-admin/admin-ajax.php",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_memberdash_v1 waits for a complete request, matches the WordPress AJAX route, and refuses user_id-targeted memberdash actions that carry no bound-user header — the cross-account IDOR shape. Bound writes continue.

```rust
const ROUTE: &[u8] = b"/wp-admin/admin-ajax.php";
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-18053/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded MemberDash (WordPress plugin) version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-18053/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-18053) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe updated its own membership presenting the bound-user header. The advisory-shaped probe targeted another user without the binding. The fixture incremented its marker when a cross-account IDOR reached the handler.

## Measured comparison (2026-11-14 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign bound self-update | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped cross-account IDOR | 200, 1 | 403, 0 | 403, 0 |

The module enforces a bound-user contract on memberdash AJAX actions targeting user IDs; it does not validate the bound identity against the target, so a bound-but-different user would pass and is a bypass to record. The durable fix is the vendor's authorization patch.
