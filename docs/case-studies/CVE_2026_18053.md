# MemberDash: subscriber account takeover via IDOR (CVE-2026-18053)

A subscriber to an affected MemberDash site can supply another WordPress user's ID during profile editing. A successful attack can change that user's email or password and take over the account, including an administrator's account.

## The vulnerability

The affected versions and upgrade guidance are listed above. The Eden policy and module were tested against the HTTP fixture described below.

## Synthetic HTTP controls

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/wp-admin/admin-ajax.php",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** The rule requires a fixture user header when the matching AJAX body includes action and user_id markers.

```rust
const ROUTE: &[u8] = b"/wp-admin/admin-ajax.php";
```

## Implement the remediation

**Vendor update.** Update MemberDash through its WordPress update channel to a supported release outside the affected range. The publisher lists 1.8.10 and the CVE record does not identify the first fixed release. In staging, verify that a subscriber can update their own profile and cannot update another user's profile. [MemberDash changelog](https://docs.nexcess.com/software/changelogs/learndash/memberdash/)

To reproduce the synthetic comparison, use the [fixture API example](../../cve/CVE-2026-18053/http-request-filter/api.md) and the synthetic controls above.

## Fixture and probes

The ordinary request included the fixture user header. The marked request supplied a different user ID without that header and the fixture counted its delivery.

## Signed module authority

Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). After revocation the marked fixture probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).

## Test scope

The fixture checks an AJAX action, a user_id marker and whether an example x-md-user header is present. It does not verify identity or account ownership. The test did not run the vendor's profile editing handler or change a WordPress account.
