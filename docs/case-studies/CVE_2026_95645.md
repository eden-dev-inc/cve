# DDI Agent Blocked Domain Command Injection (CVE-2026-95645)

An authenticated remote caller can submit crafted connectivity or policy data to ManageEngine DDI Central (through 6.3.1 build 6301) that escapes the command context the product builds on the managed Windows host, reaching remote code execution. Update DDI Central to build 6500, which validates the inputs at the command-execution layer.

**Result.** The vendor-documented injection shape reached the fixture's simulated command construction in the baseline on every attack probe, and the native module refused each one with HTTP 403 before release — no crafted value reached the simulated command path while the module served — while every benign probe kept HTTP 200, including the clean-zone-ID and wildcard-domain controls. After revocation the interlay failed closed rather than silently re-exposing the route, and a replacement operation restored the refusal.

## The vulnerability

ManageEngine DDI Central's Windows DDI Agent `clear_blocked_domains` functionality (through 6.3.1 build 6301) processed blocked-domain policy values received through the JSON payload without adequate validation, so specially crafted input could be interpreted as part of a system command executed on the Windows host (remote code execution). Fixed in build 6500, which validates domain values before processing, rejects invalid domain data with an error, and restricts the operation so that agent servers cannot initiate it independently.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies `POST` on the `/agent/policy` route family and its descendants. This is a coarse rule: it also blocks the benign probes on the same route (recorded false positives).

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {"methods": ["POST"], "path": "/agent/policy", "descendants": true},
        "require": {"kind": "deny"}
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** The module refuses policy requests on the agent route family whose JSON string values are not domain-shaped: every quoted string in the payload must consist only of the characters a domain or wildcard entry legitimately carries (`[A-Za-z0-9.*_-]`). A domain value carrying quotes, parentheses, semicolons, pipes, or spaces cannot be a domain — it can only be command material, and it is refused before release. The walker handles JSON escape sequences and refuses escaped command material inside string values.

```rust
fn domain_safe(b: u8) -> bool {
    b.is_ascii_alphanumeric() || b == b'.' || b == b'-' || b == b'*' || b == b'_'
}

/// Scan a JSON payload for string values that are not domain-shaped.
/// Walks quoted strings (handling `\\` and `\"` escapes) and refuses when any
/// string value carries a character outside the domain-safe set.
fn json_strings_all_domain_shaped(src: &[u8]) -> bool {
    let mut i = 0usize;
    let n = src.len();
    while i < n {
        let b = src[i];
        if b == b'"' {
            // string value: walk to the unescaped closing quote
            let mut j = i + 1;
            let mut bad = false;
            let mut closed = false;
            while j < n {
                let c = src[j];
                if c == b'\\' {
                    // escaped byte: only a JSON structural escape is legal
                    // inside a domain value (\uXXXX etc. never appear in one)
                    if j + 1 < n && matches!(src[j + 1], b'"' | b'\\' | b'/' | b'b' | b'f' | b'n' | b'r' | b't' | b'u') {
                        bad = true; // escapes do not belong in a domain value
                        j += 2;
                        continue;
                    }
                    bad = true;
                    j += 2;
                    continue;
                }
                if c == b'"' {
                    closed = true;
                    break;
                }
                if !domain_safe(c) {
                    bad = true;
                }
                j += 1;
            }
            if bad || !closed {
                return false; // unsafe string value (or unterminated)
            }
            i = j + 1;
            continue;
        }
        i += 1;
    }
    true
}
```

**Stated limits.** Finite lab route; the vendor publishes the functionality (blocked-domain policy data in a JSON payload) but not the agent's exact route, so the module is scoped to the policy route family in the deployment configuration; string values must be domain-shaped, so a payload carrying legitimate free-text fields must narrow the conditions. Fixed release: build 6500.

## Fixture and probes

The fixture (`gabriel-ddiagent-app`) mirrors the vendor-documented data flow — the blocked-domain policy request builds a system command from the JSON domain values, and the oracle reports which values cannot be domain data. Recorded effect deltas distinguish injection hits from benign requests.

| Probe | Shape | Baseline | Tier 1 | Tier 2 (module) |
| --- | --- | --- | --- | --- |
| benign_domains | JSON `{"operation": "clear_blocked_domains", "blocked_domains": ["ads.example.com", "*.tracker.io"]}` | 200, clean command | 403 | 200, clean command |
| benign_single_domain | JSON `{"operation": "clear_blocked_domains", "blocked_domains": ["badsite.example"]}` | 200, clean command | 403 | 200, clean command |
| attack_domain_command | JSON `{"operation": "clear_blocked_domains", "blocked_domains": ["ads.example.com", "ok.com\"); Invoke-Expression x"]}` | 200, **domain value escapes the command context** | 403 | 403, refused |
| attack_domain_semicolon | JSON `{"operation": "clear_blocked_domains", "blocked_domains": ["a.com; calc"]}` | 200, **command material in domain value** | 403 | 403, refused |
