# AhsayCBS: authentication bypass in the API password check (CVE-2026-105133)

AhsayCBS's API component has an improper authentication flaw in its system password check, letting a remote attacker bypass login protections. Successful exploitation grants unauthorized access to the backup server — and through it, to every client backup it manages.

## The vulnerability

The API password check accepts unauthenticated probing attempts, letting a remote caller bypass login protections. Eden fronts the CBS API, so the password-check request rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/cbsys/system",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_ahsayauth_v1 waits for a complete request, matches the system password-check route, and refuses password-check requests that carry no CBS session binding header — the unauthenticated guessing shape a hardened API would reject.

```rust
const ROUTE: &[u8] = b"/cbsys/system";
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-105133/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded AhsayCBS version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-105133/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-105133) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe performed a password check presenting the session binding. The advisory-shaped probe submitted a guess without the binding. The fixture incremented its marker when an unbound password check reached the handler.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign bound password check | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped unbound bypass attempt | 200, 1 | 403, 0 | 403, 0 |

The module enforces a binding-header contract on password checks but does not validate its value; a forged binding would pass the module and is a bypass to record. Rate-based enforcement would need stateful support.

## Signed module authority

Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403).
