# LiteLLM SQLi via spend logs (CVE-2024-5225)

[Source and API bundle](../../cve/CVE-2024-5225/README.md)

*[cve.now](https://cve.now/CVE-2024-5225) entry. Product: LiteLLM
(lab: `gabriel-litellm-app`).*

Eden terminates the HTTP connection to the affected product, evaluates a
declarative policy and — in tier 2 — a separately compiled native Rust module
under signed module authority, before any byte reaches the application. It does
**not** patch the affected component; the vendor's fixed release remains the
durable repair.

**Status: Remediated (tier 1 + tier 2), live-proven 2026-11-11T16:48:23Z on the
installed `eden-product-release:1.103.0` lab container.**

## The vulnerability

The LiteLLM spend-logs endpoint (`/global/spend/logs`) interpolates a
caller-supplied query value into SQL. The fixture (`make_litellm`) reproduces
the shape: a body carrying a quote-or tautology (`id' or 1=1`) records a
SQLi mark.

## The Eden patch

**Tier 1 — declarative policy (blunt, fail-closed):** deny every request under
`/global/spend/logs`, ordinary log queries included — false positives measured
below.

**Tier 2 — native Rust module `gabriel_litellm_v1` (surgical):** refuses
bodies carrying SQL quote-or tautology fragments (`' or`, `1=1`, case
insensitive); ordinary log queries pass unchanged.
