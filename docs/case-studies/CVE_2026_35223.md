# Joomla core: improper access check in com_config webservice (CVE-2026-35223)

An improper access check in Joomla lets unauthorized callers reach com_config webservice endpoints. Updating Joomla restores the intended access checks for its configuration service.

[Public CVE record](https://www.cve.org/CVERecord?id=CVE-2026-35223) · [Vendor advisory or update instructions](https://developer.joomla.org/security-centre/1040-20260508-core-improper-access-check-in-com-config-webservice-endpoints.html) · [Module source](modules/CVE-2026-35223.rs) · [Source and API bundle](../../cve/CVE-2026-35223/README.md)

**Result.** The marked request reached the synthetic backend in the baseline. Both protected configurations returned HTTP 403 for that request and the backend counter did not change. The native module passed the benign probe.

## Synthetic HTTP controls

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/api",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** The rule checks only for an Authorization header on POST and PUT targets containing com_config.

```rust
//! refuse unbound writes on com_config webservice routes.
```

## Implement the remediation

**Vendor update.** In Joomla Administrator, install the supported Joomla CMS release containing the fix through Joomla Update. Joomla lists 5.4.6 and 6.1.1 as fixed releases. [Vendor instructions](https://developer.joomla.org/security-centre/1040-20260508-core-improper-access-check-in-com-config-webservice-endpoints.html).

The published package uses registry name `joomla-configuration-web-service-guard`. Verify its own archive digest before import. Use the [fixture API example](../../cve/CVE-2026-35223/http-request-filter/api.md) to reproduce the recorded comparison. It covers the declaration, signed module activation, verification, revocation, and restoration.

## Fixture and probes

The benign probe changed configuration presenting credentials. The marked probe performed the same write without authentication. The fixture incremented its marker when an unauthenticated config write reached the webservice.

## Test scope

The rule checks only for an Authorization header on POST and PUT targets containing com_config. The fixture did not authenticate a Joomla user or exercise com_config’s access check.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the marked probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
