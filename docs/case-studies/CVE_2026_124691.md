# Kendo UI for jQuery: XSS in the Gantt Parent dropdown (CVE-2026-124691)

[CVE advisory record](https://cve.now/CVE-2026-124691) · [Vendor advisory](https://www.telerik.com/kendo-jquery-ui/documentation/knowledge-base/kb-security-kendo-gantt-parent-dropdown-xss-cve-2026-124691) · [Module source](modules/gabriel_kendogantt_v1.rs)

**Result.** The marked request reached the backend in the baseline and raised its counter. The native rule refused that request with HTTP 403 and preserved HTTP 200 for the benign probe. The synthetic fixture ran through Eden 1.103.0 on November 12, 2026 (UTC).

## The vulnerability

The Gantt task editor builds the Parent dropdown from existing task titles. In affected builds, a title supplied by someone who can edit a task is rendered as markup when another user opens the parent selector. The action that introduces the title and the action that renders it can occur in different sessions.

Progress lists affected builds from 2020.3.915 through 2026.3.1015. The fix is in 2026.4.1111. The CVE record reports a CVSS base score of **7.1**.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies requests to `/kendo-ui/gantt` and its descendants. The empty method list leaves the deny unrestricted by HTTP method. This is a coarse rule and blocked the benign probe on the same path.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/kendo-ui/gantt",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** `gabriel_kendogantt_v1` waits for the request to be complete, checks whether the request target starts with `/kendo-ui/gantt`, and looks for any configured marker in the body. The substring comparison is ASCII case-insensitive. Outside that prefix or without a marker, the module returns `Continue`. The shown lines are excerpts from the linked source.

```rust
const ROUTE: &[u8] = b"/kendo-ui/gantt";
static NEEDLES: [&[u8]; 2] = [b"<script", b"onerror="];
```

```rust
NEEDLES.iter().any(|n| find_ignore_case(body, n).is_some()) && return Ok(Decision::Refuse);
```

## Fixture and probes

The fixture was a synthetic HTTP handler behind Eden. It answered the probes and kept a separate counter that increased when the handler recognized its marker bytes. The counter measures a fixture effect. An HTTP 200 from the baseline does not by itself establish that the counter moved.

**Request.** `POST /kendo-ui/gantt/save` for the benign probe and the marked probe.

The benign request saved a task named t1. The second request carried a script marker in the task value plus an event-handler marker in another field. The synthetic backend incremented its counter when those bytes reached it.

## Test scope

The filter scans the whole request body. A markup fragment in an unrelated field can also trigger a refusal, and ordinary task metadata may carry text that looks like markup. The experiment did not open the Gantt editor or verify its dropdown rendering. The route applies only where the integration sends these values through Eden.
