# Shipo: admin impersonation via forged login cookies (CVE-2026-19907)

A remote caller who knows a username can forge a login cookie in affected versions of Shipo for WordPress. An attacker impersonating an administrator can perform privileged actions such as creating another administrator account.

**Patch title.** Shipo Login Cookie Guard (`shipo-login-cookie-guard` in the registry). The [original source snapshot](https://github.com/eden-dev-inc/cve/blob/9a7217a0a882374c5ab97d74c96df9b77637f923/docs/case-studies/modules/CVE-2026-19907.rs) preserves the source available for the historical report.

## The vulnerability

The affected versions and upgrade guidance are listed above. The Eden policy and module were tested against the HTTP fixture described below.

## Synthetic HTTP controls

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/wp-json/shipo",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** The rule refuses the fixture wpid cookie marker on matching REST or admin requests.

```rust
//! refuse forged WP login cookies on API routes.
```

## Implement the remediation

**Vendor update.** In WordPress, update Shipo to 1.8.1 or later. Version 1.8.1 removes the vulnerable custom REST authentication handler. Verify normal checkout and shipping operations on staging before promoting the update. [WordPress plugin releases](https://wordpress.org/plugins/shipo/#developers)

To reproduce the synthetic comparison, use the [fixture API example](../../cve/CVE-2026-19907/http-request-filter/api.md) and the synthetic controls above.

## Fixture and probes

The ordinary probe carried a session cookie. The marked probe carried the fixture wpid cookie marker and the handler counted its delivery.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the marked fixture probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).

## Test scope
