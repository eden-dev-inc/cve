# Airflow: queued-asset deletion gated on READ instead of EDIT (CVE-2026-75157)

Apache Airflow's asset queued-events DELETE endpoints checked the caller's Dag-axis permission with READ instead of EDIT: any authenticated user who could read a Dag could delete its queued asset events, silently suppressing asset-triggered scheduling — a state-changing action on a read-only permission.

## The vulnerability

The asset endpoints authorize deletion with the read permission, so a read-level user destroys scheduling events. Eden cannot see Airflow's RBAC levels, so the module enforces an edit-binding header on queued-event deletions — the established binding pattern (forged bindings pass, recorded as a bypass).

## The Eden patch

**Tier 1 — declaratory policy.** The recorded policy denies every method on the recorded route family and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/api/v2/assets",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** airflow_queued_event_edit_guard waits for a complete request, matches queued-event routes, and refuses DELETEs without an edit binding header. Bound deletions continue.

```rust
//! refuse queued-event deletions without an edit binding.
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-75157/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Apache Airflow (asset events) version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged.
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-75157) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe deleted a queued event presenting the edit binding. The advisory-shaped probe deleted the same event without any binding. The fixture incremented its marker when an unbound deletion reached the endpoint.

## Measured comparison (2026-11-14 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign bound event delete | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped unbound delete | 200, 1 | 403, 0 | 403, 0 |

The module enforces a binding contract it cannot verify against Airflow's RBAC — a read-level user forging the header passes, which is a recorded bypass; the rule's value is forcing deployments to surface edit authority at the boundary. The durable fix is the vendor's permission-level patch.
