# FrankenPHP: Brotli decoder out-of-bounds write (CVE-2026-128014)

A remote unauthenticated caller can send a crafted Brotli stream to an application that passes it to brotli_uncompress_add(). On affected static FrankenPHP builds the decoder can write out of bounds, causing a process crash and potentially disclosing memory or executing code.

## The vulnerability

The affected versions and upgrade guidance are listed above. The test used an 8 KiB body labeled as Brotli and a fixture threshold of 4096 bytes.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/api",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_fpbrotli_v1 waits for a complete request and refuses Brotli-encoded bodies (Content-Encoding: br) larger than 4096 bytes.

```rust
// refuse Content-Encoding: br bodies larger than 4096 bytes
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-128014/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded FrankenPHP (standalone static binaries) version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-128014/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the marked fixture request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** Follow the update instructions for the installed product and release line. [Vendor or publisher advisory](https://github.com/php/frankenphp/security/advisories/GHSA-p746-jj3f-94p8)

## Fixture and probes
