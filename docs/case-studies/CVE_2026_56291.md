# Balbooa Forms: unauthenticated PHP upload to RCE (CVE-2026-56291)

An unauthenticated attacker can upload executable files through affected Balbooa Forms installations and run code on the Joomla server. CISA lists this vulnerability as exploited.

**Result.** The marked request reached the synthetic backend in the baseline. Both protected configurations returned HTTP 403 for that request and the backend counter did not change. The native module passed the benign probe.

## Synthetic HTTP controls

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/balbooa",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** The shared rule scans the target and body for .php or phar: when the target contains jce, pagebuilder, or balbooa.

```rust
static MARKS: [&[u8]; 2] = [b".php", b"phar:"];
```

## Implement the remediation

**Vendor update.** Update Balbooa Forms to 2.4.1 or a later supported release. Follow the vendor’s instructions to inspect the extension’s upload directories for unexpected executable files. [Vendor instructions](https://www.balbooa.com/help/joomla-forms-documentation/basics/changelog).

The published package uses the build name above. Verify its own archive digest before import. Use the [fixture API example](../../cve/CVE-2026-56291/http-request-filter/api.md) to reproduce the recorded comparison. It covers the declaration, signed module activation, verification, revocation, and restoration.

## Fixture and probes

The benign probe uploaded a form definition. The marked probe uploaded shell.php. The fixture incremented its marker when a PHP-named upload reached the handler.

## Test scope

The shared rule scans the target and body for .php or phar: when the target contains jce, pagebuilder, or balbooa. The fixture did not run Balbooa Forms or check its upload validation, storage configuration, or PHP execution.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the marked probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
