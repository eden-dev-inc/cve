# NginxPulse: SQL injection on the stats route (CVE-2026-129171)

An unauthenticated caller can append SQL through the id and locationType parameters of `/api/stats/:type`, close the quoted table identifier, and use error-based output to read the database. Because the bundled deployment runs PostgreSQL as superuser, the advisory notes the same path reads and writes server files — unauthenticated data theft through remote code execution.

## The vulnerability

The stats route interpolates the id and locationType query parameters into a quoted identifier, so a caller who closes the quote appends SQL and reads the response through error output. Eden fronts the NginxPulse web tier, so the injection rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on `/api/stats` and its descendants. This is a coarse rule: it also blocked the benign stats read, which is the recorded false positive.

```json
{ "version": 1, "profile": "http-structure-v1", "policy": { "version": 1, "rules": [ { "scope": { "methods": [], "path": "/api/stats", "descendants": true }, "require": { "kind": "deny" } } ] } }
```

**Tier 2 — native Rust module.** `gabriel_nginxpulse_v1` waits for a complete request, matches targets starting with `/api/stats`, and refuses targets carrying SQL-injection markers (`' OR`, `1=1`, `union select`, `'--`, `;--`). Clean stats queries continue.

```rust
const ROUTE: &[u8] = b"/api/stats";
static NEEDLES: [&[u8]; 5] = [b"' or", b"1=1", b"union select", b"'--", b";--"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-129171/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded NginxPulse version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declarative policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-129171/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the marked fixture request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** Apply the fix for the installed release line and verify the application behavior after upgrading. [Advisory reference](https://vul.yulun.ac.cn/20261030/nginxpulse/)

## Fixture and probes

The benign probe fetched `/api/stats/metrics?id=1&locationType=global`. The marked fixture probe appended `'+OR+1=1--` to the id parameter. The fixture incremented its marker when the injected predicate reached its query layer.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal.
