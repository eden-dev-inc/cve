# Pulse: authorization bypass in the AI approval API (CVE-2026-129428)

A viewer-level Pulse user can access and change AI approval requests through missing authorization checks. This can expose pending commands and let the user approve or reject another person's request.

**Patch title.** Pulse AI Approval Request Guard (`pulse-ai-approval-request-guard` in the registry). The [original source snapshot](https://github.com/eden-dev-inc/cve/blob/9a7217a0a882374c5ab97d74c96df9b77637f923/docs/case-studies/modules/CVE-2026-129428.rs) preserves the source available for the historical report.

## The vulnerability

The affected versions and upgrade guidance are listed above. The Eden policy and module were tested against the HTTP fixture described below.

## Synthetic HTTP controls

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/api/approval",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** The rule requires a fixture role header on matching POST and PUT requests.

```rust
//! refuse unbound writes on the approval API.
```

The ordinary approval included the synthetic role header. The marked request omitted it and the fixture counted its delivery.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the marked fixture probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).

## Test scope

The rule requires a synthetic role header on POST and PUT requests containing /api/approval. It does not verify the header value or match the vendor's /api/ai/approvals route. The test did not use Pulse or exercise viewer permissions.
