# Keycloak: unauthenticated account takeover in the reset-credentials flow (CVE-2026-18963)

A flaw in the reset-credentials flow of keycloak-services — the core identity engine of Red Hat Build of Keycloak — lets an unauthenticated attacker take over accounts. An identity-provider compromise cascades to every application that federates through it.

## The vulnerability

The reset-credentials flow completes without binding the reset to the request that initiated it, so an unauthenticated caller finishes takeovers. Eden fronts the Keycloak realm endpoints, so the reset rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/realms/master/login-actions/reset-credentials",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_keycloak_v1 waits for a complete request, matches realm reset-credential routes, and refuses reset POSTs that carry no action binding header — the unbound reset shape the flow should demand.

```rust
const ROUTE: &[u8] = b"/realms";
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-18963/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Red Hat Build of Keycloak version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-18963/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-18963) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe completed a reset presenting the action binding. The advisory-shaped probe submitted the reset without the binding. The fixture incremented its marker when an unbound reset reached the flow.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign bound reset | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped unbound reset | 200, 1 | 403, 0 | 403, 0 |

The module enforces a binding-header contract on reset requests; the real flow binds via action tokens rather than a header, so an operator adopting this rule must align the binding name. Forged bindings pass the module and are a bypass to record.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
