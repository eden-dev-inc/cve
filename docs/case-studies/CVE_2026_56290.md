# Page Builder CK: unauthenticated executable upload (CVE-2026-56290)

An unauthenticated attacker can use affected Page Builder CK installations to upload executable files and gain code execution on the Joomla server. CISA lists this vulnerability as exploited.

[Public CVE record](https://www.cve.org/CVERecord?id=CVE-2026-56290) · [Vendor advisory or update instructions](https://forum.joomlack.fr/index.php/divers-miscellaneous/21638-page-builder-ck-vulnerability) · [Module source](modules/CVE-2026-56290.rs) · [Source and API bundle](../../cve/CVE-2026-56290/README.md) · [CNA advisory](https://www.joomlack.fr/)

**Result.** The marked request reached the synthetic backend in the baseline. Both protected configurations returned HTTP 403 for that request and the backend counter did not change. The native module passed the benign probe.

## Synthetic HTTP controls

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/pagebuilder",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** The shared rule scans the target and body for .php or phar: when the target contains jce, pagebuilder, or balbooa.

```rust
static MARKS: [&[u8]; 2] = [b".php", b"phar:"];
```

## Implement the remediation

**Vendor update.** Install a supported Page Builder CK release newer than 3.6.0 through Joomla’s extension updater. The vendor identifies 3.6.0 as the minimum, while the CVE record’s affected version field includes 3.6.0. Follow the vendor’s guidance to check for signs of prior compromise. [Vendor instructions](https://forum.joomlack.fr/index.php/divers-miscellaneous/21638-page-builder-ck-vulnerability).

The published package uses the build name above. Verify its own archive digest before import. Use the [fixture API example](../../cve/CVE-2026-56290/http-request-filter/api.md) to reproduce the recorded comparison. It covers the declaration, signed module activation, verification, revocation, and restoration.

## Fixture and probes

The benign probe uploaded a page definition. The marked probe uploaded shell.php. The fixture incremented its marker when a PHP-named upload reached the handler.

## Test scope

The shared rule scans the target and body for .php or phar: when the target contains jce, pagebuilder, or balbooa. The fixture did not run Page Builder CK, write an executable file, or execute PHP.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the marked probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
