# Grafana: plugin path traversal file read (CVE-2021-43798)

An unauthenticated caller can read arbitrary files from a Grafana server through the public plugins file route, including configuration files holding secrets and data-source credentials. The advisory shapes the traversal with encoded segments (`..%2f`) that many fronting proxies forward verbatim.

**Patch title.** Grafana Plugin Path Traversal File Read Guard (`grafana-plugin-path-traversal-file-read-guard` in the registry). ## The vulnerability

Grafana joins a plugin name from the public route into a local file read without confining it, so encoded traversal segments escape the plugin directory and read server files. Eden fronts the Grafana web tier, so the traversal rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on `/public/plugins` and its descendants. This blocks every plugin asset load, benign or not (the recorded false positive), so it is an emergency posture.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/public/plugins",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** `gabriel_grafana_v1` waits for a complete request, matches targets starting with `/public/plugins/`, and refuses any target carrying a raw or percent-encoded traversal marker. Clean asset paths continue. On the tested interlay the traversal-shaped targets never reached the module's decision: the gateway refused them at its own layers (see the measured comparison).

```rust
const ROUTE: &[u8] = b"/public/plugins/";
static MARKS: [&[u8]; 4] = [b"../", b"..%2f", b"%2e%2e", b"..\\"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2021-43798/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Grafana version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declarative policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2021-43798/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds; re-approve, re-admit, and reactivate a replacement operation to restore protection. Keep the route isolated during the change window.

**Vendor update.** Apply the fix for the installed release line. The [advisory](https://github.com/grafana/grafana/security/advisories/GHSA-8pjx-jj86-j47p) documents affected versions and update guidance.

## Fixture and probes

The benign probe fetched a plugin's `module.js`. The advisory-shaped probe used the published encoded traversal `..%2f..%2f..%2fetc%2fpasswd`, and the variant probe used an overlong dot run `....//....//etc/passwd`, which evades segment-based traversal normalization. The fixture incremented its marker only for requests whose raw path reached the backend.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's escaped-read counter. The advisory-shaped request never passed the gateway in any arm; the variant reached the backend only in the baseline, and both protected arms failed it closed.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign plugin asset | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped `..%2f` traversal | 400 gateway, 0 | 400 gateway, 0 | 501 E1A54, 0 |
| Variant `....//` traversal | 200, 1 | 503 E1A02, 0 | 400 E1A44, 0 |

On the tested 1.103.0 interlay the advisory-shaped (`..%2f`) request was refused by the gateway's own request-target validation in every arm (400 without the module and 501 with it), so the backend effect could not be reproduced for it at all. The `....//` variant reached the backend in the baseline (counter +1) and was prevented in both protected arms — but not by a clean module refusal: under the declarative policy it returned 503 `E1A02 inspection unavailable`, and under the active module it returned 400 `E1A44 inspection input is malformed`. Both fail closed (nothing reached the backend), but a module Refuse on a traversal-shaped target was not demonstrated on this release.

Product findings recorded during the run: (1) the gateway's request-target validation refuses classic traversal shapes (`../`, `%2e%2e`, `..%2f`, `..%5c`) with 400 before any policy or module sees them; (2) with a native module active, an encoded traversal target returns `501 E1A54 Original HTTP forwarding profile is unsupported` and a dot-run target returns `400 E1A44 inspection input is malformed` — both fail closed, but the module never evaluates them; (3) the declarative path-scope deny returns `503 E1A02` on the dot-run variant.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal.

## Test scope

The gateway rejected the advisory-shaped request before it reached the fixture, including with the patch absent. Both protected tiers prevented a backend hit for the dot-run variant through gateway errors. The test establishes fail-closed behavior for that variant on Eden 1.103.0. A clean native refusal of the advisory request remains unverified.
