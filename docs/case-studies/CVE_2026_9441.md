# Edimax BR-6478AC: OS command injection in formiNICbasic (CVE-2026-9441)

A remote attacker can inject commands through the rootAPmac field handled by formiNICbasic on affected Edimax BR-6478AC routers. Successful exploitation can allow command execution on the device.

## The vulnerability

The affected versions and upgrade guidance are listed above. The Eden policy and module were tested against the HTTP fixture described below.

## Synthetic HTTP controls

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/goform/formiNICbasic",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** The rule scans the synthetic /goform/form route and its request bodies for selected shell strings.

```rust
const ROUTE: &[u8] = b"/goform/form";
static MARKS: [&[u8]; 3] = [b";", b"$(", b"`"];
```

## Implement the remediation

Check Edimax's firmware support for the BR-6478AC. The CNA lists firmware 1.23 as affected and does not identify a fixed release. [Advisory and remediation guidance](https://vuldb.com/vuln/365422)

The recorded module and policy reproduce the synthetic comparison. [Fixture API example](../../cve/CVE-2026-9441/http-request-filter/api.md)

## Fixture and probes

The ordinary request submitted a clean SSID value. The marked request added shell metacharacters and the fixture counted its delivery.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the marked fixture probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
