# Apache XML Graphics Batik: xml:base same-origin bypass (CVE-2026-49236)

[Source and API bundle](../../cve/CVE-2026-49236/README.md)

*[cve.now](https://cve.now/CVE-2026-49236) entry. Product: Apache XML Graphics
Batik (org.apache.xmlgraphics) (lab: `gabriel-batik2-app`).*

Eden terminates the HTTP connection to the affected product, evaluates a
declarative policy and — in tier 2 — a separately compiled native Rust module
under signed module authority, before any byte reaches the application. It does
**not** patch the affected component; the vendor's fixed release remains the
durable repair.

**Status: Remediated (tier 1 + tier 2), live-proven 2026-11-11T17:04:06Z on the
installed `eden-product-release:1.103.0` lab container.**

## The vulnerability

Batik's `xml:base` handling lets an SVG color-profile reference bypass the
external-resource same-origin check, redirecting resource resolution to a
remote origin. The fixture (`make_batikxmlbase`, port 18327) reproduces the
delivery shape: an SVG whose root carries a remote `xml:base` declaration
records an SSRF mark.

## The Eden patch

**Tier 1 — declarative policy (blunt, fail-closed):** deny every request under
`/batik/render`, local-profile SVGs included — false positives measured below.

**Tier 2 — native Rust module `gabriel_batikxmlbase_v1` (surgical):** refuses
SVG bodies carrying a remote `xml:base` declaration; local-profile SVGs pass
unchanged.

## Authority lifecycle and negatives

Import 201, `activation: explicit_required`; publisher `enroll_key`, host
`inventory` + `approve`, reader `inspect` refused 403; tampered-statement admit
400; invalid-signature admit 403; `admit` prepared (not serving), `activate`
→ receipt `serving_now`, applied shards **2/2**. Revoke → the identical attack
gets **503** (fail-closed); re-approve + re-activate → 403 again. All recorded
in the evidence JSON.

## Honest scope
