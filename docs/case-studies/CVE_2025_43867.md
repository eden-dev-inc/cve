# Johnson Controls FX Server: file access through a vulnerable component (CVE-2025-43867)

Johnson Controls FX Server, FX80, and FX90 contain a vulnerable third-party component that lets an attacker access, modify, or delete files — reachable remotely over the network with a low-privilege login and no user action. Building-control servers are critical infrastructure; file access is a direct path to manipulation.

## The vulnerability

The vulnerable component resolves caller-supplied file paths outside its intended root, letting a low-privilege user reach arbitrary files. Eden fronts the FX server's web interface, so the crafted path rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/fs/files",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_fxserver_v1 waits for a complete request, matches FX file routes, and refuses targets carrying traversal markers (../, percent-encoded forms). On the tested interlay the traversal-shaped targets were failed closed by the gateway itself before the module (see the measured comparison) — the recorded gateway behavior, not a clean module refusal.

```rust
const ROUTE: &[u8] = b"/fs/files";
static MARKS: [&[u8]; 3] = [b"../", b"..%2f", b"%2e%2e"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2025-43867/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Johnson Controls FX Server / FX80 / FX90 version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2025-43867/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2025-43867) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe fetched a quarterly report by its clean path. The advisory-shaped probe used a traversal path. The fixture incremented its marker when a traversal-bearing path reached the file handler. Classic ../ shapes are 400'd by the gateway's own request-target validation; the overlong-dot variant (....//) reached the backend unremediated in the baseline.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign report fetch | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped traversal path | 200, 1 | 503 E1A02, 0 | 400 E1A44, 0 |

Honest recording: the gateway failed the traversal target closed at its own layers (503 E1A02 under tier-1; 400 E1A44 with the module active) — the same product findings recorded for the Grafana case. Prevention of the backend effect is verified (counter frozen); a clean module 403 on traversal-shaped targets could not be demonstrated on this release.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
