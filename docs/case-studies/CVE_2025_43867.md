# Johnson Controls FX Server: file access through a vulnerable component (CVE-2025-43867)

A vulnerable dependency in Johnson Controls FX Server, FX80, and FX90 can let an attacker access, change, or delete files. Those changes can disrupt or compromise a building control system.

**Patch title.** Johnson Controls FX Server File Access Guard (`johnson-controls-fx-server-file-access-guard` in the registry). ## The vulnerability

The affected versions and upgrade guidance are listed above. The Eden policy and module were tested against the HTTP fixture described below.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the fixture route and its descendants. The benign request was denied. The gateway rejected the marked traversal request before a native module decision.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/fs/files",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_fxserver_v1 waits for a complete request, matches FX file routes, and refuses targets carrying traversal markers (../, percent-encoded forms). On the tested interlay the traversal-shaped targets were failed closed by the gateway itself before the module (see the measured comparison).

```rust
const ROUTE: &[u8] = b"/fs/files";
static MARKS: [&[u8]; 3] = [b"../", b"..%2f", b"%2e%2e"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2025-43867/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Johnson Controls FX Server / FX80 / FX90 version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2025-43867/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the marked fixture request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** Follow the update instructions for the installed product and release line. [Vendor or publisher advisory](https://www.johnsoncontrols.com/trust-center/cybersecurity/security-advisories)

## Fixture and probes

The benign probe fetched a quarterly report by its clean path. The marked fixture probe used a traversal path. The fixture incremented its marker when a traversal-bearing path reached the file handler. Classic ../ shapes are 400'd by the gateway's own request-target validation; the overlong-dot variant (....//) reached the backend unremediated in the baseline.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the marked fixture probe received HTTP 503 (fail-closed); re-approval and reactivation restored the operation. The recorded traversal comparison attributes the block to the gateway.
