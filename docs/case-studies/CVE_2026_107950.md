# HCL Commerce: XML external entity in the Storefront REST API (CVE-2026-107950)

The Storefront REST API of HCL Commerce parses caller-supplied XML with external entity resolution enabled, so a remote attacker without logging in can read local files or exhaust memory with a crafted DOCTYPE payload. The durable repair is the fixed HCL Commerce release.

## The vulnerability

A Storefront REST API endpoint accepts XML and resolves external entities in it, letting an unauthenticated caller point an entity at a local file (file disclosure) or at an external DTD (parameter-entity blind read, memory exhaustion). Eden fronts the Commerce storefront, so the crafted XML rides an HTTP request Eden can refuse before the parser ever sees it.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded route family and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/wcs/resources",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** hcl_commerce_storefront_xxe_guard waits for a complete request, matches requests to the Storefront REST API prefix (/wcs/resources), and refuses bodies carrying a DTD marker (<!DOCTYPE or <!ENTITY, case-insensitive) — the external-entity family the advisory describes. Storefront REST bodies are JSON in normal use, and XML without a DTD passes, so benign traffic is unaffected.

```rust
static MARKS: [&[u8]; 2] = [b"<!doctype", b"<!entity"];
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-107950/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded HCL Commerce version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission.
2. **Apply the declarative policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged.
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-107950) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probes queried the storefront product API with a JSON body and with a well-formed XML body carrying no DTD. The advisory-shaped probes submitted XML with a DOCTYPE declaring a SYSTEM entity on file:///etc/passwd, and a parameter-entity variant pointing at a remote DTD. The fixture mirrored the parser's primitive: it marked the trigger when a DTD/ENTITY declaration reached the API.
