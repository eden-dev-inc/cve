# phpAfterShell: interrupted session writes to remote code execution (CVE-2026-126714)

An unauthenticated remote caller can submit a multipart/form-data request that PHP's RFC1867 upload-progress callback answers by opening, updating, and rewriting the file-backed session — before the target script runs, with no `session_start()` anywhere. A worker death inside that buffered update (`pwrite()` mid-copy, or between the handler's write and truncate syscalls) leaves a spliced session file: the replacement prefix joined to the retained carrier tail. Both source states are valid; the splice can also be valid with a different meaning, and a later `session_start()` promotes bytes that were inert string data in the carrier into live session records — including serialized objects, which the vendor chains (through a withheld PHP-native-class memory corruption) to remote code execution. No fixed release existed at publication.

**Result.** The crafted session file **corrupted the real session state** in the baseline: on every affected PHP series, the spliced file — the replacement prefix joined to the retained carrier tail, the exact byte state a killed worker leaves — decoded through PHP's real session decoder with the carrier's inert bytes promoted into a live `$_SESSION['evil']` object. **Real worker kills landed inside the handler's write**: a swept SIGKILL caught the 100 MiB buffered `pwrite` mid-copy (two TARGET observations at T=165/180 ms inside a clean EARLY→TARGET→LATE oracle band), and five SIGKILLs landed between the handler's real `pwrite64(…, 104857600, 0) = 104857600` and its real `ftruncate`, each leaving the splice. On a real Apache SAPI, an unauthenticated multipart POST wrote the session file **before the script ran** — a script with no session code — and a later ordinary `session_start()` decoded it. The native module refused every progress-carrying multipart request with HTTP 403 before release, preserved HTTP 200 for non-multipart and plain-multipart traffic, and after revocation the interlay failed closed rather than re-exposing the upload route.

## The vulnerability

With `session.upload_progress.enabled` (PHP's default), the session extension subscribes to the RFC1867 multipart parser's events. A form part named `PHP_SESSION_UPLOAD_PROGRESS` supplies a progress key; the callback then resolves the request's session ID (`PHPSESSID`), initializes the session module, and — while the multipart body is still being parsed, **before `index.php` executes a single line** — reads the current session, inserts `upload_progress_<key>` records (whose serialized strings carry the multipart field names and filenames), serializes the whole session, and writes it back to `sess_<SID>` with `flock` + `pwrite()` + `ftruncate()`.

Those filesystem operations are not atomic. A worker death inside the update leaves a prefix of the new serialized session joined to the retained tail of the old one. Both source sessions are valid PHP-serialized values, and — because the session format is `key|serialized` records with attacker-influenced length fields — the splice can be valid too, with a different meaning: a prefix that changes a declared string length can make the decoder resume exactly where the carrier kept an object as inert string data, promoting it into a live `$_SESSION` record. Nothing needs to deserialize during the callback; the attacker only leaves the bytes on disk and waits for the application to call `session_start()`.

The affected source history splits into three families:

| Versions | Session behavior | Write ordering |
| --- | --- | --- |
| 8.2.35–current 8.2, 8.3.36–current 8.3, 8.4.27, 8.5.12 | `__PHP_Incomplete_Class` transport (the php2shell fix) | **Variant A** — ftruncate *before* the write when shorter |
| 8.4.28RC1+, 8.5.13RC1+, 8.6.0RC4+, master | `__PHP_Incomplete_Class` transport | **Variant B** — write first, ftruncate after |
| 8.2.0–8.2.34, 8.3.0–8.3.35, 8.4.0–8.4.26, 8.5.0–8.5.11, 8.6.0RC1–RC3 | ordinary object semantics during RFC1867 (original php2shell path) | — |

Variant A exploits a replacement **at least as long as** the carrier (no pre-truncate; kill mid-`pwrite` leaves `R[0:k] || C[k:]`). Variant B exploits a **shorter** replacement (the complete write is followed by truncation; a death between the two syscalls leaves `R || C[|R|:]`). No fixed release existed at publication; the vendor's EOL mitigation branches disable the callback ("the upload-progress callback returns without opening the Session").

## Deterministic primitive on real affected builds (2026-11-19 UTC)

Each public Docker Hub PHP image was run on the verification host. The carrier and replacement session files were written through the **real** files session handler (`session_start` + assignment + `session_write_close` on the target SID — the same write path the RFC1867 callback uses), with the session-grammar geometry self-calibrated against the real serializer's output. The interrupted-write byte state was then constructed deterministically — a partial `pwrite` of the replacement at offset zero with no `ftruncate`, byte-identical to the inode state a killed worker leaves — and decoded with the real `session_start()`. The public proof object is `evil|O:8:"stdClass":1:{s:5:"proof";s:5:"pwned";}`, carried dormant inside a carrier string and promoted by the splice.

**A genuine release finding:** PHP 8.6.0RC4 flips `session.use_strict_mode` to **On** by default. The callback discards caller-supplied session IDs in that configuration, which reshapes (but does not remove) the primitive's ID control; the lab pins the documented Off for SID control. Nothing else about the session write changed.

## Real worker kills inside the handler's write (2026-11-19 UTC)

Deterministic byte states prove the decoder; real kills prove the file states occur from actual worker deaths. Geometry at 100 MiB (the acceptance window spans essentially the whole buffered copy):

**Variant A** (`php:8.2.35` — no pre-truncate for a longer replacement). A detached child committed the replacement through the real handler; the parent SIGKILLed the container at a swept delay after the child's in-file READY marker, then decoded the inode with the real session decoder:

| Kill at READY+T | Outcome |
| --- | --- |
| 0–150 ms (6 samples) | CARRIER — killed before the write |
| **165 ms** | **TARGET — object promoted from the spliced tail** |
| **180 ms** | **TARGET — object promoted** |
| 195–450 ms (8 samples) | LATE — complete replacement |

**Variant B** (`php:8.4.28RC1` — write-then-truncate). The child ran under strace with `ftruncate` fault-injected (`delay_enter=3000ms`), which widens the genuine between-syscall window so a real SIGKILL lands deterministically between the handler's real `pwrite64(…, 104857600, 0) = 104857600` and its real `ftruncate`: **5/5 attempts TARGET** — every kill left `Rb || C[|Rb|:]` and the real decoder promoted the object.

Both kill legs used real container SIGKILLs against the real handler's real syscalls; the only artificial element is the injected syscall delay in the variant-B leg (recorded honestly — without injection the window is microseconds and was not won by external timing alone).

## Unauthenticated pre-script write on a real Apache SAPI (2026-11-19 UTC)

Stock `php:8.2.35-apache` (mod_php) and EOL `php:8.1-apache`, with a docroot script that contains **no session code** (`echo` only):

- An unauthenticated `multipart/form-data` POST carrying a `PHP_SESSION_UPLOAD_PROGRESS` part and a real file caused the SAPI to create `sess_<SID>` (owned by www-data) **before the script ran** — no `session_start()` anywhere.
- The attacker-controlled multipart filename rode the serialized progress record into the session file.
- A later ordinary GET to a route that calls `session_start()` decoded the file as trusted server-side state (`upload_progress_<key>` present in `$_SESSION`).

Empty file parts did not arm the callback (the progress record updates during file-data events) — a trigger-requirement observation recorded for completeness.

**Not reproduced (honest limit):** the vendor's over-HTTP kill calibration (the adaptive memory-pressure lanes and parser-depth timing that land the kill mid-update from outside). The real kills above were driven from the verification harness against the same handler code paths; the HTTP leg proves the unauthenticated write path and the consumer path separately.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies `POST` on the `/upload` route family. This is a coarse rule: it blocked the benign upload probes on the same route (recorded false positives).

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [
            "POST"
          ],
          "path": "/upload",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** The module refuses `multipart/form-data` requests that carry a form part named `PHP_SESSION_UPLOAD_PROGRESS` — the field that arms the RFC1867 session-write callback. The callback never runs, so no pre-script session write occurs and no splice state can be produced from a refused request. This is the vendor's own EOL mitigation (`session.upload_progress` disabled) expressed at the request boundary. Detection is boundary-aware: the part name is matched only inside multipart part-header regions (after each boundary), never in part bodies, so file contents that merely mention the field name do not trip the rule. Non-multipart requests and multipart requests without the field pass untouched.

```rust
const PROGRESS_FIELD: &[u8] = b"PHP_SESSION_UPLOAD_PROGRESS";

fn lower(b: u8) -> u8 {
    if b.is_ascii_uppercase() { b + 32 } else { b }
}

/// Case-insensitive substring search (ASCII). Returns the match start.
fn find_ci(hay: &[u8], needle: &[u8]) -> Option<usize> {
    if needle.is_empty() || hay.len() < needle.len() {
        return None;
    }
    'outer: for i in 0..=(hay.len() - needle.len()) {
        for (j, nb) in needle.iter().enumerate() {
            if lower(hay[i + j]) != lower(*nb) {
                continue 'outer;
            }
        }
        return Some(i);
    }
    None
}

/// Byte-wise equality at an offset (no slice compare: the closed profile
/// rejects bcmp imports).
fn eq_at(hay: &[u8], at: usize, needle: &[u8]) -> bool {
    if at > hay.len() || hay.len() - at < needle.len() {
        return false;
    }
    for (j, nb) in needle.iter().enumerate() {
        if hay[at + j] != *nb {
            return false;
        }
    }
    true
}

/// Case-sensitive substring search. Returns the match start.
fn find(hay: &[u8], needle: &[u8]) -> Option<usize> {
    if needle.is_empty() || hay.len() < needle.len() {
        return None;
    }
    for i in 0..=(hay.len() - needle.len()) {
        if eq_at(hay, i, needle) {
            return Some(i);
        }
    }
    None
}

/// Extract the multipart boundary from a Content-Type header value.
/// `multipart/form-data; boundary=X` — X may be quoted.
fn boundary_of(ct: &[u8]) -> Option<&[u8]> {
    let at = find_ci(ct, b"boundary=")?;
    let mut rest = &ct[at + b"boundary=".len()..];
    if rest.first() == Some(&b'"') {
        rest = &rest[1..];
        let end = rest.iter().position(|&b| b == b'"')?;
        Some(&rest[..end])
    } else {
        let end = rest
            .iter()
            .position(|&b| b == b';' || b == b'\r' || b == b'\n' || b == b' ')
            .unwrap_or(rest.len());
        Some(&rest[..end])
    }
}

/// Does a part header region (the `Content-Disposition` etc. headers after a
/// boundary) declare a form field named `PHP_SESSION_UPLOAD_PROGRESS`?
fn part_header_has_progress(region: &[u8]) -> bool {
    let mut from = 0usize;
    while let Some(rel) = find_ci(&region[from..], b"name=") {
        let at = from + rel;
        let mut v = at + b"name=".len();
        if region.get(v) == Some(&b'"') || region.get(v) == Some(&b'\'') {
            v += 1;
        }
        if region[v..].len() < PROGRESS_FIELD.len() {
            return false;
        }
        if eq_at(region, v, PROGRESS_FIELD) {
            // Require a real field-name terminator: quote, CR, LF, ; or =
            let after = region.get(v + PROGRESS_FIELD.len()).copied();
            return matches!(
                after,
                None | Some(b'"') | Some(b'\'') | Some(b'\r') | Some(b'\n') | Some(b';') | Some(b'=')
            );
        }
        from = at + b"name=".len();
    }
    false
}

/// Scan a multipart body for any part whose header names the progress field.
fn multipart_carries_progress(body: &[u8], boundary: &[u8]) -> bool {
    let sep_prefix = b"--";
    let mut from = 0usize;
    while let Some(rel) = find(&body[from..], boundary) {
        let b_at = from + rel;
        // require the RFC 2046 dashes before the boundary (the first part
        // starts at byte 0 with no preceding bytes)
        let dashed = b_at == 0
            || (b_at >= sep_prefix.len() && eq_at(body, b_at - sep_prefix.len(), sep_prefix));
        let part = b_at + boundary.len();
        let headers_end = match find(&body[part..], b"\r\n\r\n") {
            Some(rel) => part + rel,
            None => match find(&body[part..], b"\n\n") {
                Some(rel) => part + rel,
                None => body.len(),
            },
        };
        if dashed && part_header_has_progress(&body[part..headers_end]) {
            return true;
        }
        from = b_at + boundary.len();
    }
    false
}

fn request_is_multipart_with_progress(head: &[u8], body: &[u8]) -> bool {
    // Request line first; headers follow. Find the Content-Type header value.
    let ct_at = match find_ci(head, b"content-type:") {
        Some(at) => at + b"content-type:".len(),
        None => return false,
    };
    let ct_end = head[ct_at..]
        .iter()
        .position(|&b| b == b'\r' || b == b'\n')
        .map(|rel| ct_at + rel)
        .unwrap_or(head.len());
    let ct = &head[ct_at..ct_end];
    if find_ci(ct, b"multipart/form-data").is_none() {
        return false;
    }
    let boundary = match boundary_of(ct) {
        Some(b) => b,
        None => return false,
    };
    multipart_carries_progress(body, boundary)
}
```

**Stated limits.** Upload progress is disabled outright for protected routes — an application using the progress data on the same route loses that feature, the identical trade-off of the vendor's mitigation. The module is request-shape-only: it cannot see the save handler's on-disk behavior, and a deployment that arms the callback through another request shape not covered here is out of scope. The durable fix is the PHP release that makes the session update safe (or the vendor's EOL mitigation branches).

## Implement the remediation

1. **Prepare the target.** Confirm the PHP version and family against the advisory (`php -i | grep session`). Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission.
2. **Apply the declarative policy.** Set `INTERLAY` to the target interlay UUID. Save the interlay's current settings, place the tier-1 policy in `settings.remediation`, and PATCH the full settings with a fresh `Idempotency-Key`. Read back `remediation_status.state == ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the published source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and all shards are acknowledged.
4. **Verify, revoke, and restore.** Replay the benign and marked probes and compare the fixture oracle. Revoke and confirm the route fails closed (503); re-approve, re-admit and reactivate a replacement operation to restore protection.

## Fixture and probes

The fixture (`gabriel-phpfs-app`) mirrors the RFC1867 data flow: the serialized session-record strings are built from the request's multipart part metadata (lab transport: hex in the part name, since multipart header grammar cannot carry quote bytes verbatim; the production entry carries attacker bytes through ordinary multipart metadata — observed on the real Apache leg). When the request arms the callback, the fixture models the interrupted handler write at a deterministic kill offset inside the acceptance window (the same window the real kills landed in), decodes the spliced file with the php session format, and records a `phpfs_primitive` effect when inert carrier bytes are promoted into a live object record.

| --- | --- | --- | --- | --- |
| benign_json_post | non-multipart JSON body | 200, no splice | 403 | 200, no splice |
| benign_multipart_no_progress | multipart without the progress field | 200, callback inactive | 403 | 200, callback inactive |

| attack_progress_splice | multipart + progress field + carrier/replacement parts | 200, **spliced session decodes with `$_SESSION['evil']` = stdClass{proof: pwned}** | 403 | 403, refused |
