# SvelteKit: cross-function argument leak in query.batch (CVE-2026-128119)

When SvelteKit's experimental remote functions flag is enabled, an unauthenticated remote attacker can access function arguments meant for other private query.batch functions when those functions share a request batch — reading data the server never intended to expose.

## The vulnerability

The batch endpoint fails to isolate arguments between functions sharing a batch, so a crafted multi-call batch exposes other functions' private arguments. Eden fronts the SvelteKit app, so the crafted batch rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the recorded fixture route and its descendants. This is a coarse rule: it also blocked the benign probe on the same route, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/__remote",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_kitbatch_v1 waits for a complete request, matches the remote-functions route, and refuses batched request bodies carrying more than one call — the multi-call batch in which arguments leak. Single calls continue.

```rust
const ROUTE: &[u8] = b"/__remote";
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-128119/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded SvelteKit (remote functions) version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declaratory policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-128119/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** The fixed release carries the durable repair; the [advisory](https://cve.now/CVE-2026-128119) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe issued a single function call. The advisory-shaped probe batched two calls — one private — in one request. The fixture incremented its marker when a multi-call batch reached the handler.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign single call | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped multi-call batch | 200, 1 | 403, 0 | 403, 0 |

The rule refuses multi-call batches wholesale; the leak-specific shape (which functions co-batch) is not detected, so legitimate multi-call batches are also refused — a recorded false-positive trade-off. The feature is experimental; the durable fix is the framework patch.

## Signed module authority

Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403).
