# Apache HTTP Server: mod_vhost_alias 1-byte stack buffer overwrite (CVE-2026-109163)

[Source and API bundle](../../cve/CVE-2026-109163/README.md)

*[cve.now](https://cve.now/CVE-2026-109163) entry. Product: Apache HTTP Server
(lab: `gabriel-modvhostalias-app`). Follow-up to CVE-2026-63292.*

Eden terminates the HTTP connection to the affected product, evaluates a
declarative policy and — in tier 2 — a separately compiled native Rust module
under signed module authority, before any byte reaches the application. It does
**not** patch the affected component; the vendor's fixed release remains the
durable repair.

**Status: Remediated (tier 1 + tier 2), live-proven 2026-11-11T17:02:16Z on the
installed `eden-product-release:1.103.0` lab container.**

## The vulnerability

`mod_vhost_alias` writes one byte past a stack buffer when parsing an
overlong crafted `Host` value (the residual case after CVE-2026-63292). The
fixture (`make_modvhostalias`, port 18315) reproduces the delivery shape: a
request whose `Host` exceeds 64 bytes records a stack-overwrite mark.

## The Eden patch

**Tier 1 — declarative policy (blunt, fail-closed):** deny every request on
the host — the entire interlay — false positives measured below.

**Tier 2 — native Rust module `gabriel_modvhostalias_v1` (surgical):** refuses
requests whose `Host` header value exceeds 64 bytes; ordinary hostnames pass
unchanged.

## Authority lifecycle and negatives

Import 201, `activation: explicit_required`; publisher `enroll_key`, host
`inventory` + `approve`, reader `inspect` refused 403; tampered-statement admit
400; invalid-signature admit 403; `admit` prepared (not serving), `activate`
→ receipt `serving_now`, applied shards **2/2**. Revoke → the identical attack
gets **503** (fail-closed); re-approve + re-activate → 403 again. All recorded
in the evidence JSON.

## Honest scope

vhost-alias interpolation logic. Bypass variants (encoded hosts, trailing-dot
tricks) are not bypass-tested; the rule is a lab-grade partial. Module binary
