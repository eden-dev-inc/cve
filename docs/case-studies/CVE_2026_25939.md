# FUXA: unauthenticated scheduler write (CVE-2026-25939)

FUXA 1.2.8 through 1.2.10 let an unauthenticated remote caller create and modify arbitrary schedulers. FUXA schedulers drive connected SCADA and ICS actions, so a forged schedule can trigger follow-on commands against physical processes that the operator never authorized.

## The vulnerability

FUXA's scheduler API accepts writes without authenticating the caller, so anyone who can reach the web port can install a scheduler that acts on the connected SCADA environment. Eden fronts the FUXA web tier, so the write rides an HTTP request Eden can refuse before release.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on `/api/scheduler` and its descendants. This is a coarse rule: it also blocked the benign scheduler read, which is the recorded false positive.

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/api/scheduler",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** `gabriel_fuxa_v1` waits for a complete request, matches targets starting with `/api/scheduler`, and refuses non-GET requests that carry no `X-FUXA-User` header. Reads and authorized writes continue, which passed the benign probe.

```rust
const ROUTE: &[u8] = b"/api/scheduler";
// refuse non-GET without x-fuxa-user
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-25939/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded FUXA version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declarative policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-25939/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds; re-approve, re-admit, and reactivate a replacement operation to restore protection. Keep the route isolated during the change window.

**Vendor update.** Apply the fix for the installed release line. The [advisory](https://github.com/frangoteam/FUXA/security/advisories/GHSA-c869-jx4c-q5fc) documents affected versions and update guidance.

## Fixture and probes

The benign probe listed schedulers with GET. The advisory-shaped probe posted a new schedule body without a user header. The fixture incremented its marker when an unauthenticated scheduler write landed.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's scheduler-write counter. The declarative tier blocked the benign read (the recorded false positive); the module refused only the unauthenticated write.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign scheduler read | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped unauthenticated write | 200, 1 | 403, 0 | 403, 0 |

The module requires a user header on non-GET scheduler requests but does not validate its value; a forged header would pass the module and is a bypass to record. Scheduler subpaths beyond `/api/scheduler` and non-HTTP FUXA protocols were not exercised.



## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal.

The baseline arm measures the unprotected interlay's forward path, which exhibits a separate ~41 ms response-write stall on this release (a recorded product finding), so it is not a like-for-like module-overhead comparison; the deny and module arms are the comparable pair.

## Test scope

The fixture verifies refusal of a scheduler write with the user header absent. The module checks for the header's presence, so a forged value can pass. The test does not establish authentication of scheduler writes.
