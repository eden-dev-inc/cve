# Plex Media Server: arbitrary file write via TranscoderH264Options (CVE-2026-96656)

Plex Media Server before 1.43.3.10861 appends the TranscoderH264Options preference verbatim to x264's option string, so an administrator-level user can write arbitrary files that the server later executes on load — control of the host.

**Result.** The advisory-shaped request raised the backend counter in the baseline (200, +1). The declaratory tier refused it (403, counter unchanged, benign false positive recorded). The native module refused the advisory-shaped request (403, counter unchanged) while the benign probe stayed HTTP 200 — surgical, verified against an independent backend counter through Eden 1.103.0.

## The vulnerability

The preference value is appended verbatim to x264's option string, so an admin user can plant file-writing options that the server later executes on load. Eden fronts the media server, so the preference write rides an HTTP request Eden can refuse.

## The Eden patch

**Tier 1 — declarative policy.** The recorded policy denies every method on the preference route and its descendants. This blocks every preference write, benign or not (the recorded false positive).

```json
{
  "version": 1,
  "profile": "http-structure-v1",
  "policy": {
    "version": 1,
    "rules": [
      {
        "scope": {
          "methods": [],
          "path": "/prefs",
          "descendants": true
        },
        "require": {
          "kind": "deny"
        }
      }
    ]
  }
}
```

**Tier 2 — native Rust module.** gabriel_plextranscode_v1 waits for a complete request, matches targets starting with the preference route, and refuses bodies naming the TranscoderH264Options preference — the exact field the advisory says is appended to x264's option string. Other preference writes continue.

```rust
const ROUTE: &[u8] = b"/prefs/";
if find_ignore_case(body, b"transcoderh264options").is_some() { return Ok(Decision::Refuse); }
```

## Implement the remediation

The commands are operator examples for the recorded scope. Compare fixture routes and software selectors with the intended deployment before use. See [deployment prerequisites](../deployment.md) and the [API example](../../cve/CVE-2026-96656/http-request-filter/api.md).

1. **Prepare the target.** Verify the loaded Plex Media Server version against the advisory. Use a compatible Eden HTTP interlay and an authenticated operator with Configure permission. Use the recorded declaration and the linked source.
2. **Apply the declarative policy.** Set `INTERLAY` to the target interlay UUID in the authenticated Eden CLI. Save the interlay's complete current settings, place the policy from this report in `settings.remediation`, and PATCH the full settings object with a fresh `Idempotency-Key`. Read the interlay back and confirm `remediation_status.state` is `ready`.
3. **Import and activate the native module.** Build the schema-2 archive from the linked source with the compatible SDK, verify its digest, and PUT it to the interlay's patch-packages endpoint. Import requires explicit activation: enroll the publisher key, attest the host inventory, inspect the returned configuration, obtain independent host approval, sign the typed statement, admit, and activate. Read the receipt until `serving_now` is true and the expected shards are acknowledged. Full command sequences are in the [API example](../../cve/CVE-2026-96656/http-request-filter/api.md).
4. **Verify, revoke, and restore.** Replay the benign and advisory-shaped probes and compare the backend counter. Revoke the operation and confirm the advisory-shaped request no longer succeeds (fail-closed 503); re-approve, re-admit, and reactivate a replacement operation to restore protection.

**Vendor update.** Plex Media Server 1.43.3.10861 carries the durable fix; the [advisory](https://cve.now/CVE-2026-96656) links the vendor's update instructions where available. Eden's tiers are an enforcement stopgap for a deployment that cannot upgrade immediately.

## Fixture and probes

The benign probe set an ordinary preference (TranscoderDuration). The advisory-shaped probe wrote TranscoderH264Options with a file-writing value. The fixture incremented its marker when the field reached its transcoder option assembly.

## Measured comparison (2026-11-13 UTC)

The values after each status are the observed increases in the fixture's effect counter.

| Probe | Baseline | Declarative policy | Native module |
| --- | --- | --- | --- |
| Benign preference write | 200, 0 | 403, 0 | 200, 0 |
| Advisory-shaped TranscoderH264Options | 200, 1 | 403, 0 | 403, 0 |

The rule refuses writes naming the TranscoderH264Options preference; other preferences continue. The advisory path is an administrator-level user — the recorded risk is privilege escalation from admin to host control, not anonymous access.

## Signed module authority

Import returned HTTP 201 with explicit activation required and signature verification deferred. Read-only inspection was refused (403) for the reader principal, admission of a tampered statement was rejected (400), and admission of an invalid signature was refused (403). The activation receipt reported the module serving on all 32 expected shards. After revocation the advisory-shaped probe received HTTP 503 (fail-closed); re-approval and reactivation restored the refusal (403, counter unchanged).
